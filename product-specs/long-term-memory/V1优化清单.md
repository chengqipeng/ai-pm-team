## 二、P0 第一阶段详细设计

### 2.1 四路并行拆分（#1）

```
MemoryExtractor.extract_all()
├── _extract_profile         ← OVERWRITE, 输入=仅user, 注入已有profile
├── _extract_preferences     ← MERGE by slug, 输入=仅user, 不注入已有
├── _extract_agent_rules     ← OVERWRITE, 输入=仅user, 注入已有rules, 4步进化
└── _extract_entities        ← MERGE by parent_entity, 输入=全量, 注入已有实体索引
        ├── events 子类型标记
        ├── cases 子类型标记
        └── patterns 子类型标记
```

关键取舍：
- events/cases/patterns 不砍掉，挂到 entities 流程里作为子类型标签
- tools/skills 从 LLM 提取中完全移除，改由系统统计
- soul 全量重命名为 agent_rules，对齐 neo-apps 语义

### 2.2 输入过滤策略（#2）

| 维度 | 输入消息 | 原因 |
|---|---|---|
| profile | 仅 user | 用户身份只能从用户自述中提取 |
| preferences | 仅 user | 偏好是用户表达的 |
| agent_rules | 仅 user | Agent 行为规则来自用户指令 |
| entities | 全量（user + assistant + tool） | 实体信息可能在工具返回中 |

### 2.3 多租户隔离（#5）

使用 `tenant_id` 作为唯一隔离边界：
- MemoryEngine 接口签名增加 `tenant_id` 参数
- 存储 partition key = `(tenant_id, user_id)`
- URI 格式：`/memory/{tenant_id}/{user_id}/{category}[/{slug}]`
- 检索强制 `WHERE tenant_id = :current_tenant`

### 2.4 输出语言控制（#3）

所有 prompt 增加 `{output_language}` 占位符：
- 默认 `auto`：使用对话主导语言
- 可指定 `zh-CN`、`en` 等

## 三、存储抽象设计（P1-7）

```python
class StoreMode(Enum):
    OVERWRITE = "overwrite"  # profile, agent_rules（单条整体覆盖）
    MERGE = "merge"          # preferences, entities（同 slug/merge_key 合并）
    APPEND = "append"        # events, cases（每次新增）

class MemoryLevel(IntEnum):
    L0_ABSTRACT = 0   # 一句话（快速检索）
    L1_OVERVIEW = 1   # 结构化 Markdown（中等）
    L2_CONTENT  = 2   # 完整叙述（详细）
```

## 五、风险与回滚

| 改动 | 风险 | 回滚方式 |
|---|---|---|
| 4 路并行 | LLM 调用数 ×4，成本上升 | 支持模式切换（single/multi） |
| 静置批处理 | 记忆延迟可用 | 保留实时触发作为 opt-in |
| soul → agent_rules | 历史记忆不兼容 | 数据迁移脚本 + 读取时 alias |
| 存储抽象 | tcvectordb 适配层重写 | 新旧引擎并存，特性开关切换 |
