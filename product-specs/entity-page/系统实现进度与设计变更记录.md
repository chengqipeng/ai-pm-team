## 一、架构概览

### 变更 7：团队成员权限分配

团队成员是数据级别的权限分配机制，负责人可以将数据共享给其他用户。

| 项目 | 说明 |
|------|------|
| 底层存储 | 复用 `p_data_share` 表，`share_cause=1`（团队成员） |
| 权限主体 | `subject_type=0`（USER），`subject_api_key=userId` |
| 权限级别 | `access_level`: 1=只读, 2=读写 |
| 权限生效 | `DataPermissionFilter.buildCondition` → `DataShareQueryService.getVisibleDataIds` → `PermissionCondition.applyTo` |
| 服务层 | `TeamMemberService`：addMember/removeMember/listMembers/replaceMembers |
| API 层 | `TeamMemberApiService`：RESTful CRUD，路径 `/entity/data/{entity}/{dataId}/team-members` |

权限过滤链路（无需修改，已有基础设施自动生效）：
```
用户请求 → DataPermissionFilter.buildCondition()
  → UserSubjectService.getUserSubjects(userId)  // 展开用户主体
  → DataShareQueryService.getVisibleDataIds()    // 查 share 表（含 share_cause=1 的团队成员记录）
  → PermissionCondition.filterWith()             // 构建不可变条件
  → PermissionCondition.applyTo(qw)              // 注入 SQL: OR id IN (visibleDataIds)
```

| itemType | 控件 | 数据来源判断 |
|----------|------|-------------|
| 2(SELECT) + referGlobalFlg=1 | 全局选项集下拉 | `/meta/metadata/global-pick-options?globalPickApiKey={globalPickItemApiKey}` |
| 2(SELECT) + referGlobalFlg≠1 | 普通下拉 | `/meta/metadata/pick-options?itemApiKey={apiKey}` |
| 3(MULTI_SELECT) | 多选标签 | 同上 |
| 10(REFER) | 关联实体下拉 | `/entity/data/{referEntityApiKey}` |
| 27(FORMULA) | 不显示 | 计算型字段 |
| 5(INTEGER) | 数字输入 | — |
| 6(REAL) / 33(PERCENT) | 小数输入 | — |
| 7(DATE) | 日期选择 | — |
| 38(DATETIME) | 日期时间选择 | — |
| 31(BOOL) | 开关 | — |
| 22(PHONE) | 电话输入 | — |
| 23(EMAIL) | 邮箱输入 | — |
| 24(URL) | 网址输入 | — |
| 1(TEXT) / 其他 | 文本输入 | — |

省市区级联：fCity 按 `parentMetadataApiKey === form.fState` 过滤，fDistrict 按 `parentMetadataApiKey === form.fCity` 过滤。
