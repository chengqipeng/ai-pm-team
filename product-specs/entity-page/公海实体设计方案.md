# 公海实体设计方案

> 日期：2026-04-25
> 参考：老系统 `a_high_sea` 表 + `TerritoryHighSea` 区域公海模块

## 一、老系统公海模型分析

### 1.1 客户公海（a_high_sea）

老系统的公海是一个独立表 `a_high_sea`，核心字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 公海池 ID |
| name | VARCHAR | 公海池名称 |
| assignRule | SMALLINT | 领取规则：0=自行领取，1=手动分配 |
| recycleRule | SMALLINT | 回收规则：0=自动回收，1=手动回收 |
| transferRule | SMALLINT | 转移规则：0=仅管理员，1=成员也可转移 |
| noNewOpportunity | INT | 无新商机回收天数 |
| noTransferDay | INT | 无成交回收天数 |
| noActivitiesDay | INT | 无活动回收天数 |
| noNextActivitiesDay | INT | 无再次跟进回收天数 |
| noNextTransferDay | INT | 无再次赢单回收天数 |
| noActivitiesAfterWonDay | INT | 赢单后无跟进回收天数 |
| remindDay | INT | 提前提醒天数 |
| receiveForbidDay | INT | 回收后禁止领取天数 |
| canApplyDelay | SMALLINT | 是否允许延期申请 |
| allowOthersToJoin | SMALLINT | 是否允许其他成员加入 |
| complyWithCurrentRule | SMALLINT | 自建数据遵守回收规则 |
| claimLimitDay | INT | 回收后不可再领天数 |
| thawDay | INT | 解冻天数 |
| releaseLimit | INT | 主动退回次数限制 |
| isOpportunity | SMALLINT | 回收条件含商机 |
| isSaleOrder | SMALLINT | 回收条件含订单 |
| isContract | SMALLINT | 回收条件含合同 |

### 1.2 领取上限（a_account_high_sea_assign_limit）

| 字段 | 类型 | 说明 |
|------|------|------|
| userId | BIGINT | 用户 ID |
| assignLimit | INT | 该用户的领取上限 |

### 1.3 区域公海（Territory High Sea）

区域公海不是独立表，而是 territory（销售区域）实体上的扩展功能：
- 每个 territory 可以配置为"公海区域"
- 客户通过 `territoryHighSeaId` 字段关联到区域公海
- 区域公海有独立的回收规则、成员管理

### 1.4 客户与公海的关联

account 表中的公海相关字段：
- `highSeaId` → 所属客户公海池 ID
- `highSeaStatus` → 公海状态（active/inactive/inHighSea/claimed）
- `highSeaAccountSource` → 客户来源（公海维度）
- `territoryHighSeaId` → 所属区域公海（关联 territory）
- `claimTime` → 认领时间
- `expireTime` → 到期时间
- `releaseDescription` → 退回描述

## 二、新系统公海实体设计

### 2.1 设计原则

1. **公海池作为标准实体**：注册为 `highSea` 实体，存储在 `p_tenant_data` 分表中
2. **元数据驱动**：字段定义在 `p_common_metadata`（metamodel_api_key='item', entity_api_key='highSea'）
3. **简化回收规则**：P0 阶段只实现核心的回收天数配置，复杂规则（延期申请、解冻等）P2 实现
4. **区域公海复用 territory**：territory 实体增加 `highSeaFlg` 开关，标记为公海区域

### 2.2 highSea 实体字段设计

| apiKey | label | itemType | dbColumn | 说明 |
|--------|-------|----------|----------|------|
| highSeaName | 公海池名称 | 1(TEXT) | name | 主属性 |
| assignRule | 领取规则 | 2(SELECT) | dbc_smallint1 | 0=自行领取 1=手动分配 |
| recycleRule | 回收规则 | 2(SELECT) | dbc_smallint2 | 0=自动回收 1=手动回收 |
| transferRule | 转移规则 | 2(SELECT) | dbc_smallint3 | 0=仅管理员 1=成员可转移 |
| noActivitiesDay | 无跟进回收天数 | 5(INT) | dbc_int1 | 天数，0=不启用 |
| noNewOpportunityDay | 无新商机回收天数 | 5(INT) | dbc_int2 | 天数，0=不启用 |
| noTransferDay | 无成交回收天数 | 5(INT) | dbc_int3 | 天数，0=不启用 |
| remindDay | 提前提醒天数 | 5(INT) | dbc_int4 | 回收前提醒 |
| claimLimitDay | 回收后禁领天数 | 5(INT) | dbc_int5 | 回收后多少天不可再领 |
| releaseLimit | 主动退回次数限制 | 5(INT) | dbc_int6 | 0=不限制 |
| enableFlg | 是否启用 | 31(BOOL) | dbc_smallint4 | 1=启用 0=停用 |
| description | 描述 | 4(TEXTAREA) | dbc_textarea1 | |

### 2.3 account 字段关联修正

| account 字段 | 修改 |
|-------------|------|
| highSeaId | itemType 改为 10(REFER)，referEntityApiKey='highSea' |
| territoryHighSeaId | 保持 10(REFER)，referEntityApiKey='territory' |
| highSeaStatus | 保持 2(SELECT)，pickOption 已有 |
| claimTime / expireTime | 保持 7(DATE)，系统自动填充 |

## 三、实现步骤

### 3.1 注册 highSea 实体元数据

在 `init_local_dev.py` 中：
1. 在 `STANDARD_ENTITIES` 中添加 `highSea`
2. 注册 entity 元数据（p_common_metadata, metamodel_api_key='entity'）
3. 注册 item 字段定义
4. 注册 defaultBusiType
5. 分配分表路由

### 3.2 初始化种子数据

创建 2-3 个默认公海池：
- 默认客户公海（全公司共享）
- VIP 客户公海（高价值客户专用）

### 3.3 修正 account.highSeaId 字段

将 `highSeaId` 的 itemType 从 5(INT) 改为 10(REFER)，设置 referEntityApiKey='highSea'。
