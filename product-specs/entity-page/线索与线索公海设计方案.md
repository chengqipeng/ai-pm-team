## 二、线索公海实体设计（leadHighSea）

### 2.1 设计原则

1. 与客户公海（highSea）**结构一致**，独立实体独立管理
2. 注册为标准实体，存储在 `p_tenant_data` 分表中
3. 回收规则针对线索场景简化（无商机/订单/合同条件）

### 2.2 leadHighSea 字段设计

| # | apiKey | 标签 | itemType | dataType | dbColumn | 说明 |
|---|--------|------|----------|----------|----------|------|
| 1 | leadHighSeaName | 公海池名称 | 1(TEXT) | 1(VARCHAR) | name | 主属性 |
| 2 | assignRule | 领取规则 | 2(SELECT) | 1(VARCHAR) | dbc_smallint1 | 0=自行领取 1=手动分配 |

### 2.3 与客户公海（highSea）的对比

| 维度 | highSea（客户公海） | leadHighSea（线索公海） |
|---|---|---|
| 管理对象 | account（客户） | lead（线索） |
| 回收条件 | 无跟进/无商机/无成交/提醒/禁领/退回限制 | 无跟进/无联系/提醒/禁领/退回限制 |
| 差异 | 有"无新商机""无成交"条件 | 无商机/订单条件，增加"无联系"条件 |
| 转化出口 | 无（客户不转化） | L2O 转化为客户+联系人+商机 |

## 四、线索公海状态机

```
                    ┌──────────┐
         新建线索 ──→│  active   │──→ 分配给 SDR
                    └────┬─────┘
                         │ 超时未跟进 / 手动退回
                         ▼
                    ┌──────────┐
                    │ inHighSea│──→ 在公海池中等待领取
                    └────┬─────┘
                         │ SDR 领取 / 管理员分配
                         ▼
                    ┌──────────┐
                    │ claimed  │──→ 已被领取，跟进中
                    └────┬─────┘
                    ┌────┴─────┐
                    ▼          ▼
             ┌──────────┐ ┌──────────┐
             │converted │ │ invalid  │
             │ 已转化    │ │ 无效     │
             └──────────┘ └──────────┘
```

### pickOption 定义

| apiKey | label | 说明 |
|---|---|---|
| active | 活跃 | 新建/已分配，正常跟进中 |
| inHighSea | 公海中 | 在公海池等待领取 |
| claimed | 已领取 | 从公海领取，跟进中 |
| converted | 已转化 | L2O 转化为客户+商机 |
| invalid | 无效 | 标记为无效线索 |

## 五、线索公海核心操作 API

### 5.1 领取线索

```
POST /entity/data/lead/{id}/claim
```

业务逻辑：
1. 校验线索 `leadHighSeaStatus = 'inHighSea'`
2. 校验当前用户是否有领取权限（公海池成员 + 未超过持有上限）
3. 设置 `ownerId = 当前用户`，`claimTime = now`，`leadHighSeaStatus = 'claimed'`
4. 计算 `expireTime = claimTime + 回收天数`

### 5.2 退回线索到公海

```
POST /entity/data/lead/{id}/release
Body: { "releaseReason": "opt_no_response", "releaseDefinition": "多次联系无回应" }
```

业务逻辑：
1. 校验线索 `leadHighSeaStatus = 'claimed'` 且 `ownerId = 当前用户`
2. 校验退回次数未超过 `releaseLimit`
3. 设置 `lastOwnerId = ownerId`，`ownerId = null`，`leadHighSeaStatus = 'inHighSea'`
4. 设置 `releaseTime = now`，`releaseNum += 1`

### 5.3 线索转化（L2O）

```
POST /entity/data/lead/{id}/convert
Body: {
  "accountName": "华为技术有限公司",
  "contactName": "张三",
  "opportunityName": "华为 CRM 项目",
  "existingAccountId": null  // 关联已有客户时传 ID
}
```

业务逻辑：
1. 创建或关联客户（account）
2. 创建联系人（contact），关联到客户
3. 创建商机（opportunity），关联到客户和联系人
4. 设置线索 `leadHighSeaStatus = 'converted'`，`opportunityId = 新商机 ID`

### 5.4 自动回收

定时任务（每小时执行）：
```sql
-- 查找超时线索
SELECT id FROM p_tenant_data_{N}
WHERE entity_api_key = 'lead'
  AND lead_high_sea_status = 'claimed'
  AND expire_time < EXTRACT(EPOCH FROM NOW()) * 1000
  AND delete_flg = 0;
```

## 六、实体关联关系

```
leadHighSea (线索公海池)
    │
    │ lead.leadHighSeaId → leadHighSea.id
    ▼
lead (线索)
    │
    │ L2O 转化
    ├──→ account (客户)     lead.opportunityId 记录转化结果
    ├──→ contact (联系人)
    └──→ opportunity (商机)
```

### entityLink 定义

| apiKey | label | parent | child | referItemApiKey | cascadeDelete |
|---|---|---|---|---|---|
| leadHighSea_to_lead | 公海线索 | leadHighSea | lead | leadHighSeaId | 0(不级联) |
| lead_to_opportunity | 转化商机 | lead | opportunity | — | 0(不级联) |
| lead_to_contact | 转化联系人 | lead | contact | contactId | 0(不级联) |
