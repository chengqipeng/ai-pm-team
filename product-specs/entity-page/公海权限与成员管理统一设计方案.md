# 公海权限与成员管理 — 统一设计方案

> 日期：2026-04-29
> 范围：客户公海(highSea) + 线索公海(leadHighSea) + 区域公海(territory) + 成员管理 + 权限体系
> 原则：元模型驱动、departApiKey 全链路、统一权限判定

---

## 一、老系统问题与新系统目标

### 1.1 老系统问题

| 问题 | 说明 |
|------|------|
| 三套独立代码 | 客户公海、线索公海、区域公海各自独立实现，逻辑重复 |
| departId 硬编码 | 成员范围通过 `userId + departId`（Long）关联，已废弃 |
| 权限散落 | `canClaim`/`canAllot`/`canChange`/`canDetail` 分散在 Util 类中 |
| 成员管理独立表 | `a_high_sea_member`/`a_lead_high_sea_member` 独立表，不走元数据 |
| 区域公海过度复杂 | 27 个子实体、137 个 Java 文件，大量功能未使用 |

### 1.2 新系统目标

```
一套权限引擎 × 三种公海类型 × 统一成员模型
```

- 公海池成员用 **子实体** 存储在大宽表，走元数据标准链路
- 部门范围用 `departApiKey`（String），不再用 `departId`（Long）
- 权限判定统一为一个 `HighSeaPermissionService`，三种公海共用
- 区域公海精简为 territory 实体扩展，不引入 27 个子实体

## 三、成员子实体设计

### 3.1 highSeaMember（客户公海成员）

注册为 entity 的子实体，数据存储在 `p_tenant_data` 大宽表。

**entity 注册：**

| 属性 | 值 |
|---|---|
| api_key | highSeaMember |
| label | 公海池成员 |
| namespace | system |
| enableFlg | 1 |

**字段定义：**

| # | apiKey | label | itemType | dataType | dbColumn | referEntityApiKey | 说明 |
|---|--------|-------|----------|----------|----------|-------------------|------|
| 1 | highSeaId | 所属公海池 | 10(REFER) | 3(BIGINT) | dbc_bigint1 | highSea | 关联公海池 |
| 2 | userId | 成员用户 | 10(REFER) | 3(BIGINT) | dbc_bigint2 | user | 关联用户 |
| 3 | memberRole | 成员角色 | 2(SELECT) | 6(SMALLINT) | dbc_smallint1 | — | 0=普通成员 1=管理员 2=默认管理员 |
| 4 | memberStatus | 成员状态 | 2(SELECT) | 6(SMALLINT) | dbc_smallint2 | — | 1=启用 0=停用 |

**entityLink：**

| apiKey | parent | child | referItemApiKey | cascadeDelete |
|---|---|---|---|---|
| highSea_to_member | highSea | highSeaMember | highSeaId | 1(级联删除) |

### 3.2 highSeaDepart（客户公海部门范围）

| # | apiKey | label | itemType | dataType | dbColumn | referEntityApiKey | 说明 |
|---|--------|-------|----------|----------|----------|-------------------|------|

| 3 | includeChildFlg | 含下级部门 | 31(BOOLEAN) | 6(SMALLINT) | dbc_smallint1 | — | 1=包含子部门 |

**entityLink：**

| apiKey | parent | child | referItemApiKey | cascadeDelete |
|---|---|---|---|---|

### 3.3 leadHighSeaMember / leadHighSeaDepart

结构与 highSeaMember / highSeaDepart **完全一致**，仅 `highSeaId` 改为 `leadHighSeaId`，referEntityApiKey 改为 `leadHighSea`。

| 实体 | 字段差异 |
|---|---|
| leadHighSeaMember | `leadHighSeaId` → referEntityApiKey = `leadHighSea` |
| leadHighSeaDepart | `leadHighSeaId` → referEntityApiKey = `leadHighSea` |

### 3.4 territory 成员（复用已有 territory 体系）

territory 实体已有 `ownerId`（区域负责人），区域成员管理复用 `TeamMemberPanel`（已实现的团队成员功能），不新增子实体。区域管理员 = 团队成员中 `accessLevel = 2` 的用户。

## 四、统一权限引擎

### 4.1 角色定义

三种公海共用同一套角色体系：

| 角色 | 判定方式 | 权限级别 |
|------|---------|---------|
| **系统管理员** | `DataPermission.canOperateAll(entity, UPDATE)` | 最高，所有操作 |
| **公海管理员** | `highSeaMember.memberRole IN (1, 2)` | 分配、领取、转移、查看 |
| **公海成员** | `highSeaMember.memberRole = 0` 或 用户部门在 `highSeaDepart` 范围内 | 领取（自行领取模式）、查看 |
| **非成员** | 不在成员列表且部门不在范围内 | 无权限 |

### 4.2 操作权限矩阵

| 操作 | 系统管理员 | 公海管理员 | 公海成员 | 非成员 | 受配置影响 |
|------|:---------:|:---------:|:-------:|:-----:|-----------|
| 查看公海列表 | ✅ | ✅ | ✅ | ❌ | — |
| 查看数据详情 | ✅ | ✅ | ✅ | ❌ | — |
| 领取 | ✅ | ✅ | ✅ | ❌ | `assignRule=0` 时成员可领取；`=1` 时仅管理员可分配 |
| 分配 | ✅ | ✅ | ❌ | ❌ | — |
| 退回 | ✅ | ✅ | ✅(仅自己的) | ❌ | — |
| 转移分组 | ✅ | ✅ | 按配置 | ❌ | `transferRule=1` 时成员可转移 |
| 修改团队成员 | ✅ | ✅ | ❌ | ❌ | — |
| 删除 | ✅ | ✅ | ❌ | ❌ | — |

### 4.3 成员判定逻辑（伪代码）

```java
/**
 * 统一的公海权限判定。
 * 适用于 highSea / leadHighSea / territory（区域公海）。
 */
public class HighSeaPermissionService {

    /** 判定用户在指定公海池中的角色 */
    public HighSeaRole resolveRole(String poolEntityApiKey, long poolId, Long userId) {
        // 1. 系统管理员 → 最高权限
        if (canOperateAll(poolEntityApiKey, userId)) {
            return HighSeaRole.SYSTEM_ADMIN;
        }

        // 2. 查成员表（highSeaMember / leadHighSeaMember）
        String memberEntity = poolEntityApiKey + "Member";  // highSeaMember / leadHighSeaMember
        Map<String, Object> member = findMember(memberEntity, poolId, userId);
        if (member != null) {
            int role = toInt(member.get("dbc_smallint1")); // memberRole
            if (role == 1 || role == 2) return HighSeaRole.POOL_ADMIN;
            return HighSeaRole.POOL_MEMBER;
        }

        // 3. 查部门范围（highSeaDepart / leadHighSeaDepart）
        String departEntity = poolEntityApiKey + "Depart";
        String userDeptApiKey = getUserDepartApiKey(userId);  // ← departApiKey，非 departId
        if (isDepartInScope(departEntity, poolId, userDeptApiKey)) {
            return HighSeaRole.POOL_MEMBER;
        }

        return HighSeaRole.NONE;
    }

    /** 部门范围判定：用户部门是否在公海池的部门范围内 */
    private boolean isDepartInScope(String departEntity, long poolId, String userDeptApiKey) {
        List<Map<String, Object>> depts = listPoolDeparts(departEntity, poolId);
        for (Map<String, Object> dept : depts) {
            String scopeDeptApiKey = (String) dept.get("dbc_varchar1");  // departApiKey
            if (scopeDeptApiKey.equals(userDeptApiKey)) return true;
            // includeChildFlg = 1 时，检查用户部门是否是该部门的下级
            int includeChild = toInt(dept.get("dbc_smallint1"));
            if (includeChild == 1 && isDescendantDept(userDeptApiKey, scopeDeptApiKey)) {
                return true;
            }
        }
        return false;
    }
}
```

### 4.4 区域公海的权限适配

区域公海复用同一套权限引擎，但成员来源不同：

| 维度 | 普通公海 | 区域公海 |
|------|---------|---------|
| 成员来源 | `highSeaMember` / `leadHighSeaMember` 子实体 | territory 的团队成员（`p_data_share`） |
| 管理员判定 | `memberRole IN (1,2)` | 团队成员 `accessLevel = 2` |
| 部门范围 | `highSeaDepart` / `leadHighSeaDepart` 子实体 | territory 自身的 `departApiKey` |
| 权限入口 | `resolveRole("highSea", poolId, userId)` | `resolveRole("territory", territoryId, userId)` |

## 五、领取限额机制

### 5.1 限额配置

| 级别 | 配置位置 | 说明 |
|------|---------|------|
| 公海池级别 | `highSea.claimMaxCount` / `leadHighSea.claimMaxCount` | 每人在该公海池最多持有数 |
| 全局级别 | 系统设置（后续扩展） | 每人跨所有公海池最多持有数 |

### 5.2 限额校验逻辑

```
领取前校验：
  1. 查询用户当前持有数量
     SELECT COUNT(*) FROM p_tenant_data_{N}
     WHERE entity_api_key = 'lead'
       AND owner_id = :userId
       AND dbc_varchar9 = 'claimed'   -- leadHighSeaStatus = claimed
       AND dbc_bigint5 = :highSeaId   -- leadHighSeaId = 当前公海池
       AND delete_flg = 0
  2. 如果 持有数 >= claimMaxCount → 拒绝领取
  3. 校验冷却期：退回后 claimLimitDay 天内不可再领
  4. 校验冻结：退回次数 >= releaseLimit → 冻结
```

## 六、核心操作流程（统一）

### 6.1 领取

```
前端 → PUT /entity/data/{entity}/{id}/claim
         │
         ▼
HighSeaOperationService.claim(entityApiKey, dataId, userId, highSeaId)
         │
         ├── 1. 权限校验
         │     role = permissionService.resolveRole(poolEntity, poolId, userId)
         │     if (role == NONE) → 403
         │     if (assignRule == 1 && role < POOL_ADMIN) → 403 "该公海池为手动分配模式"
         │
         ├── 2. 限额校验
         │     if (claimMaxCount > 0 && 持有数 >= claimMaxCount) → 400 "超过持有上限"
         │
         ├── 3. 冷却期校验
         │     if (claimLimitDay > 0 && 该用户最近退回该数据 < claimLimitDay 天) → 400
         │
         ├── 4. 冻结校验
         │     if (releaseLimit > 0 && 该数据退回次数 >= releaseLimit) → 400 "已冻结"
         │
         └── 5. 执行领取
               UPDATE: ownerId=userId, status='claimed', claimTime=now,
                       expireTime=now+回收天数
               初始化数据权限 share
```

### 6.2 退回

```
前端 → PUT /entity/data/{entity}/{id}/release
         │
         ├── 1. 校验：当前用户是 ownerId 或 管理员
         ├── 2. 更新：ownerId=null, status='inHighSea', lastOwnerId=原ownerId
         ├── 3. 累加 releaseNum
         ├── 4. 如果 releaseNum >= releaseLimit → 设置冻结状态
         └── 5. 清理数据权限 share
```

### 6.3 分配

```
前端 → PUT /entity/data/{entity}/{id}/assign
         │
         ├── 1. 权限校验：必须是管理员或系统管理员
         ├── 2. 限额校验：目标用户的持有数
         └── 3. 执行：同领取，但 operator ≠ targetUser
```

## 七、数据可见性

### 7.1 公海池列表可见性

```
用户能看到哪些公海池？
  ├── 系统管理员 → 所有公海池
  └── 普通用户 → resolveRole != NONE 的公海池

```
用户能看到公海池内哪些数据？
  ├── 系统管理员 / 公海管理员 → 该公海池所有数据
  └── 公海成员 → 该公海池中 status='inHighSea' 的数据（可领取的）
       + 自己 ownerId 的数据（已领取的）

## 八、与现有系统的集成点

### 8.1 DataPermissionFilter 扩展

当前 `DataPermissionFilter.checkAccess()` 不感知公海。需要扩展：

```java
// 在 checkAccess 中增加公海管理员判定
if (access == null || access == 0) {
    // 当前用户无通用数据权限，检查是否是公海管理员
    Long highSeaId = getHighSeaId(record);  // 从记录中取 highSeaId
    if (highSeaId != null) {
        HighSeaRole role = permissionService.resolveRole(poolEntity, highSeaId, userId);
        if (role.isAdmin()) return 2;  // 管理员有读写权限
        if (role.isMember()) return 1; // 成员有只读权限
    }
}
```

### 8.2 HighSeaOperationService 扩展

在现有 `claim`/`release`/`assign`/`transfer` 方法中注入权限校验：

```java
// 现有代码（无权限校验）
public void claim(String entityApiKey, long dataId, Long userId, Long highSeaId) {
    // 直接执行 UPDATE ...
}

// 扩展后
public void claim(String entityApiKey, long dataId, Long userId, Long highSeaId) {
    // 1. 权限校验（新增）
    String poolEntity = resolvePoolEntity(entityApiKey);  // account→highSea, lead→leadHighSea
    HighSeaRole role = permissionService.resolveRole(poolEntity, highSeaId, userId);
    if (role == HighSeaRole.NONE) throw new ForbiddenException("无权限");
    
    // 2. 读取公海池配置（新增）
    Map<String, Object> pool = getPoolConfig(poolEntity, highSeaId);
    int assignRule = toInt(pool.get("dbc_smallint1"));
    if (assignRule == 1 && !role.isAdmin()) throw new ForbiddenException("该公海池为手动分配模式");
    
    // 3. 限额校验（新增）
    int claimMaxCount = toInt(pool.get("dbc_bigint6"));
    if (claimMaxCount > 0) {
        long held = countHeldByUser(entityApiKey, userId, highSeaId);
        if (held >= claimMaxCount) throw new LimitExceededException("超过持有上限");
    }
    
    // 4. 执行领取（现有逻辑）
    // ...
}
```

## 十、关键设计决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 成员存储方式 | 子实体（大宽表） | 走元数据标准链路，支持自定义字段扩展，前端复用 EntityDataList |
| 部门关联字段 | `departApiKey`（VARCHAR） | 新系统已全量迁移，禁止 departId（Long） |
| 三种公海共用权限引擎 | `HighSeaPermissionService` 统一入口 | 避免老系统三套代码重复的问题 |
| 区域公海不新增子实体 | 复用 territory 团队成员 | 避免老系统 27 个子实体的复杂度 |
| 权限校验在 Service 层 | 不在 Controller 层 | 保证 API 调用和定时任务都经过校验 |
| 成员角色用 SELECT 字段 | 不用独立的 role 表 | 公海成员角色简单（3 种），不需要 RBAC |
