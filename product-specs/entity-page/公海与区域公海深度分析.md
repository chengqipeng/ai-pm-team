# 公海与区域公海 — 老系统深度分析

> 基于 apps-salescloud-service 源码分析 | 2026-04-27

---

## 一、两套公海体系的本质区别

老系统有**两套完全独立的公海体系**，不是同一个东西的两个字段：

| 维度 | 客户公海（Account HighSea） | 区域公海（Territory HighSea） |
|------|--------------------------|---------------------------|
| 代码位置 | `paas-customize-service/.../highsea/` | `apps-salescloud-service/.../territorymanagement/` |
| 数据模型 | 独立表 `a_high_sea`（AccountHighSeaEntity） | 元数据驱动，territory 实体体系（27 个子实体） |
| 关联字段 | `highSeaId`（dbc_bigint8）→ 公海池 ID | `territoryHighSeaId`（dbc_bigint27）→ 区域 ID |
| 状态字段 | `highSeaStatus`（dbc_varchar21） | `territoryHighSeaStatus`（独立字段） |
| 适用场景 | 简单公海：按部门划分，一个公海池对应一组销售 | 区域公海：按区域模型划分，支持多维度覆盖、规则引擎 |
| 复杂度 | 低（CRUD + 定时回收） | 极高（137 个 Java 文件，含审批流、MQ、缓存体系） |

| recycleRule | Short | 回收规则：0=自动回收, 1=手动回收 |
| transferRule | Short | 转移规则：0=仅管理员, 1=成员可转 |
| noActivitiesDay | Integer | 无跟进回收天数 |
| noNewOpportunity | Integer | 无新商机回收天数 |
| noTransferDay | Integer | 无成交回收天数 |
| noNextActivitiesDay | Integer | 无再次跟进回收天数 |
| noActivitiesAfterWonDay | Integer | 赢单后无跟进回收天数 |
| remindDay | Integer | 提前提醒天数 |

### 2.2 account 上的关联字段

### 2.3 核心流程

- `HighSeaAssignLimitServiceImpl` — 领取限额管理

## 三、区域公海（Territory HighSea）

### 3.1 架构概览

区域公海是一个**完整的区域管理平台**，远比客户公海复杂：

```
territorymanagement/
├── territoryhighsea/           # 区域公海核心
│   ├── flow/service/           # 审批流（领取审批、退回审批、延期审批）
│   │   ├── HighSeaClaimFlowImpl      # 领取审批流
│   │   ├── HighSeaReleaseFlowImpl    # 退回审批流
│   │   └── HighSeaDelayFlowImpl      # 延期审批流
│   ├── rest/                   # REST API（TerritoryHighSeaRest）
│   ├── service/                # 服务层（2800+ 行）
│   └── dto/                    # 数据传输对象
├── territoryworkobjectassignment/
│   └── highsea/                # 公海操作实现
│       ├── impl/
│       │   ├── HighSeaClaimImpl      # 领取
│       │   ├── HighSeaReleaseImpl    # 退回
│       │   ├── HighSeaRecycleImpl    # 回收
│       │   ├── HighSeaAssignImpl     # 分配
│       │   ├── HighSeaChangeImpl     # 换组
│       │   ├── HighSeaCloseImpl      # 废弃
│       │   ├── HighSeaRecoverImpl    # 恢复
│       │   ├── HighSeaInitImpl       # 初始化
│       │   ├── HighSeaDeleteImpl     # 删除
│       │   └── HighSeaUnfreezeImpl   # 解冻
│       ├── validate/           # 校验器链
│       └── handler/            # 数据同步处理器
└── util/cache/impl/            # Redis 缓存体系
    ├── highsea/config/         # 公海配置缓存
    ├── highsea/admin/          # 管理员缓存
    ├── highsea/modelconfig/    # 模型配置缓存
    ├── recycle/rule/           # 回收规则缓存
    └── recycle/resourceobject/ # 资源对象缓存
```

### 3.3 区域公海状态

```java
TerritoryHighSeaStatusValue:
  HIGHSEA_STATUS_OWNED = 1      // 自建（销售自己创建的数据）
  HIGHSEA_STATUS_CLAIMED = 2    // 已领取
  HIGHSEA_STATUS_UNCLAIMED = 3  // 未领取（在公海中）
```

### 3.4 核心操作（10 种）

| 操作 | 实现类 | 说明 |
|------|--------|------|
| 领取 claim | HighSeaClaimImpl | 销售从公海领取数据，设置 owner + status=2 |
| 退回 release | HighSeaReleaseImpl | 销售退回数据到公海，清空 owner + status=3 |
| 回收 recycle | HighSeaRecycleImpl | 系统自动回收超时数据 |
| 分配 assign | HighSeaAssignImpl | 管理员分配数据给销售 |
| 换组 change | HighSeaChangeImpl | 数据从一个区域移到另一个区域 |
| 废弃 close | HighSeaCloseImpl | 标记数据为废弃 |
| 恢复 recover | HighSeaRecoverImpl | 恢复废弃的数据 |
| 初始化 init | HighSeaInitImpl | 将数据放入公海 |
| 删除 delete | HighSeaDeleteImpl | 从公海删除数据 |
| 解冻 unfreeze | HighSeaUnfreezeImpl | 解除冻结状态 |

### 3.5 领取流程（HighSeaClaimImpl.operateData）

```
1. 校验公海模型配置是否存在
2. 校验源公海和目标公海是否存在
3. 检查公海领取策略（claimScope: 本级/跨级）
4. 检查全局领取范围
5. 检查 N 天内是否可重复领取
6. 校验特定公海私池数量限制
7. 校验全局私池数量限制
8. 执行更新：
   - territoryId = targetHighSeaId
   - highSeaStatus = CLAIMED(2)
   - assignOwnerId = targetUserId
   - assignTime = now
   - statusUpdatedAt = now
```

## 四、新系统实现建议

### 4.1 当前状态

| 项目 | 状态 |
|------|------|
| highSea 实体（10 条种子数据） | ✅ 已实现 |
| account.highSeaId（dbc_bigint8）关联 | ✅ 已实现，存 highSea 的雪花 ID |
| 120 条客户种子数据关联公海 | ✅ 已实现 |
| 前端新建表单显示"所属公海"下拉 | ✅ 已实现 |
| territoryHighSeaId 前端隐藏 | ✅ 已隐藏 |

### 4.2 P0 — 客户公海核心操作

基于已有的 highSea 实体 + account.highSeaId 关联，实现 4 个核心操作：

| 操作 | API | 业务逻辑 |
|------|-----|---------|
| 领取 | PUT `/entity/data/account/{id}/claim` | 设置 ownerId + highSeaStatus='claimed' + claimTime + expireTime |
| 退回 | PUT `/entity/data/account/{id}/release` | 清空 ownerId + highSeaStatus='inHighSea' + releaseDescription |
| 分配 | PUT `/entity/data/account/{id}/assign` | 设置 ownerId + highSeaStatus='claimed' + claimTime |
| 转移 | PUT `/entity/data/account/{id}/transfer` | 更换 ownerId + 重置 claimTime |

### 4.3 P1 — 区域公海

区域公海是一个独立的大模块（137 个文件），建议作为 P1 独立规划：
- 需要先实现 territory 实体体系（至少 5-6 个核心实体）
- 需要实现区域模型配置
- 需要实现区域成员管理
- 需要实现区域规则引擎
- account.territoryHighSeaId 关联到 territory 实体

### 4.4 数据关联方式确认

**业务数据之间通过雪花 ID（BIGINT）关联**，这是正确的：
- `account.highSeaId`（dbc_bigint8）→ `highSea.id`
- `account.parentAccountId`（dbc_bigint3）→ `account.id`
- `account.territoryHighSeaId`（dbc_bigint27）→ `territory.id`
- 所有 REFER(10) 类型字段的 dbColumn 都是 `dbc_bigint*`

"禁止 ID 关联，统一用 apiKey" 规范适用于**元数据之间**（entity→item 通过 entity_api_key），不适用于业务数据。
