# 因果推导纪律

> 本文件不是"模式库"——不预设任何固定的因果链路。
> 它只定义"怎么推导"的方法论纪律，Agent 基于实际数据自由推导。

## 推导方法（必须遵循的思考步骤）

发现任何事实后，按以下顺序思考：

1. **追问"为什么"** — 至少追溯 1 层原因，最多 2 层。追不到就标注 [gap]，绝不编造。
2. **追问"如果不干预"** — 基于原因做 1 步时间推演（恶化/好转/维持）。推演必须标注时间窗口。
3. **追问"应该做什么"** — 给出具体行动（WHO + WHAT + WHEN），行动必须能被执行而非"建议关注"。

## 推导质量标准

| 等级 | 特征 | 判定 |
|:---|:---|:---|
| ✅ 合格 | 事实→原因(≥1层)→推演(含时间)→行动(WHO/WHAT/WHEN) | 输出 |
| ❌ 不合格-断链 | 有事实但直接跳到行动，缺少原因和推演 | 补全 |
| ❌ 不合格-编造 | 原因或推演无数据支撑 | 改为 [gap] |
| ❌ 不合格-模式套用 | "因为是制造业所以一定是XX" | 用实际数据重新推导 |

## 反过拟合原则

- **不预设因果方向** — 活跃度下降不一定意味着流失；商机停滞不一定是竞品；EB缺失不一定是问题。数据说什么就是什么。
- **允许"没有因果"** — 有些事实就是事实，没有深层原因。这时直接输出事实 + 建议验证方式。
- **允许"推翻假设"** — 如果数据显示假设方向错误，直接推翻并说明推翻原因。推翻本身就是有价值的发现。
- **多解释并存** — 同一事实可能有 2-3 种原因解释。不强制选一个，列出可能性并标注各自的置信度。

## 示例（仅展示格式，不是让你套用内容）

```
好的因果推导：
  [事实] 方案确认阶段停留 45 天（标准 20 天），但近 2 周活动频次正常（6 次）
  [追问为什么] 活动记录中 3 次出现"集团审批""总部签批"关键词
  [原因] 客户内部审批流程卡住（非我方可控因素）[likely]
  [追问如果不干预] 超期 60 天后客户可能重新评估优先级
  [行动] 本周提供 ROI 量化材料帮客户加速内部审批 — 售前负责

坏的因果推导（禁止）：
  [事实] 活跃度下降
  [直接套模板] → 一定是关键人离职 → 一定会流失 → 要激活高管关系
  问题：没有验证关键人是否离职，没有看实际原因，直接套了"流失模式"
```

## 什么时候停止追问

- 追溯 2 层原因后仍无法确定 → 标注 [gap]，建议获取方式
- 原因明显是外部不可控因素（政策/市场）→ 不需要继续追问，直接给应对建议
- 数据充分且因果链清晰 → 1 层原因够了就不要硬凑 2 层
