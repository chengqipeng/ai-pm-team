Design Overview

给 Agent 一套隔离、可控、可审计的文件系统能力

让 Neo Agent V2 能够在受隔离的环境里读写文件、执行命令、运行 Skill 脚本并交付产物——既扩展了 Agent 的"动手"能力，又不牺牲安全与可控性。本页面向团队讲解整体设计思路，不涉及实现细节。

作者 张泽森 日期 2026-06-24 范围 service/neo_agent_v2 定位 设计讲解 · 非开发指导

01 目标与价值

我们要解决的问题：当前 Agent 只能"说"，不能稳定地"做"——无法持久地读写文件、跑脚本、产出可交付的文件结果。

🔒安全隔离

文件读写与命令执行都在隔离沙箱内进行，平台与宿主环境不被任意访问，危险命令被拦截。

🧩会话隔离

每个会话（conversation）拥有独立的工作目录与数据，互不可见，多租户、多用户天然隔离。

🤖模型自主

通过提示引导而非硬编码规则，让模型自己判断何时该用文件能力，保留灵活性。

📦可交付

Agent 产出的文件可登记为"交付物"，前端直接渲染/下载，形成完整闭环。

⚡按需启用

纯聊天请求不创建沙箱，零额外成本；只有真正用到文件能力时才懒加载启动。

🛡️可审计可治理

命令分级审计、超大输出落盘治理，既防风险也防上下文被撑爆。

一句话定位：把"文件 + 命令 + Skill 脚本执行"作为一组工具，安全地接进现有 Agent 的中间件/工具体系，让模型按需、自主地使用。

02 能力边界

明确"做什么、不做什么、什么时候做"，避免对能力的误解。

一期范围 本期

  • 文件读 / 写 / 搜索（ls、read_file、glob、grep、write_file、str_replace）
  • 命令与 Skill 脚本执行（bash）+ 命令安全审计
  • 交付物登记与前端呈现（present_files）
  • 会话级目录隔离、沙箱按需启动 / 挂起
  • 个人 / 租户 Skill 只读挂载 + 提示引导渐进式加载
  • 主 / 子 Agent 共享同一沙箱：子 Agent 继承沙箱中间件与工具后，复用主 Agent 的沙箱实例与数据，无需重复创建

二期 / 后续 规划

  • 用户上传文件接入沙箱目录 + 上传清单注入
  • 多模态：读取图片供模型查看分析
  • 跨 Agent 工作区、产物清单自动注入等增强

明确不做

  • 不自研执行后端（复用平台远端沙箱）
  • 不承载应用数据层（记忆 / 会话 / 检查点等是另一套持久化，与沙箱无关）

03 整体架构

能力横跨三层，自上而下：提示引导（告诉模型怎么用）→ 中间件编排（管理生命周期与安全）→ 工具与执行（实际干活），底层对接平台托管的远端隔离沙箱。

第 1 层 · 提示引导

告诉 Agent「有哪些目录、何时用、怎么用」

在系统提示里说明工作目录职责、文件操作方法论，并把每个 Skill 的沙箱路径注入，引导模型渐进式加载。不写死规则，靠语义引导。
工作目录说明文件操作方法论Skill 路径注入
↓
第 2 层 · 中间件编排

管理「目录准备 → 启动沙箱 → 安全审计 → 输出治理」

把横切关注点按顺序串进 Agent 执行流程：准备目录信息、按需启动/挂起沙箱、拦截危险命令、治理超大输出。
Workspace 中间件Sandbox 中间件命令审计中间件输出治理中间件
↓
第 3 层 · 工具与执行

把沙箱能力封装成 Agent 可调用的工具

一组文件工具（读/写/搜/执行/交付），每个工具先确保沙箱就绪，再委托给沙箱接口执行。
ls / read_fileglob / grepwrite_file / str_replacebashpresent_files
↓
底座 · 远端沙箱

平台托管的远端隔离沙箱 + 持久化存储

不自己跑容器：复用平台提供的远端沙箱原子能力（创建/执行/读写/挂起/恢复），文件持久化到对象存储，按会话隔离。我方只做一层适配。
隔离执行环境会话级存储隔离挂起 / 恢复 / 自动回收
设计原则：复用现有 Agent 装配机制（工具 + 中间件）、请求级状态走图 state（可在主/子 Agent 间传播）、懒加载优先、失败不打断主流程、单一开关可灰度。

04 实现分层 · 每层包含什么、各自作用

这是讲解的重点：每一层由哪些组件构成，它们各自负责什么。只讲职责与用途，不展开实现。

① 提示引导层

组件职责与作用
工作目录说明告诉模型有哪些目录（工作区 / 交付区 / 只读 Skill 区）及各自用途，把工作区作为默认落脚点。
文件操作方法论引导"改文件优先用替换、长文件分段写、成品落交付区"等最佳实践，避免低效或超限操作。
Skill 路径注入把每个 Skill 在沙箱里的目录路径写进提示，让模型"先读说明 → 再按需读资源 / 跑脚本"渐进式加载。

② 中间件编排层

中间件职责与作用
Workspace 中间件请求开始时计算本会话的目录布局，并把目录信息注入系统提示。是"目录准备 + 提示注入"的入口。
Sandbox 中间件管理沙箱生命周期：首次用到时启动、全程复用、请求结束时挂起，并把沙箱标识在主/子 Agent 间传播。
命令审计中间件对 bash 命令做安全分级——高危拦截、中危告警、正常放行，并记录审计日志。
输出治理中间件当工具输出过大时落盘并替换为预览引用，避免一次输出撑爆模型上下文（无沙箱时不介入）。
顺序铁律：Workspace 先于 Sandbox（后者依赖前者准备的目录信息）

③ 工具与执行层

📂ls

树形列出目录内容，帮模型了解有哪些文件。

📄read_file

读文本文件，支持按行范围分页读取。

🔎glob

按文件名模式查找路径。

🔍grep

在文件内容中搜索匹配行。

✍️write_file

写入 / 追加文本，带单次写入大小上限。

♻️str_replace

对文件做子串替换，适合增量改动。

⌨️bash

在隔离环境执行命令 / 运行 Skill 脚本。

📤present_files

把交付区文件登记为产物，推送前端渲染 / 下载。

工具是"瘦封装"：只做路径校验 → 确保沙箱就绪 → 委托执行三件事，真正的 I/O 全部交给底层沙箱。整组工具由单一开关控制启停，便于灰度。

④ 底座 · 远端沙箱与目录体系

🗂️目录体系

  • 工作区：临时 / 中间产物，默认工作目录
  • 交付区：最终成品，只有这里能被交付
  • 只读 Skill 区：个人 / 租户两类 Skill，挂载为只读

💾隔离与持久化

  • 按会话隔离，不同会话数据互不可见
  • 文件持久化到对象存储，跨轮次保留
  • 沙箱可挂起 / 恢复，过期自动回收，数据不丢

05 沙箱生命周期（对 Agent 而言）

关键只有两个时刻：什么时候启动、什么时候挂起。沙箱完全挂靠在 Agent 的执行钩子上，按需启动、请求末挂起、中间全程复用。

生命周期锚点（映射到 Agent 钩子）

Agent 钩子沙箱动作时机说明
before_agent不启动准备目录信息并注入系统提示；纯聊天请求沙箱永不启动。
模型决策循环不启动模型未调用沙箱工具时，沙箱保持未启动，零成本。
首个沙箱工具启动第一次真正用到文件能力时，懒加载创建沙箱（幂等，仅建一次）并初始化目录。
后续沙箱工具复用同一请求内只此一个沙箱实例，直接复用；过期自动重建且数据不丢。
after_agent挂起本轮结束即挂起，停计费、保留现场；不销毁，下轮恢复即可继续。
一句话：沙箱 = 首个沙箱工具调用时启动，请求结束（after_agent）时挂起，中间全程复用同一实例。判定都在中间件里完成，对工具与模型透明。

请求内时序

before_agent

准备目录信息 不启动

计算目录布局并注入系统提示。纯聊天请求到此为止，沙箱永不启动。

模型决策循环

等待模型决定 不启动

模型没调用文件工具时，沙箱保持未启动状态，零成本。

首个沙箱工具

启动沙箱 启动时机

第一次真正用到文件能力时，懒加载创建沙箱（幂等，只建一次），并初始化目录。

后续工具调用

复用同一沙箱 复用

同一请求内只有一个沙箱实例，后续工具直接复用；过期会自动重建且数据不丢。

after_agent

挂起沙箱 挂起时机

本轮结束即挂起，停止计费、保留现场；不销毁。下轮恢复即可继续，工作区文件仍在。

主 / 子 Agent 共享：子 Agent 只要继承了沙箱中间件与工具，就会复用主 Agent 的同一沙箱实例与数据，无需重复创建。

06 安全设计（概览）

多重防护叠加，点到为止。

🧱环境隔离

命令与文件操作都在隔离沙箱内，宿主与平台不可达。

🚧会话隔离

按会话独立存储，跨会话数据互不可见。

⚖️命令分级

bash 命令按风险分级：高危拦截、中危告警、正常放行。

🧭路径校验

拒绝路径穿越、拒绝写只读区与非法路径。

📝审计日志

每次命令执行结构化记录，可追溯。

📐写入上限

单次写入大小受限，防超大写入引发异常。

🪣输出治理

超大输出落盘并替换为预览，保护上下文。

📤交付收口

只有交付区文件能被呈现给用户，形成清晰边界。

07 端到端示例 · 用 Skill 脚本做数据分析

把各层串起来，直观理解整体协作。

1
请求开始，Workspace 中间件准备目录信息并注入系统提示——模型看到工作区、交付区以及可用 Skill 的路径。
2
模型判断要用某个 Skill，调用 read_file 读取该 Skill 的说明——这是首个沙箱工具，沙箱在此刻启动。
3
模型用 write_file 把待分析数据写入工作区。
4
模型用 bash 运行 Skill 脚本——命令审计中间件先做安全分级，再在沙箱内执行。
5
脚本结果写入交付区，模型调用 present_files 把成品登记为交付物，前端渲染 / 下载。
6
请求结束，Sandbox 中间件在 after_agent 把沙箱挂起；下轮可恢复继续，文件仍在。
整个过程模型是自主决策的：用不用文件能力、用哪个工具、读哪个 Skill，都由提示引导下的模型判断，框架只负责安全、生命周期与交付。
