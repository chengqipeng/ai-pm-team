🔄 会话生命周期
功能腾讯云 AGSAWS AgentCore CI差异
创建会话 ✓ Sandbox.create(template, timeout, metadata) ✓ ci.start(name, session_timeout_seconds) 等价
执行命令 ✓ sandbox.commands.run(cmd) ✓ ci.invoke("executeCommand", {command}) 等价
执行代码 ✓ sandbox.run_code(code, language) ✓ ci.invoke("executeCode", {language, code}) 等价
暂停（Pause） ✓ sandbox.pause() — 冻结 microVM，停止计费，进程/内存/磁盘全保留 ✗ 不支持，无此 API 腾讯独有
恢复（Resume） ✓ Sandbox.connect(id) — 瞬时恢复到暂停前状态 ✗ 不支持，只能新建 腾讯独有
销毁 ✓ sandbox.kill() ✓ ci.stop() 等价
状态查询 ✓ sandbox.get_info() → RUNNING/PAUSED/EXPIRED ✓ GetCodeInterpreterSession → ACTIVE/STOPPED AWS 状态更少
过期自动重建 ✓ 远端自动重建，响应返回 new_sandbox_id ✗ 需自行检测+重建（我方已实现） 需适配层
TTL 上限 最大 8 小时（28800s），最小 300s 最大 8 小时（28800s），默认 900s 等价
📁 文件操作
功能腾讯云 AGSAWS AgentCore CI差异
写文件 API ✓ sandbox.files.write(path, content) — 原生 API △ 无原生 API，通过 executeCode(python) 模拟 AWS 无原生
读文件 API ✓ sandbox.files.read(path) — 原生 API △ 无原生 API，通过 executeCommand(cat) 模拟 AWS 无原生
文件上传到沙箱 ✓ SDK 直传字节流 △ 通过 executeCode 写入或 S3 中转 AWS 间接
大文件支持 SDK 直传，无明显限制 受限于 executeCode 的 payload 大小和 stdout 截断（~50KB） 腾讯更强
工作目录 /sandbox/（自定义镜像可控） /tmp/（非 root，根目录不可写） 路径不同
💾 数据持久化与隔离
功能腾讯云 AGSAWS AgentCore CI差异
对象存储挂载 ✓ COS virtiofs 实时挂载，写入即落盘 ✗ 无挂载到单 session 的能力（S3 Files 挂载无隔离） 腾讯独有
写入即持久化 ✓ 天然（COS 挂载） △ 通过 write_file 即时双写 S3 模拟（我方实现） 需适配层
会话隔离 COS subPath 挂载隔离（user/conv 级） ★ microVM 级隔离（操作系统级，更强） AWS 更强
跨轮数据保持 ✓ pause 后 resume，数据原样 △ 通过 S3 sync/restore 模拟（我方实现） 需适配层
TTL 超时后数据 ✓ COS 数据永久保留 △ 需在超时前 sync 到 S3（我方增量 sync 覆盖） 需适配层
进程状态保持 ✓ pause 保留进程、内存、环境变量 ✗ stop 后一切归零，无法保留进程状态 腾讯独有
数据保留期限 COS 数据永久（按 COS 生命周期策略） 会话数据 TTL 30 天（元数据/日志），文件靠 S3 手动管理 机制不同
