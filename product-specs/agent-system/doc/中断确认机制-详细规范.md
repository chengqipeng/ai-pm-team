# 中断确认机制 — 详细规范

> 基于 LangGraph 1.1.9 的 `interrupt()` + `Command(resume=...)` + `MemorySaver` 实现。
> 不是自定义方案，而是 LangGraph 原生的 Human-in-the-Loop 机制。

---

## 一、LangGraph interrupt 原生机制

### 1.1 核心 API

```python
from langgraph.types import interrupt, Command
from langgraph.checkpoint.memory import MemorySaver

# interrupt(value) — 在工具/节点内调用，暂停 graph 执行
# value: 传递给客户端的数据（如选项列表）
# 返回值: 客户端 resume 时传入的数据

# Command(resume=value) — 客户端恢复执行时传入
# resume: 用户的响应数据
```

### 1.2 工作原理

```
┌─────────────────────────────────────────────────────────────────────────┐
│ LangGraph 执行流程（带 interrupt）                                        │
│                                                                          │
│  graph.invoke(input, config={"configurable": {"thread_id": "t1"}})       │
│       │                                                                  │
│       ▼                                                                  │
│  Agent Node → LLM 决定调用 ask_user 工具                                 │
│       │                                                                  │
│       ▼                                                                  │
│  ask_user 工具内部调用 interrupt(value):                                  │
│       │                                                                  │
│       ├─ 1. 将当前 graph 状态写入 checkpointer（MemorySaver）            │
│       ├─ 2. 抛出 GraphInterrupt 异常                                     │
│       ├─ 3. graph.invoke() 返回（不是报错，是正常暂停）                   │
│       └─ 4. 返回值中包含 interrupt 信息：                                │
│            {"__interrupt__": [{                                           │
│              "value": {type:"select", options:[...]},                     │
│              "resumable": true,                                           │
│              "ns": ["ask_user:xxx"]                                       │
│            }]}                                                            │
│                                                                          │
│  ... 等待用户响应 ...                                                    │
│                                                                          │
│  graph.invoke(Command(resume="C001"), config={"configurable":            │
│               {"thread_id": "t1"}})                                       │
│       │                                                                  │
│       ├─ 1. 从 checkpointer 恢复状态（thread_id="t1" 的最新 checkpoint） │
│       ├─ 2. interrupt() 函数返回 "C001"（用户的选择）                    │
│       ├─ 3. ask_user 工具继续执行，返回 "C001" 给 Agent                  │
│       └─ 4. Agent 继续后续工具调用                                       │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.3 关键约束

| 约束 | 说明 |
|------|------|
| **必须有 checkpointer** | 没有 checkpointer，interrupt 无法保存状态，恢复时找不到上下文 |
| **必须有 thread_id** | checkpointer 按 thread_id 存储/恢复状态 |
| **interrupt 在工具内调用** | 不是在 node 外部，而是在工具执行函数内部 |
| **resume 通过 Command 传入** | 不是新的 input，而是 `Command(resume=value)` |
| **同一 thread_id 恢复** | 恢复时必须用相同的 thread_id，才能找到暂停的 checkpoint |

## 二、系统改造方案

### 2.1 改造点清单

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 改造 1：AgentFactory 启用 checkpointer                                   │
│                                                                          │

│ 改造 3：adapter.py 处理 interrupt 返回                                   │
│                                                                          │

│                                                                          │

│ 收到 CUSTOM("interrupt") → 渲染 UI 组件                                 │
```

### 2.2 ask_user 工具实现

```python
from langgraph.types import interrupt
from src.tools.base import Tool
from src.core.dtypes import ToolResult

class AskUserTool(Tool):
    """中断确认工具 — 调用 LangGraph interrupt 暂停执行"""

    @property
    def name(self) -> str:
        return "ask_user"

    def input_schema(self) -> dict:
        return {
            "type": "object",
            "properties": {
                "interrupt_type": {
                    "type": "string",
                    "enum": ["confirm", "select", "multi_select", "input"],
                },
                "title": {"type": "string"},
                "message": {"type": "string"},
                "options": {
                    "type": "array",
                    "items": {"type": "object",
                              "properties": {"id": {"type": "string"},
                                             "label": {"type": "string"},
                                             "description": {"type": "string"}}}
                },
            },
            "required": ["interrupt_type", "title"],
        }

    async def call(self, input_data: dict, context, on_progress=None) -> ToolResult:
        interrupt_type = input_data.get("interrupt_type", "confirm")
        title = input_data.get("title", "")
        message = input_data.get("message", "")
        options = input_data.get("options", [])

        # 调用 LangGraph interrupt — 暂停 graph 执行
        # value 会传递给客户端（通过 __interrupt__ 返回）
        # interrupt() 的返回值是客户端 resume 时传入的数据
        user_response = interrupt({
            "type": interrupt_type,
            "title": title,
            "message": message,
            "options": options,
        })

        # 执行到这里说明已经 resume 了
        # user_response 是用户选择的值
        if isinstance(user_response, dict):
            if user_response.get("cancelled"):
                return ToolResult(content="用户取消了操作", is_error=True)
            return ToolResult(content=str(user_response.get("value", "")))
        return ToolResult(content=str(user_response))
```

### 2.4 Checkpointer 选择

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| MemorySaver | 零配置、快 | 进程重启丢失、内存占用 | 开发/测试 |
| PostgresSaver | 持久化、可恢复 | 需要额外表、稍慢 | 生产 |
| RedisSaver | 快、可设 TTL | 需要 Redis | 高并发生产 |

**推荐**：开发阶段用 MemorySaver，生产用 PostgresSaver（复用现有 PG）。

```python
# 开发阶段
from langgraph.checkpoint.memory import MemorySaver
checkpointer = MemorySaver()

# 生产阶段
from langgraph.checkpoint.postgres import PostgresSaver
checkpointer = PostgresSaver(conn_string="postgresql://...")
```

```

RUN_FINISHED {outcome: {type: "success"}}
```


## 四、Checkpointer 生效机制

### 4.1 状态保存时机

```
graph.invoke(input, config={"thread_id": "t1"})
    │
    ├─ 每个 node 执行完后 → checkpointer.put(thread_id, state)
    │   保存内容：messages 列表、工具调用历史、中间状态
    │
    ├─ interrupt() 被调用时 → checkpointer.put(thread_id, state + interrupt_info)
    │   额外保存：interrupt 的位置（哪个 node、哪个工具调用）
    │
    └─ graph 正常结束 → checkpointer.put(thread_id, final_state)
```

### 4.2 状态恢复时机

```
graph.invoke(Command(resume="C001"), config={"thread_id": "t1"})
    │
    ├─ 1. checkpointer.get(thread_id="t1") → 获取最新 checkpoint
    │     包含：暂停时的完整状态（messages + 工具调用栈 + interrupt 位置）
    │
    ├─ 2. 恢复到 interrupt 调用点
    │     interrupt() 函数返回 "C001"（resume 传入的值）
    │
    ├─ 3. 工具继续执行
    │     ask_user 工具拿到 "C001" → 返回 ToolResult(content="C001")
    │
    └─ 4. Agent Loop 继续
          LLM 看到 ask_user 返回 "C001" → 调用下一个工具
```

### 4.3 Checkpoint 数据结构

```json
{
  "thread_id": "t1",
  "checkpoint_id": "cp_xxx",
  "parent_checkpoint_id": "cp_yyy",
  "channel_values": {
    "messages": [
      {"role": "user", "content": "洞察华为科技"},
      {"role": "assistant", "tool_calls": [{"name": "query_data", ...}]},
      {"role": "tool", "content": "[3条结果]"},
      {"role": "assistant", "tool_calls": [{"name": "ask_user", ...}]}
    ]
  },
  "pending_sends": [],
  "metadata": {
    "step": 3,
    "source": "loop",
    "writes": {"ask_user": {"__interrupt__": [...]}}
  }
}
```

## 五、前端交互规范

### 5.1 收到 interrupt 事件

```typescript
// 监听 CUSTOM("interrupt") 事件
onCustomEvent: ({event}) => {
  if (event.name === "interrupt") {
    const { type, title, message, options, interrupt_id } = event.value;
    // 渲染对应 UI 组件
    interruptRenderer.show(type, { title, message, options, interrupt_id });
  }
}

// 监听 RUN_FINISHED(outcome.interrupt)
onRunFinishedEvent: ({event}) => {
  if (event.outcome?.type === "interrupt") {
    // 标记当前 thread 处于等待确认状态
    setThreadState("awaiting_confirmation");
  }
}
```

### 5.2 用户响应

```typescript
// 用户点击选项后
async function handleInterruptResponse(interruptId: string, value: any) {
  // 发起 resume run
  await fetch("/api/chat/agui", {
    method: "POST",
    body: JSON.stringify({
      threadId: currentThreadId,
      message: "",           // 空消息
      resume: {
        interrupt_id: interruptId,
        value: value,        // 用户选择的值
      }
    })
  });
  // 继续监听 SSE 事件流
}

// 用户取消
async function handleInterruptCancel(interruptId: string) {
  await fetch("/api/chat/agui", {
    method: "POST",
    body: JSON.stringify({
      threadId: currentThreadId,
      message: "",
      resume: {
        interrupt_id: interruptId,
        cancelled: true,
      }
    })
  });
}
```

### 5.3 UI 状态管理

```
Thread 状态机：
  idle → running → [completed | awaiting_confirmation]
                         ↓
                    用户响应 → running → completed

awaiting_confirmation 状态下：
  - 输入框禁用（不允许发新消息）
  - 显示确认 UI 组件
  - 只允许点击确认/取消
```
