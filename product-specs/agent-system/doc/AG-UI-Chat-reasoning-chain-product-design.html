1.1 产品价值

AG-UI Chat 推理链路是连接用户自然语言输入与 Agent 智能执行的核心管道。通过将复杂的多步推理过程结构化、可观测化，它为产品带来以下核心价值：

  • 端到端透明度 — 将 Agent 的"黑盒"推理过程转化为可追踪、可回放的事件流，让运营和研发团队能够精确定位每一步的耗时、成本与异常，大幅降低排障成本。
  • 用户体验可控 — 通过 AG-UI 事件协议将推理进度实时映射到前端 UI（思考中 → 工具调用中 → 生成中），消除用户等待焦虑，提升交互信任感。
  • 质量与安全保障 — 在链路关键节点嵌入内容审查、护栏校验、循环检测等中间件，确保 Agent 输出合规、可控、不失控。
  • 成本可归因 — 每次 LLM 调用和子 Agent 执行均记录资源消耗，支持按租户、按 Skill、按请求维度的精细化成本核算。
  • 架构可扩展 — 中间件 + 事件流的分层设计使得新增能力（如新的 Skill、新的审查策略）无需改动核心链路，即插即用。

1.2 产品目标

本推理链路设计需达成以下可量化的产品目标：

目标维度具体目标
响应体验首 token 延迟（TTFT）≤ 3s；用户感知等待时间通过进度事件降低 50%（对比无推理链路展示的方案）
全链路可观测100% 请求生成完整 Trace；关键节点（LLM 调用、工具执行、子 Agent）埋点覆盖率 100%
异常检测循环调用、超时、护栏拦截等异常在 ≤ 1s 内被识别并触发告警或自动降级
成本透明每次请求的 token 消耗和资源点成本可精确归因到具体 Skill / 子 Agent，误差 ≤ 1%
安全合规所有用户输入经过内容审查 + PII 脱敏；所有工具调用经过护栏校验；敏感操作触发人工确认
扩展性新增 Middleware 或 Skill 不需要修改核心 Agent Loop 代码；子 Agent 支持最大 3 层嵌套深度

二、埋点节点规则定义

基于上述完整推理链路，定义每个关键节点的埋点规则。
目标：全链路可观测、性能可度量、异常可定位、成本可归因。
埋点数据写入 ai_trace + ai_span 表，支持 OpenTelemetry 导出。

2.1 埋点分层模型

层级 Span 类型 覆盖节点 粒度 关键指标
L0 · 请求 request 整个用户请求生命周期（SSE 连接建立 → RUN_FINISHED → 后处理完成） 1 次/请求 总耗时、总 token、总成本(cost_credits)、循环总数
L1 · 阶段 phase 入口预处理(entry) / 上下文准备(context) / Agent Loop(reasoning) / 回复输出(output) / 后处理(post) 5 次/请求 阶段耗时、阶段状态、阶段内节点数
L2 · 循环 loop_iteration Agent Loop 每一轮（Summarization → LLM 推理 → after_model 中间件 → Guardrail → 工具/Skill 执行） N 次/请求 轮次号、LLM 耗时、工具耗时、是否 FINAL
L3 · 操作 operation 单次 LLM 调用 / 单次工具执行 / 单次 Middleware / 单次 Skill 执行 M 次/轮 操作耗时、输入/输出大小、错误码、cost_credits
L4 · 子Agent sub_agent fork 模式 Skill 的子 Agent 完整生命周期（独立 thread_id，内含子循环 L2 + 子操作 L3） K 次/请求 子循环数、子LLM调用数、子工具调用数、depth、总耗时、cost_credits

2.4 埋点触发规则

规则 描述 适用节点
全量记录每次触发都记录，无采样所有 L0-L3 节点；RUN_STARTED/FINISHED；STEP_*；STATE_*；ACTIVITY_*
