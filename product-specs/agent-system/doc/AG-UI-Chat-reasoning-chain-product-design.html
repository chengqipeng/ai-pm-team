二、埋点节点规则定义

基于上述完整推理链路，定义每个关键节点的埋点规则。
目标：全链路可观测、性能可度量、异常可定位、成本可归因。
埋点数据写入 ai_trace + ai_span 表，支持 OpenTelemetry 导出。

2.1 埋点分层模型

层级 Span 类型 覆盖节点 粒度 关键指标
L0 · 请求 request 整个用户请求生命周期（入口→回复完成） 1 次/请求 总耗时、总 token、总成本
L1 · 阶段 phase 入口预处理 / 上下文准备 / Agent Loop / 输出转换 / 后处理 5 次/请求 阶段耗时、阶段状态
L2 · 循环 loop_iteration Agent Loop 每一轮（before_model → LLM → after_model → tool） N 次/请求 轮次号、LLM 耗时、工具耗时
L3 · 操作 operation 单次 LLM 调用 / 单次工具执行 / 单次 Middleware / 子 Agent M 次/轮 操作耗时、输入/输出大小、错误码
L4 · 事件 ag_ui_event 每个 AG-UI SSE 事件的产出时刻 K 次/请求 事件类型、时间戳、关联 span_id

2.4 埋点触发规则

规则 描述 适用节点
全量记录每次触发都记录，无采样所有 L0-L3 节点；RUN_STARTED/FINISHED；STEP_*；STATE_*；ACTIVITY_*
采样记录 (10%)高频事件按 trace_id hash 取模采样TEXT_MESSAGE_CONTENT；REASONING_MESSAGE_CONTENT；TOOL_CALL_ARGS
异常全量升级当请求出现异常时，该 trace 下所有事件升级为全量记录RUN_ERROR 触发后回填该 trace 的采样事件
耗时阈值告警超过阈值时自动标记 alert=true 并推送监控见各节点"异常判定规则"列
成本归因每个 LLM_CALL 和 SUB_AGENT span 记录 cost_credits，汇总到 L0llm_call, sub_agent_*
链路关联所有 span 通过 trace_id + parent_span_id 形成树状结构全部节点；子Agent span 的 parent = skill span
AG-UI 事件关联每个 AG-UI 事件记录 related_span_id 指向产出它的 L3 span所有 agui_* 节点
