# 多租户 Agent 沙盒架构设计

## 一、业务场景

ToB 产品，多用户通过 Web 入口访问云端 Agent，Agent 的 terminal/file/code 类命令在独立的云端沙盒中执行，需要支持多用户、多对话的完全隔离。

## 四、沙盒隔离粒度

### 每用户每对话一个沙盒

```
用户A ─┬─ 对话1 → Sandbox-A1 (独立容器，独立文件系统)
       ├─ 对话2 → Sandbox-A2 (独立容器，独立文件系统)
       └─ 对话3 → Sandbox-A3 (独立容器，独立文件系统)

用户B ─┬─ 对话1 → Sandbox-B1 (独立容器，独立文件系统)
       └─ 对话2 → Sandbox-B2 (独立容器，独立文件系统)
```

选择"每对话"的原因：
- 对话内命令需要状态连续（cd、export 保持）
- 不同对话可能做不同项目，不应互相干扰
- 用户可以同时开多个对话并行工作
- 可独立回滚某个对话的环境

## 五、Agent 容器 ↔ 沙盒容器 授权机制

### 5.1 授权架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        宿主机 / K8s 集群                                 │
│                                                                         │
│  ┌─────────────────────┐         ┌─────────────────────────────────┐   │
│  │  Agent 容器          │         │  Sandbox API 服务 (安全网关)     │   │
│  │                     │  gRPC   │                                 │   │
│  │  • AI 推理          │────────▶│  • 验证 Token + 权限            │   │
│  │  • Tool 路由        │  Token  │  • 创建/管理 Sandbox 容器        │   │
│  │  • 无 Docker 权限   │  认证   │  • 转发命令到对应 Sandbox        │   │
```

### 5.2 Token 设计 (JWT)

```json
{
    "sub": "agent-instance-007",
    "tenant_id": "user-alice",
    "allowed_sandboxes": ["A1", "A2"],
    "permissions": ["exec", "read", "write"],
    "iat": 1716364800,
    "exp": 1716368400
}
```

### 5.3 验证逻辑

```python
def verify_request(token, sandbox_id, action):
    claims = jwt.decode(token, PUBLIC_KEY, algorithms=["RS256"])

    # 1. Token 是否过期
    if claims["exp"] < now():
        raise Unauthorized("Token expired")

    # 2. 该 Agent 是否有权操控这个沙盒
    if sandbox_id not in claims["allowed_sandboxes"]:
        raise Forbidden("Not allowed to access this sandbox")

    # 3. 操作类型是否允许
    if action not in claims["permissions"]:
        raise Forbidden("Action not permitted")
```

### 5.4 网络隔离

```yaml
networks:
  # Agent ↔ Sandbox API 通信网络
  control-plane:
    internal: true

  # Sandbox 容器的隔离网络（无外网，容器间也不互通）
  sandbox-net:
    internal: true
    driver_opts:
      com.docker.network.bridge.enable_icc: "false"
```

```
网络拓扑:
  Agent ──(control-plane)──▶ Sandbox API ──(sandbox-net)──▶ Sandbox 容器
  Agent ✘──────────────────────────────────────────────────▶ Sandbox 容器
  Sandbox ✘────────────────────────────────────────────────▶ Agent
  Sandbox-A1 ✘─────────────────────────────────────────────▶ Sandbox-B1
```

### 5.5 安全防护总结

| 威胁 | 防护 |
|------|------|
| Sandbox 恶意代码逃逸 | 无网络出口 + cap-drop ALL + no-new-privileges |
| Agent 被注入访问别人沙盒 | Token 白名单限定 allowed_sandboxes |
| 伪造 Token | RS256 非对称签名，私钥仅编排系统持有 |
| Sandbox 反连窃取 LLM 密钥 | 网络隔离，sandbox-net 无法路由到 control-plane |
| Agent 容器被攻破操控 Docker | Agent 无 Docker Socket，只能通过 API 间接操作 |

## 六、Sandbox 测试用例（10 个核心场景）

| # | 用例名称 | 前置条件 | 操作步骤 | 预期结果 | 覆盖模块 |
|---|---------|---------|---------|---------|---------|
| 1 | **沙盒创建与隔离** | 用户A已登录，发起新对话 | 1. 用户A创建对话1<br>2. Agent 调用 `terminal` 执行 `echo $HOSTNAME` | 返回独立容器 hostname；沙盒状态为 running；资源配额按用户套餐分配（CPU:1, Mem:2G） | 沙盒生命周期、资源配额 |
| 2 | **多对话沙盒互不干扰** | 用户A已有对话1的沙盒（内含文件 /tmp/a.txt） | 1. 用户A创建对话2<br>2. 在对话2中执行 `cat /tmp/a.txt` | 对话2返回"文件不存在"；对话1的文件系统不可被对话2访问 | 隔离粒度（每用户每对话） |
| 3 | **跨租户隔离验证** | 用户A沙盒A1运行中，用户B沙盒B1运行中 | 1. 从沙盒A1尝试 `ping <B1内网IP>`<br>2. 从沙盒A1尝试访问 Sandbox API 端口 | 两次均超时/拒绝；网络层完全隔离，容器间不互通（ICC=false） | 网络隔离、安全防护 |
| 4 | **Token 越权访问拦截** | Agent 实例持有 Token（allowed_sandboxes=["A1"]） | 1. Agent 携带该 Token 请求操作 Sandbox-B1<br>2. 观察 Sandbox API 响应 | 返回 403 Forbidden "Not allowed to access this sandbox"；操作被拒绝，审计日志记录越权尝试 | 授权机制（JWT 白名单） |
| 5 | **Token 过期自动失效** | Agent Token 设置 exp=当前时间-1s（已过期） | 1. Agent 携带过期 Token 请求执行命令<br>2. 观察 Sandbox API 响应 | 返回 401 Unauthorized "Token expired"；不执行任何沙盒操作 | 授权机制（Token 生命周期） |
| 6 | **沙盒内命令状态连续性** | 用户A对话1的沙盒已创建 | 1. 执行 `cd /opt && export MY_VAR=hello`<br>2. 执行 `pwd && echo $MY_VAR` | 第二次返回 `/opt` 和 `hello`；同一对话内 shell 状态保持连续 | 会话状态管理 |
| 7 | **沙盒空闲自动回收** | 沙盒A1运行中，空闲超时阈值设为 5 分钟 | 1. 停止对沙盒A1的所有操作<br>2. 等待超过 5 分钟<br>3. 检查沙盒状态 | 沙盒状态变为 hibernated/destroyed；文件快照已保存至 S3；资源已释放 | 空闲检测与回收 |
| 8 | **沙盒休眠唤醒恢复** | 沙盒A1已休眠（快照存于 S3），用户A重新发起对话1的请求 | 1. 用户A在对话1中执行 `ls /workspace`<br>2. 观察恢复过程 | 沙盒自动唤醒；文件系统从快照恢复；之前创建的文件仍存在；响应延迟 < 5s | 生命周期（休眠/唤醒）、文件同步 |
| 9 | **资源配额超限防护** | 沙盒B1配额为 CPU:2, Mem:4G | 1. 在沙盒中执行内存炸弹 `python -c "x='a'*10**10"`<br>2. 在沙盒中执行 fork 炸弹 `:(){ :\|:& };:` | 内存超限时进程被 OOM Kill，沙盒不崩溃可继续使用；fork 炸弹被 PID 限制阻止；不影响宿主机和其他沙盒 | 资源配额、安全防护 |
| 10 | **沙盒逃逸防护** | 沙盒C1运行中（cap-drop ALL, no-new-privileges） | 1. 尝试 `mount /dev/sda1 /mnt`<br>2. 尝试 `chmod u+s /bin/bash`<br>3. 尝试写入 `/proc/sys/kernel/` | 所有操作返回 Permission denied；容器无法提权、无法挂载宿主设备、无法修改内核参数 | 安全防护（逃逸防御） |

## 七、沙盒空闲检测与回收
