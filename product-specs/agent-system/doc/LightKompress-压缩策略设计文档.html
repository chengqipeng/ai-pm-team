阶段 1: 填充短语预删除（路径 C）

在分句之前，先扫描全文删除预定义的零信息量填充短语

设计原理

语言学共识：这些短语永远不承载实质信息，删除不改变事实含义。在分句之前执行可避免它们占据句子配额影响后续评分。

阶段 2: 智能分句（三级降级策略）

确保任何格式的文本（标准中文、无标点OCR、超长英文复合句）都能被有效分割

Level 1: 标准标点分句

按 。！？；\n 和英文 .!? 后空格分割，过滤 <5 字符的碎片

正则: ([。！？；\n]|(?<=[.!?])\s+)

触发条件：始终执行

退出条件：分句结果 > 2 句 → 使用此结果

Level 2: 逗号降级分句

按 ，,、 分割，合并分隔符到前一个片段

触发条件: Level 1 结果 ≤ 2 句 且 平均句长 > 80 字符

退出条件：分句结果 > 2 句 → 使用此结果

Level 3: 固定窗口分句

在 jieba 词边界处按 ~60 字符窗口切割，最后片段 <15 字符则合并到上一段

触发条件: Level 2 后仍 ≤ 2 句 且 文本长度 > 150 字符

退出条件：切割后 > 2 段 → 使用此结果；否则返回整个文本作为单句

设计意图：Level 1 处理标准文本，Level 2 处理逗号分隔的无句号长段落，Level 3 兜底处理 OCR/API 返回的无标点纯文本块。三级降级保证任何输入都能被有效分割。

阶段 3: 六维度评分体系

对每个句子计算加权重要性分数，决定保留优先级

评分总览

维度权重计算方式设计目的
1. TF-IDF 关键词×3.0Σ(词TF-IDF权重) / √(词数+1)识别主题核心句
2. 位置加权+2.5/1.8/1.5/1.0首句/次句/末句/前4句 固定加分保留开头结论和总结
3. 实体密度×4.0 + base 3.013条正则命中数 × 4 + 3保护关键数据不被删除
4. 上下文相关×3.0句子与用户问题的内容词交集大小保留与当前问题相关的内容
5. 信息密度×2.0实词占比 = 非停用词/总词数过滤废话/过渡句
6. 技术标识符×2.0 + base 2.0技术模式命中数 × 2 + 2保护代码/配置/协议等技术细节

维度 1: TF-IDF 关键词密度

算法步骤

# 1. 对全文提取 TOP50 关键词及其 TF-IDF 权重
keywords = jieba.analyse.extract_tags(full_text, topK=50, withWeight=True)
keyword_weights = {word: weight for word, weight in keywords}

# 2. 对每个句子计算关键词得分
for i, sent in enumerate(sentences):
    words = jieba.cut(sent)
    kw_score = sum(keyword_weights.get(w, 0) for w in words)
    scores[i] += (kw_score / math.sqrt(len(words) + 1)) * 3.0
公式: score_tfidf[i] = ( Σ TF-IDF(word) for word in sentence ) / √(|words| + 1) × 3.0

除以 √(词数+1) 的目的：归一化，避免长句因词多而占优

维度 2: 位置加权

固定加分规则

位置加分理由
首句 (i=0)+2.5通常包含核心结论或主题句
次句 (i=1)+1.8对首句的补充说明，常含关键数据
末句 (i=n-1)+1.5结论/建议/总结句
前4句 (i≤3)+1.0前置信息通常较重要

维度 4: 上下文相关性

算法：句子与用户问题的词交集

# 用户问题分词 → 去停用词 → 取长度>1的词
context_words = set(jieba.cut(context)) - STOP_WORDS
context_words = {w for w in context_words if len(w) > 1}

# 计算每个句子与问题的词重叠数
for i, sent in enumerate(sentences):
    sent_words = set(jieba.cut(sent))
    overlap = len(context_words & sent_words)
    if overlap:
        scores[i] += overlap * 3.0
score_context[i] = |context_words ∩ sent_words| × 3.0

作用：当用户问"为什么查询超时"时，包含"查询""超时""错误"等词的句子会获得加分，优先保留。当 context="" 时此维度不生效。

维度 5: 信息密度

算法：实词占比

# 实词 = 非停用词 且 长度>1 的词
content_words = [w for w in words
                 if w.strip() and len(w.strip()) > 1
                 and w not in STOP_WORDS]
density = len(content_words) / (len(words) + 1)
scores[i] += density * 2.0
score_density[i] = |content_words| / (|words| + 1) × 2.0

设计意图：废话/过渡句中停用词占比高、实词密度低，得分自然低于信息密集句。

阶段 4: 动态选句

四条路径协同：硬约束保护 + 冗余检测 + 自适应target + 贪心选句

路径 A: 硬约束保护（不可删句子）

路径 A — 实体保护前置

规则：含任意正则实体命中的句子，标记为 protected，无条件保留，不参与删除候选

for i, sent in enumerate(sentences):
    if any(pattern.search(sent) for pattern in MUST_KEEP_PATTERNS):
        protected_indices.add(i)
与维度 3 的区别：维度 3 是"加分"（让含实体句更可能被选中），路径 A 是"硬约束"（即使分数不够也必须保留）。双重保障确保关键数据零丢失。

路径 B: 冗余句检测

路径 B — Jaccard 相似度去重

规则：相邻 3 句范围内，如果两句之间内容词 Jaccard 相似度 > 0.5，标记后面的为冗余

for i in range(len(sentences) - 1):
    words_i = set(jieba.cut(sentences[i])) - STOP_WORDS
    words_i = {w for w in words_i if len(w) > 1}
    for j in range(i+1, min(i+3, len(sentences))):
        words_j = set(jieba.cut(sentences[j])) - STOP_WORDS
        words_j = {w for w in words_j if len(w) > 1}
        jaccard = len(words_i & words_j) / len(words_i | words_j)
        if jaccard > 0.5:
            redundant.add(j)  # 删后面的，保前面的
Jaccard(sent_i, sent_j) = |words_i ∩ words_j| / |words_i ∪ words_j|
阈值: 0.5（50%+ 词重叠 = 高度冗余）

设计意图：处理复述/总结式冗余（同一段中反复说类似内容）。只看前后3句以控制计算量。

路径 D: 自适应 target_ratio

路径 D — 根据信息密度动态调整压缩目标

# 计算全文信息密度
all_words = jieba.cut(cleaned_text)
content_words = [w for w in all_words if len(w)>1 and w not in STOP_WORDS]
info_density = len(content_words) / (len(all_words) + 1)

# 映射到 [0.35, 0.85]：密度高→保留多，密度低→压缩多
adaptive_ratio = 0.35 + info_density * 0.5

# 取 adaptive 和 user_target 中更激进（更小）的那个
effective_target = min(target_ratio * bias, adaptive_ratio)
effective_target = max(0.30, min(0.85, effective_target))

# 计算目标字符数
target_chars = int(len(cleaned_text) * effective_target)

选句算法伪代码

# Step 2: 非保护句按分数降序排列

deletable.sort(key=score, reverse=True)  # 高分优先保留

# Step 3: 贪心填充到目标字符数

# Step 4: 保底 — 确保 TOP2 高分句被保留
top2 = sorted(range(n), key=lambda i: scores[i], reverse=True)[:2]

阶段 5: 句内精简

对保留的长句进行子句级/词级二次压缩

触发条件

触发时机：当句子级压缩后的 ratio > effective_target × 0.85 时启动句内精简。
即句子级选择已经接近但未达到目标压缩率，需要进一步在句内削减。

子句级压缩（对 >100 字符的长句）

步骤一：按子句边界分割

使用以下模式将长句拆分为子句：

分割符类型匹配内容
标点分隔符， , ； ;
中文连接词而且 但是 因为 虽然 另外 此外 同时 不过 然而

分隔符合并到前一个子句（保持语法完整性）。

步骤二：子句评分

for clause in merged_clauses:
    score = 0.0
    # 实体命中
    for pattern in MUST_KEEP_PATTERNS:
        score += len(pattern.findall(clause)) * 3.0
    # 信息密度
    words = jieba.cut(clause)
    content_words = [w for w in words if len(w)>1 and w not in STOP_WORDS]
    score += (len(content_words) / (len(words) + 1)) * 2.0
    # 极短子句惩罚
    if len(clause.strip()) < 10:
        score -= 1.0

三种压缩模式对比

提取式压缩 (LightKompress)

原理：评分→选句→删低分句

输出：原文句子的子集

忠实度：100% (不编造)

压缩率：15-62%

延迟：4-20ms

适合：工具输出压缩

生成式摘要 (需LLM)

原理：LLM 理解→重写

输出：全新生成的文本

忠实度：有幻觉风险

压缩率：80-95%

延迟：1-5s

适合：知识库预处理

BERT Token-clf (原方案)

原理：逐token预测keep/drop

输出：保留token拼接

忠实度：高(概率性)

压缩率：50-80%

延迟：15-50ms

适合：不计成本的极致压缩

完整数据流与设计决策

端到端流程图 + 核心设计原则 + 已知限制与演进方向

完整数据流（端到端）

compress(text, context, bias=1.0, target_ratio=0.5)
│
├─ [Guard] text为空 或 len(text) < 100 → 返回 strategy="too_short"
│
├─ [阶段1] 填充短语预删除 → cleaned_text
│   └─ 60+ 条中英文填充短语逐一删除 → 清理连续标点
│
├─ [阶段2] 智能分句 → sentences[]
│   ├─ L1: 按句末标点分割
│   ├─ L2: (≤2句 且 avg>80) → 按逗号分割
│   └─ L3: (≤2句 且 len>150) → 60字符窗口切割
│
├─ [Guard] len(sentences) ≤ 3 → 返回 strategy="too_few_sentences" 或 "filler_removal"
│
├─ [阶段3] 六维度评分 → scores[]
│   ├─ 维度1: TF-IDF关键词 (×3.0)
│   ├─ 维度2: 位置加权 (+2.5/1.8/1.5/1.0)
│   ├─ 维度3: 实体密度 (hits×4+3)
│   ├─ 维度4: 上下文相关 (overlap×3.0)
│   ├─ 维度5: 信息密度 (density×2.0)
│   └─ 维度6: 技术标识符 (hits×2+2)
│
├─ [阶段4] 动态选句
│   ├─ 路径A: 标记 protected_indices (含实体的句子)
│   ├─ 路径B: 标记 redundant_indices (Jaccard>0.5)
│   ├─ 路径D: 计算 effective_target (自适应密度)
│   ├─ 贪心: protected必选 → 高分优先 → 跳过冗余 → TOP2保底
│   └─ 拼接: 按原始顺序输出
│
├─ [阶段5] 句内精简 (当 ratio > effective_target×0.85)
│   ├─ 长句(>100字符): 子句边界分割 → 子句评分 → 贪心选择
│   └─ 激进模式(ratio<0.4): 词级填充短语删除
│
└─ 返回 CompressResult(compressed, ratio, strategy="tfidf_textrank", ...)

五大核心设计决策

#设计决策原因Trade-off
1确定性正则保护 > 概率性模型预测关键数据（金额、日期、百分比）100%不丢失可能过度保护，降低压缩率
2提取式 > 生成式输出是原文子集，忠实度100%，不编造压缩率上限不如 LLM 摘要
3三级降级分句兼容标准文本、无标点OCR、超长复合句Level 3 可能在不恰当位置断开
4自适应 target_ratio密度高少压缩、废话多多压缩，自动调节增加计算复杂度（~1ms）
5零模型零GPU部署成本为零，延迟确定性 <20ms无法做语义理解/同义判断

已知限制与演进方向

限制影响计划演进方向
压缩率上限 ~62%不如 BERT 的 80%已引入句间冗余检测（路径B），继续优化 Jaccard 阈值
recall 93.9%（非数字术语可能丢）产品名/动词短语可能被删硬约束分离：路径A已实现实体不可删
评分权重手动设定换场景可能失效自适应权重（按文本类型自动调整维度权重）
无语义理解无法识别同义重复引入轻量 embedding 做句间余弦相似度
子句分割依赖连接词英文无连接词的长句无法细分引入依存句法分析做更细粒度切分
