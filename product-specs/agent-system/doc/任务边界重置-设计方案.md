# 任务边界重置（Task Boundary Reset）— 详细设计方案

> 解决问题：当前上下文压缩是"只增不减"的迭代摘要，越往后 token 消耗越大。
> 核心思路：检测会话内的任务切换边界，已完成的独立任务整体归档，当前摘要定期"瘦身"。
> 与现有三层压缩机制（Micro/Auto/FullCompact）正交配合，不替代而是增强。

---

## 一、问题量化

### 1.1 当前 token 消耗增长模型

```
假设条件：
  - 每轮用户消息平均 50 tokens
  - 每轮 Agent 回复平均 200 tokens
  - 每轮工具调用产生 300-500 tokens
  - 迭代摘要每次 ADD 增加 ~80 tokens
  - answerSummary 滑动窗口固定 5 轮 × 60 tokens = 300 tokens
  - Skill 锚点最多 10 个 × 30 tokens = 300 tokens

摘要增长曲线：
  第 1 次 AutoCompact (轮次 ~8):  摘要 ~500 tokens
  第 2 次 AutoCompact (轮次 ~14): 摘要 ~700 tokens (+ADD 200)
  第 3 次 AutoCompact (轮次 ~20): 摘要 ~900 tokens (+ADD 200)
  第 4 次 AutoCompact (轮次 ~26): 摘要 ~1100 tokens (+ADD 200)
  第 5 次 AutoCompact (轮次 ~32): 摘要 ~1300 tokens (+ADD 200)

问题：摘要线性增长，无上限。30+ 轮时 System + 摘要 + 滑动窗口已占 ~4K tokens。
```

### 1.2 CRM 场景的任务模式

```
销售经理典型一次会话：

  任务 A (轮次 1-7):  "帮我看看 PT Sentosa 的情况，出个报价"
    → 查客户 → 查商机 → BANT 分析 → 竞品 → 生成报价
    → 关键实体: PT Sentosa, opportunity(opp_001)

  任务 B (轮次 8-11): "CV XYZ 那个合同到期了没"
    → 查客户 → 查合同 → 合同到期提醒
    → 关键实体: CV XYZ, contract(con_005)
    → 与任务 A 完全无关

  任务 C (轮次 12-18): "帮我分析一下本月 pipeline"
    → 查全部商机 → 阶段分布 → 风险商机 → coaching 策略
    → 关键实体: 多个 opportunity, user(andi)
    → 与任务 A/B 无关

  任务 D (轮次 19-25): "PT Sentosa 上次报价客户回复了，帮我调整一下"
    → 回到 PT Sentosa → 修改报价
    → 关键实体: PT Sentosa — 与任务 A 有关联！

当前做法：所有任务的信息堆积在一份摘要中，永不释放。
```

## 二、核心设计

### 2.1 架构概览

```
┌─────────────────────────────────────────────────────────────────────┐
│ TaskBoundaryDetector（任务边界检测器）                                │
│                                                                      │
│ 输入: 每轮的 HumanMessage + ToolMessage (entity/实体/技能)           │
│ 输出: CONTINUE / SWITCH / RETURN 信号                               │
│                                                                      │
│ 三种信号:                                                            │
│   CONTINUE — 当前任务继续，正常压缩逻辑                              │
│   SWITCH   — 切换到全新任务，旧任务归档                              │
│   RETURN   — 回到之前的某个任务，恢复该任务的摘要                     │
└──────────────────────┬──────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────────┐
│ TaskArchive（任务归档）                                               │
│                                                                      │
│ 每个已完成任务存为一条 TaskRecord:                                    │
│   task_id, primary_entities[], summary(7-section), skill_anchors,   │
│   turn_range, timestamp                                              │
│                                                                      │
│ 当 RETURN 信号触发时，从 TaskArchive 恢复该任务的摘要片段             │
└──────────────────────┬──────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 迭代摘要 (_previous_summary) 瘦身                                    │
│                                                                      │
│ SWITCH 时:                                                           │
│   当前摘要 → 归档到 TaskArchive                                      │
│   _previous_summary → 重置为空（或仅保留 Active Task）               │
│   _skill_anchors → 归档后清空                                       │
│                                                                      │
│ RETURN 时:                                                           │
│   从 TaskArchive 恢复相关任务的摘要片段                               │
│   注入到新的 _previous_summary 中                                    │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 与现有三层压缩的集成点

```
before_model() 执行顺序（修改后）:

  1. Post-Skill Compact       (不变)
  2. MD5 去重                 (不变)
  3. ★ 任务边界检测            (新增 — 在阈值判断之前)
     → SWITCH: 归档旧任务 + 重置摘要
     → RETURN: 恢复任务摘要
     → CONTINUE: 不操作
  4. 阈值判断 + 三层级联压缩  (不变)

关键: 任务边界检测在压缩之前执行。
     如果检测到 SWITCH，摘要被重置，后续估算 tokens 自然大幅降低，
     可能根本不需要触发 AutoCompact。
```

## 三、任务边界检测器（TaskBoundaryDetector）

### 3.1 检测信号

```python
@dataclass
class TaskSignal:
    """每轮结束时提取的任务相关信号"""
    primary_entities: list[str]      # 本轮操作的主实体 (account/opportunity ID)
    entity_types: list[str]          # 实体类型 (account, opportunity, contract)
    skill_name: str | None           # 本轮执行的 Skill 名称
    user_intent_keywords: list[str]  # 从 HumanMessage 提取的意图关键词
    is_question_only: bool           # 是否纯问答（无工具调用）
```

### 3.2 信号提取（零 LLM 成本）

```python
def extract_task_signal(messages_this_turn: list) -> TaskSignal:
    """从当前轮次的消息中提取任务信号（纯规则，零 LLM）"""
    
    primary_entities = []
    entity_types = set()
    skill_name = None
    
    for msg in messages_this_turn:
        # 从 tool_calls 中提取实体
        if isinstance(msg, AIMessage) and msg.tool_calls:
            for tc in msg.tool_calls:
                args = tc.get("args", {})
                name = tc.get("name", "")
                
                if name == "query_data":
                    entity_type = args.get("entity_api_key", "")
                    record_id = args.get("record_id", "")
                    if entity_type:
                        entity_types.add(entity_type)
                    if record_id:
                        primary_entities.append(f"{entity_type}({record_id})")
                
                elif name == "modify_data":
                    entity_type = args.get("entity_api_key", "")
                    record_id = args.get("record_id", "")
                    if entity_type:
                        entity_types.add(entity_type)
                    if record_id:
                        primary_entities.append(f"{entity_type}({record_id})")
                
                elif name == "skills_tool":
                    skill_name = args.get("skill_name", "")
        
        # 从 ToolMessage 中提取被查询的实体名
        if isinstance(msg, ToolMessage):
            content = getattr(msg, "content", "") or ""
            # 提取返回结果中的客户名/商机名
            names = re.findall(r'(?:PT|CV|Ltd|Inc)\s+[\w\s]{2,20}', content)
            for n in names[:3]:
                if n.strip() not in [e.split("(")[0] for e in primary_entities]:
                    primary_entities.append(n.strip())
    
    # 从 HumanMessage 提取意图关键词
    human_msgs = [m for m in messages_this_turn if isinstance(m, HumanMessage)]
    intent_keywords = []
    if human_msgs:
        user_text = human_msgs[-1].content or ""
        # 中文意图词
        intent_keywords = re.findall(r'[\u4e00-\u9fa5]{2,4}', user_text)
        # 英文实体名
        intent_keywords += re.findall(r'[A-Z][a-zA-Z\s]{2,20}', user_text)
    
    is_question_only = not any(
        isinstance(m, AIMessage) and getattr(m, "tool_calls", None)
        for m in messages_this_turn
    )
    
    return TaskSignal(
        primary_entities=primary_entities,
        entity_types=list(entity_types),
        skill_name=skill_name,
        user_intent_keywords=intent_keywords[:10],
        is_question_only=is_question_only,
    )
```

### 3.3 边界判断逻辑

```python
class TaskBoundaryDetector:
    """任务边界检测器 — 判断当前轮次是 CONTINUE / SWITCH / RETURN"""
    
    def __init__(self):
        self._current_task = TaskContext()       # 当前任务上下文
        self._task_archive: list[TaskRecord] = []  # 已归档的任务
        self._switch_cooldown: int = 0          # 切换冷却（防止误判）
    
    def detect(self, signal: TaskSignal) -> TaskBoundaryAction:
        """
        判断逻辑（按优先级）：
        
        1. 冷却期内 → CONTINUE（刚切换过，给新任务一个建立期）
        2. 纯问答轮次 → CONTINUE（用户只是问了一句话，不算切换）
        3. 实体重叠度判断:
           - 与当前任务实体重叠 ≥ 50% → CONTINUE
           - 与某个归档任务实体重叠 ≥ 50% → RETURN（回到旧任务）
           - 与所有任务实体重叠 < 30% → SWITCH（全新任务）
        4. 辅助信号（加权）:
           - entity_type 完全不同 → 加权 SWITCH
           - skill_name 与当前任务不同 → 加权 SWITCH
           - 用户消息中出现新客户名 → 加权 SWITCH
        """
        
        # 规则 1: 冷却期
        if self._switch_cooldown > 0:
            self._switch_cooldown -= 1
            self._current_task.add_signal(signal)
            return TaskBoundaryAction.CONTINUE
        
        # 规则 2: 纯问答不触发切换
        if signal.is_question_only and not signal.primary_entities:
            return TaskBoundaryAction.CONTINUE
        
        # 规则 3: 实体重叠度计算
        current_entities = set(self._current_task.all_entities)
        new_entities = set(signal.primary_entities)
        
        if not new_entities:
            # 无法提取实体时（如纯统计查询），不切换
            self._current_task.add_signal(signal)
            return TaskBoundaryAction.CONTINUE
        
        # 与当前任务的重叠
        if current_entities:
            overlap_current = len(current_entities & new_entities) / max(len(new_entities), 1)
        else:
            overlap_current = 0.0  # 当前任务还没有实体（首轮）
        
        # 与当前任务高重叠 → CONTINUE
        if overlap_current >= 0.5:
            self._current_task.add_signal(signal)
            return TaskBoundaryAction.CONTINUE
        
        # 检查是否 RETURN（回到归档任务）
        for archived_task in reversed(self._task_archive):
            archived_entities = set(archived_task.primary_entities)
            overlap_archived = len(archived_entities & new_entities) / max(len(new_entities), 1)
            if overlap_archived >= 0.5:
                return TaskBoundaryAction(
                    type="RETURN",
                    target_task_id=archived_task.task_id,
                )
        
        # 与所有已知任务低重叠 → SWITCH
        # 辅助信号: entity_type 变化
        type_changed = (
            signal.entity_types and 
            self._current_task.entity_types and
            not set(signal.entity_types) & set(self._current_task.entity_types)
        )
        
        if overlap_current < 0.3 or type_changed:
            return TaskBoundaryAction(type="SWITCH")
        
        # 模糊区间 (0.3 ~ 0.5): 保守处理，视为 CONTINUE
        self._current_task.add_signal(signal)
        return TaskBoundaryAction.CONTINUE
    
    def execute_switch(self, current_summary: str, skill_anchors: dict) -> None:
        """执行 SWITCH: 归档当前任务 + 重置上下文"""
        if self._current_task.turn_count > 0:
            record = TaskRecord(
                task_id=f"task_{len(self._task_archive)}",
                primary_entities=self._current_task.all_entities,
                entity_types=self._current_task.entity_types,
                summary=current_summary,
                skill_anchors=dict(skill_anchors),
                turn_range=(self._current_task.start_turn, self._current_task.end_turn),
                timestamp=time.time(),
            )
            self._task_archive.append(record)
        
        # 重置当前任务
        self._current_task = TaskContext()
        self._switch_cooldown = 2  # 切换后冷却 2 轮
    
    def execute_return(self, target_task_id: str) -> TaskRecord | None:
        """执行 RETURN: 找到归档任务并返回其摘要"""
        for task in self._task_archive:
            if task.task_id == target_task_id:
                return task
        return None
```

### 3.4 数据结构

```python
@dataclass
class TaskContext:
    """当前正在进行的任务上下文"""
    all_entities: list[str] = field(default_factory=list)
    entity_types: list[str] = field(default_factory=list)
    skills_used: list[str] = field(default_factory=list)
    start_turn: int = 0
    end_turn: int = 0
    turn_count: int = 0
    
    def add_signal(self, signal: TaskSignal) -> None:
        for e in signal.primary_entities:
            if e not in self.all_entities:
                self.all_entities.append(e)
        for t in signal.entity_types:
            if t not in self.entity_types:
                self.entity_types.append(t)
        if signal.skill_name and signal.skill_name not in self.skills_used:
            self.skills_used.append(signal.skill_name)
        self.turn_count += 1
        self.end_turn += 1


@dataclass  
class TaskRecord:
    """已归档的任务记录"""
    task_id: str
    primary_entities: list[str]
    entity_types: list[str]
    summary: str                    # 该任务被归档时的 7-section 摘要
    skill_anchors: dict[str, str]   # 该任务的 Skill 锚点
    turn_range: tuple[int, int]
    timestamp: float


class TaskBoundaryAction:
    CONTINUE = "CONTINUE"
    
    def __init__(self, type: str = "CONTINUE", target_task_id: str = ""):
        self.type = type
        self.target_task_id = target_task_id
```

## 四、任务归档与恢复

### 4.1 SWITCH 时的归档流程

```python
def _handle_task_switch(self) -> None:
    """任务切换时的处理逻辑（在 before_model 中调用）"""
    
    # 1. 将当前迭代摘要作为任务快照归档
    self._task_detector.execute_switch(
        current_summary=self._previous_summary or "",
        skill_anchors=self._skill_anchors.anchors,
    )
    
    # 2. 重置压缩相关的会话级状态
    self._previous_summary = None       # 摘要清空
    self._current_focus_topic = None    # Focus Topic 清空
    self._skill_anchors.clear()         # 锚点清空
    self._ineffective_compression_count = 0
    
    # 3. 当前 messages 中的旧摘要 SystemMessage 标记为可丢弃
    #    下次 AutoCompact 时会自然被 head 保护区外的逻辑处理掉
    
    logger.info("[TaskBoundary] SWITCH: 旧任务归档，摘要重置")
```

### 4.2 RETURN 时的恢复流程

```python
def _handle_task_return(self, action: TaskBoundaryAction) -> None:
    """回到之前的任务时的处理逻辑"""
    
    # 1. 先归档当前任务（如果有内容）
    if self._current_task_has_content():
        self._handle_task_switch()
    
    # 2. 从 TaskArchive 恢复目标任务
    archived_task = self._task_detector.execute_return(action.target_task_id)
    if not archived_task:
        return
    
    # 3. 恢复摘要（但标注为"历史快照"）
    restored_summary = (
        f"[任务恢复 — 来自 {archived_task.task_id}，"
        f"实体: {', '.join(archived_task.primary_entities[:5])}]\n\n"
        + archived_task.summary
    )
    self._previous_summary = restored_summary
    
    # 4. 恢复 Skill 锚点
    for key, value in archived_task.skill_anchors.items():
        self._skill_anchors._anchors[key] = value
    
    # 5. 更新 TaskDetector 的当前任务上下文
    self._task_detector._current_task = TaskContext(
        all_entities=list(archived_task.primary_entities),
        entity_types=list(archived_task.entity_types),
    )
    
    logger.info("[TaskBoundary] RETURN: 恢复任务 %s (实体: %s)",
                archived_task.task_id, archived_task.primary_entities[:3])
```

### 4.3 归档后的 Token 消耗对比

## 五、边界情况与安全机制

### 5.1 防止误判

| 风险 | 场景 | 防护措施 |
|------|------|---------|
| 假 SWITCH | 用户临时问了一句不相关的问题 | `is_question_only = True` 时不触发 SWITCH |
| 假 SWITCH | 同一客户的不同实体 (account → opportunity) | entity_type 变化但 primary_entity 相同 → CONTINUE |
| 过早 SWITCH | 任务 A 还没结束用户就提了一个新实体 | 冷却机制 `_switch_cooldown = 2` |
| 假 RETURN | 用户提到了旧客户名但不是要回到旧任务 | RETURN 阈值 ≥ 50% 实体重叠（严格） |
| 归档信息丢失 | SWITCH 后用户追问旧任务细节 | 归档的 summary 通过 recall_context 可检索 |

### 5.2 与 recall_context 的配合

```
归档的 TaskRecord.summary 同时写入 ContextArchive:
  - task_id 作为特殊的 turn_id 前缀 (如 "task_0:turn_1-7")
  - user_query = "任务A: PT Sentosa 报价"
  - entities = ["PT Sentosa", "opp_001"]
  - original_messages = 该任务期间所有被压缩的轮次原文

LLM 追问已归档任务的细节时:
  recall_context("PT Sentosa 报价付款条件")
  → ContextArchive 搜索命中 task_0 的记录
  → 返回任务 A 期间的完整原文
```

### 5.3 不触发边界检测的场景

SKIP_BOUNDARY_DETECTION = [

## 六、配合方案 1/3 的增强

### 6.1 摘要分级淘汰（与任务边界配合）

```
任务边界重置解决的是"跨任务"的摘要膨胀。
摘要分级淘汰解决的是"单个任务内"的摘要膨胀。

两者配合:
  - SWITCH 时: 整体归档（最大力度的瘦身）
  - 单任务内 AutoCompact 时: 分级淘汰（渐进式瘦身）

分级淘汰规则（在 ITERATIVE_SUMMARY_PROMPT 中追加）:
  当摘要超过 1200 tokens 时（Budget 检查）:
    EVICT: "已回答问题"中最早的条目 → 只保留最近 3 条
    EVICT: "已完成操作"中纯查询操作 → 降级为一行: "1-3. 查询客户/商机/联系人"
    KEEP:  "关键数据"永不淘汰（由 Skill 锚点保护）
    KEEP:  "Active Task"永不淘汰
```

### 6.2 渐进式遗忘（与任务边界配合）

```
任务边界重置已经天然实现了"渐进式遗忘"的效果:
  - 当前任务: 详细摘要（7-section 完整）
  - 归档任务: 只在 recall_context 被调用时才恢复
  - 长期遗忘: 归档任务的 PG 记录随会话清理

但在单个长任务内（如 20 轮的竞品调研），仍需要渐进式遗忘:
  近 3 轮:   完整操作描述
  4-10 轮前: 每轮一行 "N. [📦 turn:T] 操作 — 结果"
  11+ 轮前:  合并为 "1-5. 早期查询 PT Sentosa 客户/商机/联系人 [📦 turn:1-5]"
```

class ContextWindowMiddleware(AgentMiddleware):
    def __init__(self, ...):
        # ... 现有初始化 ...
        
        # ★ 新增: 任务边界检测器
        self._task_detector = TaskBoundaryDetector()
        self._current_turn_count = 0  # 轮次计数器
    
    def before_model(self, state, runtime):
        messages = state.get("messages", [])
        
        # 1. Post-Skill Compact (不变)
        messages = self._apply_post_skill_compact(messages)
        
        # 2. MD5 去重 (不变)
        dedup_result = self._md5_dedup(messages)
        if dedup_result:
            messages = dedup_result["messages"]
        
        # ★ 3. 任务边界检测（新增）
        if self._should_check_boundary(messages):
            current_turn_msgs = self._get_current_turn_messages(messages)
            signal = extract_task_signal(current_turn_msgs)
            action = self._task_detector.detect(signal)
            
            if action.type == "SWITCH":
                self._handle_task_switch()
                # 重置后重新估算 tokens — 可能不再需要压缩
            elif action.type == "RETURN":
                self._handle_task_return(action)
        
        # 4. 阈值判断 + 三层级联压缩 (不变)
        estimated = _estimate_tokens(messages)
        # ... 现有逻辑 ...
    
    def _should_check_boundary(self, messages: list) -> bool:
        """判断是否需要执行边界检测"""
        # 前 3 轮不检测（任务还没建立）
        if self._current_turn_count < 3:
            return False
        # Skill 正在执行时不检测
        if self._skill_tail_protection._is_skill_active(messages, 0):
            return False
        return True
    
    def _get_current_turn_messages(self, messages: list) -> list:
        """获取当前轮次的消息（最后一条 HumanMessage 之后）"""
        start = self._find_current_turn_start(messages)
        return messages[start:]

═══ 轮次 19: 回到 PT Sentosa ═══

## 十二、关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 边界检测方式 | 纯规则（零 LLM） | 每轮都执行，不能有延迟和成本 |
| 实体匹配算法 | 集合重叠度 | 简单、可解释、CRM 实体有明确 ID |
| SWITCH 冷却 | 2 轮 | 防止频繁切换（用户切换主题后通常 2 轮才稳定） |
| RETURN 恢复方式 | 直接恢复摘要 | 比 recall_context 更快（无需 LLM 发起工具调用） |
| 归档粒度 | 完整 7-section 摘要 | 恢复时无需重新压缩，直接可用 |
| 归档存储 | 内存 (session 级) | 任务记录数量少（一次会话最多 10-15 个），无需 PG |
| 与 ContextArchive 的关系 | 归档时同步写入 | 统一恢复入口，recall_context 可检索归档任务 |
