Skill 后端配置 — 产品设计

文档定位：Skill 后端管理配置页面的产品设计规范，面向前端开发与后端 API 对接。

适用范围：Agent 管理后台 → 技能管理模块（/admin/skills）

设计依据：《Skill 管理体系设计方案》、《CRM-Tool-Skill 通用工具体系设计》

🎯 核心目标

将 Skill 的定义、管理全流程从"文件导入"模式升级为"数据库定义 + 后台管理"模式，提供完整的 Skill CRUD、启用/禁用、分类管理、执行监控能力。

一、页面信息架构

1.1 整体布局

💡 为什么需要 Skill 后端配置能力

当前 Skill 定义依赖本地 Markdown 文件 + SQL 初始化脚本，存在以下核心痛点：

  • 运营无法自主管理：新增/调整技能必须开发介入修改文件并重新部署，响应周期长
  • 无法按租户定制：所有租户共享同一套技能定义，无法满足不同客户的差异化场景需求
  • 缺乏运行可观测性：技能执行效果（成功率、耗时、调用频次）无法量化，无法驱动持续优化
  • 上线风险不可控：没有启用/禁用开关，问题技能无法快速下线止血
  • 技能组织混乱：技能数量增长后缺乏分类体系，运营人员难以快速定位和管理目标技能
  • 问题排查困难：技能执行过程无日志记录，出现异常时无法追溯调用链路和失败原因

产品价值：

  • 运营自助化：业务人员通过后台界面即可完成技能的创建、编辑、测试、上下线，无需开发排期
  • 租户级定制：支持按租户配置专属技能，满足不同行业客户的个性化 Agent 能力诉求
  • 分类体系化管理：通过动态分类对技能进行归类组织，支持按业务域快速筛选，技能数量增长后仍可高效管理
  • 执行日志全链路追踪：记录每次技能执行的参数、工具调用、耗时、Token 消耗和错误信息，支持按 Thread ID 追踪完整对话链路，快速定位问题根因
  • 数据驱动优化：执行日志 + 统计面板提供技能效果量化数据，指导 Prompt 调优和工具编排优化
  • 风险可控：启用/禁用即时生效 + 确认机制 + 工具读写属性自动推断，保障生产环境稳定性

二、技能列表页

技能列表页是 Skill 后端配置的核心管理入口，运营人员在此完成技能的全生命周期管理。页面提供以下核心能力：

  • 全局总览：以卡片形式展示所有已配置的技能，一目了然掌握技能数量、状态分布和执行效果
  • 分类筛选：通过顶部分类 Tab 快速定位目标业务域的技能，避免在大量技能中逐一查找
  • 即时管控：支持在列表页直接启用/禁用技能，操作即时生效无需进入编辑页
  • 快捷操作：每个技能卡片提供编辑、日志、克隆、删除等常用操作入口

3.2 配置结构说明

页面布局

技能创建/编辑页采用左右分栏布局：

  • 左侧 — 资源文件树：展示该 Skill 关联的知识文件和资源目录，支持新增文件/文件夹、删除、刷新操作
  • 右侧 — 配置表单：Skill 的核心配置项，采用双列紧凑布局，减少页面滚动
  • 顶部标题栏：显示"编辑: 名称（apiKey）"格式，右侧放置测试/保存/取消按钮
资源文件树

每个 Skill 可关联一组知识资源文件，作为技能执行时的上下文参考：

  • SKILL.md：技能的 Prompt 定义文件（Markdown 格式）
  • knowledge/：知识库目录，存放行业知识、分析策略、竞品手册等参考文档
  • 操作栏：支持新增文件（📄+）、新增文件夹（📁+）、删除（🗑）、刷新（🔄）
  • 文件统计：顶部显示"N目录 · M文件"统计信息

五、工具管理页

工具管理页展示 Agent 系统中所有已注册的工具（Tool），供运营人员查看工具能力、了解读写属性，并在 Skill 配置时作为"允许的工具"选择依据。

  • 工具总览：以列表形式展示所有已注册工具的名称、描述、读写属性和启用状态
  • 分类筛选：按工具标签（read/write/external 等）快速筛选
  • Skill 关联查看：查看每个工具被哪些 Skill 引用

5.2 筛选与交互规则

筛选条件
筛选项类型说明
技能筛选下拉选择选项来自已有技能列表（含已禁用/已删除的技能），支持"全部技能"
状态筛选下拉选择全部 / 成功 / 失败
时间范围日期范围选择器默认最近 7 天，支持自定义范围
Thread ID文本输入精确匹配会话线程 ID，用于追踪某次对话中所有技能的执行记录
关键词搜索文本输入模糊匹配参数值、错误信息
入口方式
  • 左侧菜单入口：点击"📊 执行日志"菜单，展示所有技能的执行日志（默认）
  • 技能卡片入口：从技能列表页点击某个技能的"查看日志"按钮，跳转到执行日志页并自动筛选该技能（URL 带 ?skill=xxx 参数）
