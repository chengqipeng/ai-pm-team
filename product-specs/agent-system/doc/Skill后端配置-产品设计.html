Skill 后端配置 — 产品设计

文档定位：Skill 后端管理配置页面的产品设计规范，面向前端开发与后端 API 对接。

适用范围：Agent 管理后台 → 技能管理模块（/admin/skills）

设计依据：《Skill 管理体系设计方案》、《CRM-Tool-Skill 通用工具体系设计》

🎯 核心目标

将 Skill 的定义、管理全流程从"文件导入"模式升级为"数据库定义 + 后台管理"模式，提供完整的 Skill CRUD、启用/禁用、分类管理、执行监控能力。

一、页面信息架构

1.1 整体布局

💡 为什么需要 Skill 后端配置能力

当前 Skill 定义依赖本地 Markdown 文件 + SQL 初始化脚本，存在以下核心痛点：

  • 运营无法自主管理：新增/调整技能必须开发介入修改文件并重新部署，响应周期长
  • 无法按租户定制：所有租户共享同一套技能定义，无法满足不同客户的差异化场景需求
  • 缺乏运行可观测性：技能执行效果（成功率、耗时、调用频次）无法量化，无法驱动持续优化
  • 上线风险不可控：没有启用/禁用开关，问题技能无法快速下线止血
  • 技能组织混乱：技能数量增长后缺乏分类体系，运营人员难以快速定位和管理目标技能
  • 问题排查困难：技能执行过程无日志记录，出现异常时无法追溯调用链路和失败原因

产品价值：

  • 运营自助化：业务人员通过后台界面即可完成技能的创建、编辑、测试、上下线，无需开发排期
  • 租户级定制：支持按租户配置专属技能，满足不同行业客户的个性化 Agent 能力诉求
  • 分类体系化管理：通过动态分类对技能进行归类组织，支持按业务域快速筛选，技能数量增长后仍可高效管理
  • 执行日志全链路追踪：记录每次技能执行的参数、工具调用、耗时、Token 消耗和错误信息，支持按 Thread ID 追踪完整对话链路，快速定位问题根因
  • 数据驱动优化：执行日志 + 统计面板提供技能效果量化数据，指导 Prompt 调优和工具编排优化
  • 风险可控：启用/禁用即时生效 + 确认机制 + 工具读写属性自动推断，保障生产环境稳定性

二、技能列表页

技能列表页是 Skill 后端配置的核心管理入口，运营人员在此完成技能的全生命周期管理。页面提供以下核心能力：

  • 全局总览：以卡片形式展示所有已配置的技能，一目了然掌握技能数量、状态分布和执行效果
  • 分类筛选：通过顶部分类 Tab 快速定位目标业务域的技能，避免在大量技能中逐一查找
  • 即时管控：支持在列表页直接启用/禁用技能，操作即时生效无需进入编辑页
  • 快捷操作：每个技能卡片提供编辑、日志、克隆、删除等常用操作入口

3.2 配置结构说明

页面布局

技能创建/编辑页采用左右分栏布局：

  • 左侧 — 资源文件树：展示该 Skill 关联的知识文件和资源目录，支持新增文件/文件夹、删除、刷新操作
  • 右侧 — 配置表单：Skill 的核心配置项，采用双列紧凑布局，减少页面滚动
  • 顶部标题栏：显示"编辑: 名称（apiKey）"格式，右侧放置测试/保存/取消按钮
资源文件树

每个 Skill 可关联一组知识资源文件，作为技能执行时的上下文参考：

  • SKILL.md：技能的 Prompt 定义文件（Markdown 格式）
  • knowledge/：知识库目录，存放行业知识、分析策略、竞品手册等参考文档
  • 操作栏：支持新增文件（📄+）、新增文件夹（📁+）、删除（🗑）、刷新（🔄）
  • 文件统计：顶部显示"N目录 · M文件"统计信息

六、版本管理

版本管理为 Skill 提供完整的变更追踪与回滚能力，确保 Prompt 调优和配置变更过程可控、可追溯、可恢复。

  • 版本记录：每次点击"创建新版本"时生成版本快照，记录完整的配置状态（Prompt + 资源文件 + 配置字段）
  • 版本对比：勾选任意两个版本进行 Diff 对比，左侧展示资源文件树变更，右侧展示文件内容行级差异
  • 版本回滚：一键回滚到历史版本，回滚后生成新版本号，当前版本不丢失

6.1 入口与布局

版本管理入口

版本管理作为左侧资源文件树中的一级菜单项（与"Skill 配置"、"SKILL.md"同级），点击后右侧内容区切换为版本历史面板：

  • 顶部标题栏：显示"编辑: 名称（apiKey）vX.X.X"，右侧保留"▶ 测试"、"保存"、"取消"按钮
  • 生效版本提示：标题栏下方显示 📌 当前生效版本 vX.X.X，右侧显示"返回编辑"链接
  • 左侧菜单：资源文件树中增加 版本管理 菜单项（蓝色高亮选中态）

6.4 版本回滚

回滚交互流程
点击版本行"回滚"
→
弹出确认对话框
→
确认回滚
→
基于目标版本生成新版本号
→
刷新页面，新版本成为当前生效版本

回滚操作说明：

  • 每个历史版本行右侧显示 删除 和 回滚 两个操作链接
  • 当前生效版本（标记为"当前"）不显示回滚/删除操作
  • 回滚后基于目标版本的快照内容创建一个新版本（版本号递增），原版本记录保留不变
  • 回滚确认弹框需展示目标版本号、创建时间，并提示"回滚后将基于该版本创建新版本作为当前生效版本"

6.5 版本管理规则

规则说明
手动创建版本点击"+ 创建新版本"按钮时，基于当前编辑态的配置生成版本快照，版本号按 vX.Y.Z 格式递增（patch 位自增）
版本快照内容包含完整的 Skill 配置（基础字段 + SKILL.md Prompt + 工具列表 + 资源文件目录及内容），确保任意版本可完整恢复
版本只读已创建的版本标记为 read_only，不可直接编辑；如需修改需基于某版本回滚后在编辑态修改再创建新版本
回滚生成新版本回滚操作不会删除历史版本，而是基于目标版本创建一个新版本（版本号递增），新版本成为当前生效版本
版本删除历史版本支持删除（当前生效版本不可删除），删除后不可恢复
对比方式勾选任意两个版本的 checkbox 后点击"对比选中版本"，进入 Diff 视图；默认展示 SKILL.md 的行级差异
版本切换查看点击版本行可切换查看该版本的资源文件内容（只读模式），左侧文件树同步切换为该版本的文件快照
生效版本标识页面顶部始终显示"📌 当前生效版本 vX.X.X"，编辑页标题栏显示当前版本号
版本备注创建版本时可选填写备注说明（如"— 测试"），展示在版本条目的时间行后方

6.6 版本号在技能列表的展示

技能列表页的每个技能卡片上展示当前生效版本号（如 v2.0.3），编辑页标题栏同步显示版本号。

  • 版本号显示在技能名称右侧，使用蓝色 badge 样式
  • 编辑页标题格式："编辑: 名称（apiKey）vX.X.X"
  • 标题栏下方红色文字提示当前生效版本号，右侧"返回编辑"链接可从版本管理/只读模式切回编辑态

七、测试调试

Skill 测试调试是保障技能质量的核心能力，支持运营人员在技能上线前充分验证 Prompt 效果、工具调用链路和输出质量，避免问题技能影响生产环境。

7.1 测试入口

7.2 逐步调试模式

逐步调试交互流程
输入参数
→
LLM 推理（暂停）
→
确认/修改工具参数
→
执行工具（暂停）
→
查看结果 → 继续/终止

逐步模式下，每一步执行后暂停，运营人员可以：

  • 查看 LLM 推理过程：展示 LLM 的思考内容（thinking），理解为什么选择调用某个工具
  • 修改工具参数：在工具实际执行前，修改 LLM 生成的参数后再执行
  • 查看工具返回：展示工具的完整输入和输出，判断数据是否符合预期
  • 跳过某步：跳过当前工具调用，手动输入模拟返回值继续后续流程
  • 终止执行：发现问题后随时终止，回到 Prompt 编辑修改后重跑
  • 继续执行：确认当前步骤无误，继续下一步
逐步调试面板状态
步骤状态颜色说明
LLM 推理🟢 绿色背景展示 LLM 思考过程和决策
工具调用🔵 蓝色背景展示工具名称、输入参数、返回结果
等待确认🟡 黄色背景逐步模式下暂停，等待用户操作
高风险确认🔴 红色背景高风险工具调用前，必须用户确认
最终输出🟣 紫色背景Skill 执行完成，展示最终结果

7.3 工具 Mock 能力

Mock 数据配置

调试时可以对某些工具设置 Mock 返回值，不实际调用后端，适用于：

  • 测试环境没有真实业务数据时，模拟工具返回
  • 验证 Prompt 对不同数据场景的处理逻辑（正常数据 / 空数据 / 异常数据）
  • 避免调试过程中产生真实的数据修改（高风险工具）
Mock 配置示例
工具名称
query_data
Mock 返回值（JSON）
{"name":"测试客户","industry":"互联网","arr":"$500K"}
启用 Mock

7.4 测试用例管理

保存与回归

支持将调试过程中的参数和期望结果保存为测试用例，用于后续 Prompt 修改后的回归验证：

用例名称输入参数期望关键词上次结果操作
正常客户 account_id=ACC001 华为, ARR, 续约 ✅ 通过 执行
不存在的客户 account_id=ACC999 未找到, 不存在 ✅ 通过 执行
高风险客户 account_id=ACC007 风险, 流失, 建议 ❌ 失败 执行
▶ 批量执行全部用例 + 新增用例
测试用例验证规则
验证方式说明
关键词匹配最终输出中必须包含指定关键词（逗号分隔，全部命中=通过）
排除词检查最终输出中不能包含指定词汇（如脏数据、错误格式）
工具调用断言验证执行过程中是否调用了预期的工具（如必须调用 query_data）
耗时阈值执行总耗时不超过指定阈值（超时=失败）
