Tool 评测 — 产品设计详案

直接调用工具函数验证功能正确性，不经过 Agent 推理层，定位工具本身的缺陷

📐

核心定位与设计原则

定位
1
单元测试级别 被测对象是单个 Tool 的单个方法，验证其"给定输入 → 返回正确输出"
2
完全隔离 不经过 Agent LLM 推理，直接调用 Tool.call()，排除推理层干扰
3
可重复执行 每次执行前重置 Backend 数据为 seed data，保证用例结果确定性
4
质量门禁 Tool 评测通过是 Agent 评测和端到端评测的前置条件
设计原则
🎯
四分类覆盖 每个工具必须覆盖 正常（normal）· 异常（error）· 边界（boundary）· 副作用（side_effect）四类场景
🔄
参数组合自动生成 根据工具的 input_schema 自动推导 Pairwise / 等价类 / 边界值 组合用例
📊
多粒度执行 支持按工具 / 方法 / 用例 / 标签四种粒度触发执行
🧹
自动清理 setup_steps 写入的数据在用例执行后自动推导 cleanup_steps 清理

参数组合自动生成

根据 input_schema 自动推导用例覆盖
生成策略
A 正交覆盖（Pairwise）
最少用例覆盖所有参数对的组合，适用于参数 > 3 个且相互独立的方法
B 等价类 + 边界值
每个参数取等价类代表值 + min/max 边界，适用于有明确取值范围的方法
C 场景驱动
按业务场景枚举典型用法，适用于参数间有语义耦合的方法
D 全组合（Exhaustive）
穷举所有组合，仅用于参数少（bool ≤ 3 个）的方法
自动生成内容
+
正向用例 最小必填参数 · 全部参数默认值 · Pairwise 组合
−
逆向用例 required 参数缺失 · 类型错误 · 非法枚举值
⟷
边界用例 null · 空字符串 · 超长 · 0 · 负数 · 超大数 · min/max
用户操作路径

1. 选择工具/方法 → 点击「自动生成参数组合」

2. 系统读取 input_schema → 按策略生成用例草稿

3. 用户审核/微调 → 确认入库

4. 后续工具 schema 变更时可一键重新生成覆盖

Memory 评测 — 产品设计详案

验证长期记忆子系统的写入正确性、检索召回率、时间衰减与冲突消解能力

📐

核心定位与五层评测体系

定位
1
记忆子系统独立验证 被测对象是 Memory Engine，包含写入提取、向量检索、冲突消解三大链路
2
实例级隔离 使用独立 VDB collection + 独立 tenant，预置种子记忆数据集（40+ 条），不污染生产数据
3
串行状态累积 提取类用例按顺序执行，每次提取写入的记忆会影响后续用例的检索结果，模拟真实累积行为
4
450 条用例覆盖 200 条检索召回 + 250 条四维度提取 = 450 条完整用例集
五层评测体系
L1
写入正确性（Extract Accuracy） 用户发言 → LLM 提取 → 记忆写入，维度归类是否正确
L2
检索召回率（Retrieval Recall） 给定查询 → 返回 Top-K → 计算 Recall@K / MRR / Top1 Hit
L3
时间衰减（Temporal Dynamics） 模拟多轮对话后，早期记忆的召回是否合理衰减
L4
上下文匹配度（Context Relevance） 召回的记忆与当前对话上下文的相关性排序
L5
端到端效果（E2E Impact） 记忆注入后 Agent 回复质量是否实际提升

四维度记忆提取模型

用户发言 → LLM 四路并行提取 → 分维度写入记忆库
👤
Profile

用户/团队的稳定属性

• 身份角色、履历背景

• 团队规模、组织结构

• 行业领域、负责区域

• KPI 目标、公司信息

示例："在这个行业干了十年了，从技术转管理"
⚙️
Preferences

用户的交互偏好

• 汇报格式偏好

• 沟通风格（简洁/详细）

• 时间段偏好

• 数据展示方式

示例："以后回复简短一些，别写那么多废话"
📏
Agent Rules

用户设定的行为规则

• 操作前确认要求

• 禁止执行的操作

• 条件触发规则

• 流程限制约束

示例："金额超过 100 万的报价必须先让我确认"
🏢
Entities

业务实体的事实信息

• 客户/联系人特征

• 项目进展状态

• 商业关系与决策链

• 报价/预算/时间线

示例："华为张伟喜欢看 PPT，决策果断但要数据支撑"
提取评测验证点
维度归类正确性 发言应归入哪个维度（或不提取）
merge_key 生成质量 同主题的记忆能否正确合并 upsert
负例鲁棒性 闲聊/问候/纯指令不应触发提取
📊

评测指标体系

检索召回指标
R@K
Recall@K（召回率） Top-K 结果中命中期望记忆的比例，K=3 和 K=5 双指标
P@K
Precision@K（精确率） Top-K 结果中属于期望结果的比例，衡量噪声
MRR
Mean Reciprocal Rank 第一个正确结果出现的位置倒数，衡量排序质量
T1
Top1 Hit Rate 第一条结果即为正确的比例，最严格指标
提取正确性指标
DA
Dimension Accuracy 提取到的维度是否与期望维度一致（正确归类率）
NR
Negative Rejection Rate 不应提取的发言正确拒绝的比例（假阳性控制）
RA
Reflect Action Accuracy 反思用例中，冲突检测和动作选择的正确率
SC
State Consistency 串行执行后记忆库状态（条数/内容）与预期一致性
质量合格线
≥ 0.7 avg Recall@5
≥ 0.5 avg MRR
≥ 85% Dimension Accuracy
≥ 90% Negative Rejection
🔄

反思与冲突消解机制

新信息与旧记忆矛盾时的处理策略
冲突触发场景
⚡
用户反馈反思
用户纠正 Agent 的错误认知："不对，我不负责华东区了"
🔀
冲突检测反思
新提取信息与已有记忆矛盾："预算从 500 万变成了 800 万"
🏁
会话结束反思
对话结束时回顾全程，提炼高价值信息
⚠️
失败驱动反思
Agent 执行失败后反思原因，更新规则记忆
消解策略（expected_action）
update_old 更新旧记忆
新信息是旧信息的演进，直接覆盖（如预算变更、调岗）
archive_old 归档旧记忆
旧信息已失效，归档但不删除（如离职的联系人）
keep_both 两条并存
新旧信息分别适用不同条件，不矛盾（如不同客户的策略）
discard_new 丢弃新信息
新信息可信度低或为临时状态，不写入长期记忆
