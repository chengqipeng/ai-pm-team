# 四路提取提示词过拟合深度分析与100场景验证

## 一、过拟合分析

### 1.1 分析方法

对 `prompts.py` 中的四个提示词（PROFILE / PREFERENCES / AGENT_RULES / ENTITIES）进行以下维度的过拟合检测：

1. **模式单一性**：提示词中的"属于"示例是否覆盖了足够多的表达模式
2. **边界硬编码**：判断规则是否过度依赖特定词汇/句式，导致换一种说法就失效
3. **反例覆盖**：提示词中的"不属于"规则是否覆盖了真实场景中的混淆情况
4. **泛化能力**：对非典型表达（口语化、省略主语、反问句、多意图混合）的处理能力

---

### 1.2 PROFILE_EXTRACT_PROMPT 过拟合风险

| 风险点 | 严重度 | 说明 |
|--------|--------|------|
| 主语判断过度依赖"我" | 🟡 中 | 省略主语的中文表达（如"在华东区做了5年"）可能漏提取 |
| "我们公司"归属模糊 | 🟠 高 | "我们公司做金融"→profile，但"我们公司的张总"→entities，边界不清 |
| 排除规则过于绝对 | 🟡 中 | "精确数值不提取"但"我管理15人团队"中的15是有效画像信息 |
| 缺少否定/更新场景 | 🟡 中 | "我不再负责华东区了"这类否定更新未明确处理 |
| 复合身份表达 | 🟡 中 | "我既是产品经理也兼任售前"这类多角色表达可能只提取部分 |

**过拟合特征**：提示词中的示例全部是"我是XX"、"我负责XX"的标准句式，对口语化、省略主语、反问句等表达模式覆盖不足。

---

### 1.3 PREFERENCES_EXTRACT_PROMPT 过拟合风险

| 风险点 | 严重度 | 说明 |
|--------|--------|------|
| 偏好性动词列表有限 | 🟠 高 | 只列了"喜欢/习惯/偏好/倾向/觉得更好/更关注/不喜欢"，遗漏"受不了"、"烦"、"讨厌"、"无所谓" |
| 隐性偏好无法识别 | 🟠 高 | "每次你给我的报告我都跳过前面的废话直接看结论"→隐含偏好但无偏好性动词 |
| 与 agent_rules 边界模糊 | 🔴 极高 | "金额用万为单位"→无主语时，到底是偏好还是指令？现有规则无法区分 |
| 条件性偏好 | 🟡 中 | "如果是大客户我喜欢亲自跟，小客户让团队处理"→条件偏好未覆盖 |
| 否定偏好表达多样 | 🟡 中 | "别给我发那种长报告"→否定偏好但无"我"+"偏好动词"的标准模式 |

**过拟合特征**：严格要求"(1)有'我'作为主语 (2)有偏好性动词"的双条件，导致大量隐性偏好表达被漏掉。同时，无主语的偏好表达（"金额用万"）在 preferences 和 agent_rules 之间摇摆。

---

### 1.4 AGENT_RULES_EXTRACT_PROMPT 过拟合风险

| 风险点 | 严重度 | 说明 |
|--------|--------|------|
| 过度依赖"你"字判断 | 🔴 极高 | "回复不超过100字"无"你"字但明显是指令，现有规则可能漏提取 |
| 省略主语的指令 | 🟠 高 | "分析报告要包含同比环比"→无"你"字的指令，依赖模型推理 |
| 与操作指令边界 | 🟡 中 | "帮我查XX"是操作指令不提取，但"以后帮我查的时候加上时间范围"是持久规则 |
| 更新/撤销语义 | 🟡 中 | "取消之前的限制"、"算了不用了"这类撤销指令的处理 |
| 隐性规则 | 🟡 中 | "上次你给我的报告太长了"→隐含"以后要短"但未直接说 |

**过拟合特征**：提示词声明"主语是'你'"作为核心判断依据，但实际中文表达中大量指令省略主语。现有50个测试用例中，agent_rules 的用例几乎都包含"你"字，导致对无"你"字指令的泛化能力未被验证。

---

### 1.5 ENTITIES_EXTRACT_PROMPT 过拟合风险

| 风险点 | 严重度 | 说明 |
|--------|--------|------|
| "第三方实体名称"要求过严 | 🟠 高 | "那个客户上次说预算不够"→有指代但无具体名称，是否提取？ |
| "我们公司"的归属 | 🟠 高 | "我们公司的竞品是Salesforce"→竞品信息归 profile 还是 entities？ |
| 用户对第三方的主观判断 | 🟡 中 | "我觉得张总不靠谱"→主语是"我"但描述第三方，边界模糊 |
| 时效性信息 | 🟡 中 | "华为下周要开标"→时效性强的信息是否值得提取？ |
| 多实体混合 | 🟡 中 | "华为和腾讯都在看我们的方案"→应拆分为两条还是一条？ |

**过拟合特征**：示例全部是"XX公司的XX人"的标准模式，对指代（"那个客户"）、省略（"张总说..."不带公司名）、多实体混合等场景覆盖不足。

---

### 1.6 跨维度过拟合总结

| 过拟合类型 | 影响范围 | 根因 |
|-----------|---------|------|
| **句式模板化** | 全部4个prompt | 示例都是标准陈述句，缺少口语/反问/省略/条件句 |
| **主语判断刚性** | profile/preferences/agent_rules | 中文大量省略主语，硬性要求"我"/"你"会漏提取 |
| **边界词汇化** | preferences vs agent_rules | 依赖特定动词列表区分，而非语义意图 |
| **单一意图假设** | 全部 | 假设每句话只有一个意图，但实际常混合多意图 |
| **正面示例偏重** | 全部 | "属于"的示例远多于"不属于"，模型可能过度提取 |

## 二、100个测试场景设计

### 设计原则

1. **覆盖过拟合盲区**：针对上述分析的每个风险点设计对应用例
2. **表达多样性**：口语化、省略主语、反问、条件句、否定句、多意图混合
3. **边界对抗**：专门设计在两个维度之间摇摆的模糊用例
4. **真实场景**：模拟 CRM 销售场景中的真实对话
5. **分布均衡**：四个维度 + 不提取 + 混合场景均匀分布

### 场景分布

| 类别 | 数量 | 说明 |
|------|------|------|
| profile 正例 | 12 | 含省略主语、复合身份、否定更新 |
| preferences 正例 | 12 | 含隐性偏好、条件偏好、否定偏好 |
| agent_rules 正例 | 12 | 含无"你"字指令、更新/撤销、隐性规则 |
| entities 正例 | 12 | 含指代、多实体、时效性、主观判断 |
| 不提取（操作/寒暄/查询） | 16 | 各种不应提取的场景 |
| 混合意图（双维度） | 16 | 一句话触发两个维度 |
| 边界对抗（模糊归属） | 20 | 专门测试维度间混淆 |
| **合计** | **100** | |

## 四、关键发现与优化建议

### 4.1 高风险过拟合区域

1. **preferences vs agent_rules 的无主语边界**（#81-84）
   - 现状：依赖"你"/"我"判断，但大量真实表达省略主语
   - 建议：增加"持久性意图"判断维度——如果是对输出的持久要求且无"我+偏好动词"，归 agent_rules

2. **隐性偏好漏提取**（#13-14, #22）
   - 现状：严格要求"我+偏好动词"双条件
   - 建议：扩展偏好识别模式，增加"行为暗示"类（"每次都跳过"、"根本看不下去"）

3. **"我们公司"的归属**（#72, #91-92）
   - 现状：未明确区分"我们公司的特征"（profile）vs "我们公司被客户评价"（entities）
   - 建议：在 profile prompt 中增加规则："我们公司/我们团队的特征 → profile"

4. **指代性实体**（#39-40, #46）
   - 现状：要求"具体第三方实体名称"
   - 建议：放宽为"可推断的第三方实体"，允许上下文指代

### 4.2 建议的 Prompt 修改方向

```
# PREFERENCES — 扩展识别模式
## 属于 preferences 的信息（扩展）
除标准偏好动词外，以下模式也视为偏好：
- 行为暗示："每次都XX"、"总是XX"、"从来不XX"
- 否定厌恶："受不了XX"、"烦XX"、"看不下去XX"
- 程度表达："更在意XX"、"XX比XX重要"
- 条件习惯："如果XX就XX，否则XX"

# AGENT_RULES — 补充无主语规则
## 属于 agent_rules 的信息（补充）
即使没有"你"字，以下模式也视为 agent_rules：
- 持久性输出要求："XX要包含XX"、"XX不超过XX"、"XX用XX格式"
- 持久性流程要求："以后XX"、"每次XX"、"先XX再XX"
- 判断依据：是否是对 Agent 未来行为的持久约束（vs 一次性操作）
```

### 4.3 测试执行建议

1. 先用现有 prompt 跑完100个用例，记录准确率
2. 重点关注 G 组（边界对抗）的错误模式
3. 如果 G 组准确率 < 70%，说明过拟合严重，需要调整 prompt
4. 调整后重跑，对比前后准确率变化
