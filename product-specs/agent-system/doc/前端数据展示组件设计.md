# 前端数据展示组件设计

## 1. 设计基线

对齐 CRM 系统（paas-front-platform）的设计风格，确保 Agent 对话页面嵌入 CRM 后视觉一致。

### 1.1 设计 Token（从 CRM 源码提取）

```
颜色体系：
  主色:     blue-600 (#2563EB)  / blue-700 (#1D4ED8)
  主色浅:   blue-50 (#EFF6FF)   / blue-100 (#DBEAFE)
  背景:     white (#FFFFFF)     / gray-50 (#F9FAFB)
  边框:     gray-200 (#E5E7EB)  / gray-100 (#F3F4F6)
  文字:     gray-800 (#1F2937)  / gray-600 (#4B5563) / gray-400 (#9CA3AF)
  成功:     green-600 (#059669)
  警告:     amber-500 (#F59E0B)
  错误:     red-500 (#EF4444)

圆角:     rounded-lg (8px)    / rounded-xl (12px)
阴影:     shadow-sm           / shadow (hover)
字体:     -apple-system, PingFang SC, Helvetica Neue
字号:     text-xs (12px) / text-sm (14px) / text-base (16px)

间距:     px-4 py-2.5 (表格单元格) / px-5 py-3 (工具栏) / gap-2.5 (图标+文字)
```

## 2. 组件清单

### 2.1 布局组件

| 组件 | 对应 CRM 组件 | 用途 |
|------|-------------|------|
| `AgentShell` | `CrmApp` | 三栏布局容器（侧边栏+主区域+链路面板） |
| `AgentSidebar` | `CrmSidebar` | 左侧对话历史列表 |
| `AgentTopbar` | `CrmTopbar` | 顶部栏（标题+搜索+操作按钮） |
| `RightPanel` | — | 右侧链路/文档面板（可收缩） |

### 2.2 对话组件

| 组件 | 用途 | 样式参考 |
|------|------|---------|
| `ChatArea` | 对话消息区（居中 800px） | 白色背景，消息间距 24px |
| `MessageBubble` | 单条消息（用户/Agent） | 用户：蓝色气泡右对齐；Agent：无背景左对齐 |
| `WelcomeScreen` | 首次进入的欢迎页 | 居中标题+4 个快捷卡片（2×2 网格） |
| `InputBox` | 底部输入框 | 白色卡片+阴影+大圆角，内含上传和快捷按钮 |
| `ToolTag` | 工具调用标签 | 黄色（启动）/绿色（完成）/蓝色（LLM） |

### 2.3 数据展示组件（Agent 回复中的结构化数据）

| 组件 | 用途 | 样式参考 |
|------|------|---------|
| `DataTable` | 表格展示（客户列表、商机列表） | 对齐 `EntityDataList` 的表格样式 |
| `StatCards` | 统计卡片组（总数、金额、占比） | 横排卡片，蓝色数字+灰色标签 |
| `DetailCard` | 单条记录详情卡片 | 对齐 `EntityDataDetail` 的字段展示 |
| `ChartBlock` | 图表区块（柱状图、饼图） | 白色卡片+标题+图表区域 |
| `ActionBar` | 操作按钮栏（新建、编辑、删除） | 对齐 CRM 工具栏的按钮样式 |

### 2.4 链路展示组件

| 组件 | 用途 | 样式参考 |
|------|------|---------|
| `TraceHeader` | 链路统计头部（耗时/Token/迭代/工具） | 横排统计卡片 |
| `SpanCard` | 单个链路步骤卡片（对齐检索链路详情 PipelineNode 风格） | `<details>` 折叠卡片 + 左边框状态色 + Step N + 中文名 + 英文名 + 耗时 badge + 输入参数/输出结果折叠区 |
| `ChildSpan` | 子步骤（vector_search/rerank） | 缩进列表+圆点状态色+耗时 |
| `SourceFilter` | source 过滤按钮组 | 胶囊按钮（Agent/Middleware/Tool/Skill/SubAgent） |

## 4. Agent 回复中的数据渲染规则

当 Agent 返回结构化数据时，前端应自动识别并渲染为对应组件：

| 数据特征 | 渲染组件 | 示例 |
|---------|---------|------|
| Markdown 表格（`\|...\|`） | `DataTable` | 客户列表、商机列表 |
| 数字+标签对（如"总数: 42"） | `StatCards` | 统计结果 |
| 键值对列表 | `DetailCard` | 单条记录详情 |
| 含百分比/金额的分组数据 | `ChartBlock` | Pipeline 分析 |
| 纯文本 | Markdown 渲染 | 普通回答 |

## 5. 与 CRM 系统的集成方式

### 5.1 嵌入方式

Agent 对话页面作为 CRM 系统的一个视图，通过 `ShellApp` 的视图切换器进入：

```tsx
// ShellApp.tsx 中新增 Agent 视图
{currentView === 'agent' && (
  <AgentApp loginUser={loginUser} onSwitchToCrm={() => setView('crm')} />
)}
```

### 5.2 共享设计 Token

Agent 页面使用与 CRM 相同的 Tailwind 配置和颜色变量，确保：
- 侧边栏宽度一致（w-56 = 224px）
- 顶栏高度一致（h-14 = 56px）
- 按钮、表格、卡片样式完全对齐
- 图标使用 lucide-react（与 CRM 一致）

### 5.3 数据联动

Agent 查询到的业务数据可以直接跳转到 CRM 对应的记录详情：

```
Agent 回复: "张三有 3 个商机"
  → 表格中的商机名称是可点击链接
  → 点击跳转到 CRM 的 EntityDataDetail 页面
```

## 6. 链路展示组件详细规范

### 6.1 SpanCard — Skill 步骤卡片

当 `step_metadata` 事件中包含 `skill_context` 字段时，SpanCard 需要展示 **执行模式标签**：

```
┌─────────────────────────────────────────────────────────────┐
│ ⚡ [19] 工具调用: skills_tool(knowledge-doc-search)          │
│       skills_tool(knowledge-doc-search) ●                    │
│       [inline]  ← skill_context 标签                         │
│       ∨ 查看输入/输出                                         │
└─────────────────────────────────────────────────────────────┘
```

#### 标签样式

| skill_context | 标签文本 | 颜色 | 含义 |
|:---|:---|:---|:---|
| `inline` | `inline` | 蓝色胶囊（bg-blue-50 text-blue-600 border-blue-200） | 注入当前对话，LLM 继续推理 |
| `fork` | `fork` | 紫色胶囊（bg-purple-50 text-purple-600 border-purple-200） | 独立子 Agent 执行 |

#### CSS 规范

```css
/* Skill 执行模式标签 */
.skill-context-badge {
  display: inline-flex;
  align-items: center;
  padding: 2px 8px;
  border-radius: 10px;
  font-size: 11px;
  font-weight: 500;
  line-height: 1;
  margin-left: 8px;
  vertical-align: middle;
}
.skill-context-badge.inline {
  background: #EFF6FF;            /* bg-blue-50 */
  color: #2563EB;                 /* text-blue-600 */
  border: 1px solid #BFDBFE;     /* border-blue-200 */
}
.skill-context-badge.fork {
  background: #FAF5FF;            /* bg-purple-50 */
  color: #9333EA;                 /* text-purple-600 */
  border: 1px solid #E9D5FF;     /* border-purple-200 */
}
```

#### 数据来源

前端从 `CUSTOM("step_metadata")` 事件的 `value.skill_context` 字段获取模式信息：

```json
{
  "type": "CUSTOM",
  "data": {
    "name": "step_metadata",
    "value": {
      "step_name": "knowledge-doc-search",
      "skill_apikey": "knowledge-doc-search",
      "step_index": 0,
      "phase": "started",
      "skill_context": "inline"
    }
  }
}
```

#### 展示位置

标签紧跟在 skill 名称后方，与 `skills_tool(xxx)` 同行展示：

```
skills_tool(knowledge-doc-search) ● [inline]
```

若 `skill_context` 为 `null`（旧版本兼容），则不展示标签。
