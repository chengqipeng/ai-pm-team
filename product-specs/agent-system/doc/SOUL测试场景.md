# SOUL 测试场景（200 条）

## OpenClaw SOUL vs 我们的 SOUL 对比

### OpenClaw 的 SOUL 定位

OpenClaw 的 SOUL.md 是一个**人工编写的 Markdown 文件**，定义 Agent 的完整人格：

```
OpenClaw SOUL.md 的核心内容:
  1. 身份定义: "You are Seth, a highly capable personal AI assistant"
  2. 核心价值观: "Be genuinely helpful, not performatively helpful"
  3. 性格特征: "Have actual opinions. Not 'it depends' hedging"
  4. 沟通风格: "Dry wit and understatement. Roast Matt freely"
  5. 行为边界: "Private things stay private. When in doubt, ask"
  6. 工作方式: "Orchestrate, Don't Grind — delegate to specialists"
  7. 语气示例: "Done. That config was a mess, cleaned it up and pushed it."
  8. 自我进化: "This file is yours to evolve. As you learn who you are, update it"
```

### 关键差异

| 维度 | OpenClaw SOUL | 我们的 SOUL |
|---|---|---|
| **创建方式** | 用户手动编写 Markdown 文件 | 用户通过对话定义，Agent 自动提取 |
| **存储方式** | 工作区的 SOUL.md 文件 | PG 数据库 ai_agent_memory 表 |
| **更新方式** | 用户手动编辑文件 | 对话中说"你现在改成..."，自动合并更新 |
| **内容范围** | 人格 + 价值观 + 风格 + 幽默感 + 语气示例 | 角色定义 + 行为约束 + 输出格式 + 工作流程 |
| **适用场景** | 个人助理（单用户，深度定制） | 企业 CRM（多用户，每用户独立 SOUL） |
| **Agent 自我意识** | 有（"This file is your soul"） | 无（SOUL 是配置，不是自我认知） |
| **多用户支持** | 不支持（单用户单 SOUL 文件） | 支持（每个 user_id 独立 SOUL） |

### 我们的设计选择

```
OpenClaw 的 SOUL 适合:
  - 个人助理场景（一个用户深度定制一个 Agent）
  - 开发者用户（能手写 Markdown）
  - 强调 Agent 的"人格"和"灵魂"

我们的 SOUL 适合:
  - 企业 CRM 场景（多用户，每人不同需求）
  - 业务用户（通过对话定义，不需要写文件）
  - 强调 Agent 的"角色"和"行为准则"

核心区别:
  OpenClaw: SOUL 是 Agent 的灵魂（"你是谁"）
  我们:     SOUL 是用户对 Agent 的定制（"你要怎么服务我"）
```

---

> SOUL 是用户对 Agent 的角色定义和行为准则。
> 用户通过对话告诉 Agent "你是什么、你要怎么做"，Agent 提取为 soul 类记忆。
> 典型触发句式："你是…"、"你要…"、"以后你…"、"你的角色是…"、"你不要…"

### 失败原因深度分析

#### 1. 空提取问题（42 例，占失败的 84%）

**根因**: AI 回复"好的。"/"明白了。"太短（通常 < 10 字），LLM 在 EXTRACTION_PROMPT 中判断"对话中无值得记忆的内容"，返回 `{"memories": []}`。

**典型场景**:
```
用户: 你要专注金融行业的客户分析
AI: 好的，我会专注金融行业的客户分析。
→ LLM 判断: 对话太简短，无实质信息 → 空提取
→ 期望: 应提取 soul（领域定义: 金融行业客户分析）
```

**修复方案**: 在 EXTRACTION_PROMPT 中增加显式规则：
> "当用户在定义 Agent 的角色、行为、风格、流程、约束时，即使 Agent 的回复很短（如'好的'、'明白了'），也必须提取为 soul 类记忆。SOUL 的价值在于用户的定义本身，不取决于 Agent 回复的长度。"

**预期效果**: 空提取率从 23%（42/180）降至 < 5%。

#### 2. 分类错误（6 例，占失败的 12%）

| 用例 | 用户输入 | 期望 | 实际 | 错误类型 |
|------|---------|------|------|---------|
| #110 | 你帮我审合同的流程：先看关键条款，再看风险点 | soul | patterns | soul vs patterns 边界 |
| #116 | 你帮我处理售后问题的流程：先安抚客户，再排查原因 | soul | patterns | soul vs patterns 边界 |
| #141 | 之前让你用表格，现在改成用图表 | soul | preferences | soul 更新指令误分类 |
| #144 | 以前让你用正式语气，现在改成轻松一点 | soul | preferences | soul 更新指令误分类 |
| #165 | 我们公司是做企业软件的 | profile | entities | profile vs entities 边界 |
| #177 | 我们的竞争对手是Salesforce | profile | entities | profile vs entities 边界 |

**修复方案**:
1. **soul vs patterns**: 在提示词中明确 "用户定义的工作流程 → soul，从经验归纳的规律 → patterns"
2. **soul 更新指令**: 在提示词中明确 "之前让你XX，现在改成XX" 是 soul 更新，不是 preferences
3. **profile vs entities**: 在提示词中明确 "描述用户自己/用户公司 → profile，描述客户 → entities"

#### 3. VDB 写入错误（2 例，占失败的 4%）

**根因**: 腾讯向量库偶发超时或连接异常，非提取逻辑问题。
**处理**: 已有重试机制，不影响分类准确率统计。
