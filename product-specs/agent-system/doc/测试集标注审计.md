# 100 场景测试集标注审计

## 审计尺度

**记忆提取的充要条件**：该信息在未来新会话中对 Agent 仍有指导意义。

- 有显式持久标志（以后/每次/默认/统一）或语义上是泛化规则 → 可提取
- 单次/情境化/一周后失效 → 不提取
- 命令 Agent 未来行为 → agent_rules，不管措辞多口语化
- 描述"我这个人"长期特征 → preferences

---

## 第一类：明确标错（建议修正）

### #29 "算了，还是用表格吧，图表看不清"

| 项 | 内容 |
|---|---|
| 现标注 | agent_rules=True |
| 建议 | **全空（不提取）** |
| 理由 | 无持久标志，"图表看不清"是解释这一次选择，不是泛化规则。参考 #93「以后分析要深入一些」才有"以后"作为持久 trigger |

---

## 第二类：应双标但被单标（建议扩为 pref + rules 双打）

B 组有个系统性问题：把「用偏好措辞包装的 Agent 行为指令」都归成 pref。这些句子在语义上**同时承载了用户偏好和对 Agent 的持久约束**，应双标。

### #19 "如果是紧急的事情微信说，不急的发邮件"
| 项 | 内容 |
|---|---|
| 现标注 | pref=True |
| 建议 | **pref=True + rules=True** |
| 理由 | "微信说/发邮件"主语是 Agent 的动作；是沟通渠道的持久规则 |

### #22 "别给我发那种长报告，一页纸搞定最好"
| 项 | 内容 |
|---|---|
| 现标注 | pref=True |
| 建议 | **pref=True + rules=True** |
| 理由 | "别给我发"直接命令 Agent 的禁止规则，且"一页纸搞定"是持久长度约束 |

### #24 "早上9点前别给我推消息，那时候在开晨会"
| 项 | 内容 |
|---|---|
| 现标注 | pref=True |
| 建议 | **pref=True + rules=True** |
| 理由 | "别给我推"是持久时间窗约束（开晨会这个习惯是偏好侧） |

### #17 "数据嘛，能用图就别用表，一目了然"
| 项 | 内容 |
|---|---|
| 现标注 | pref=True |
| 建议 | **pref=True + rules=True** |
| 理由 | "能用图就别用表"是无主语的输出规则，与 #81 "金额统一用万为单位" 结构等价 |

### #82 "我要求金额用万为单位"
| 项 | 内容 |
|---|---|
| 现标注 | pref=True |
| 建议 | **pref=True + rules=True**（或直接改为 rules=True 独占） |
| 理由 | "我要求 X" 的语义等价于"X 要是 Y 格式"，与 #81 在未来行为上无实质差异；测试集自己在 G 组注释里也承认是「对抗场景」 |

## 第三类：时效性或数值型（可接受但价值低）

### #9 "今年KPI是3000万，去年完成了2800"
- 3000 万这种数字**年度变化**，明年再问就不准
- 但"用户有 KPI，量级在几千万"作为身份信号仍有效
- 可保留 profile=True

### #11 "刚来三个月，还在熟悉业务"
- "三个月" 会过时，但"新员工"状态在短期内有提示价值
- 可保留 profile=True

### #48 "赵敏下个月要去美国出差"
- 时效性强，下个月一过就失效
- 测试集明确把"时效性信息"列为 entities 的一类，可保留 entities=True

## 第四类：我认为标注正确但模型容易搞错

以下用例标注合理，LLM 判错属于能力问题而非标签问题：

- #15 "大客户我一般亲自跟，小客户让团队处理" — 条件性工作习惯 pref ✅
- #95 "我一般不加班" vs #96 "我们部门不加班" — 主语差异决定归属 ✅
- #89 vs #90 — "X 那边要求 Y"（entities）vs "跟 X 沟通要 Y"（rules）✅
