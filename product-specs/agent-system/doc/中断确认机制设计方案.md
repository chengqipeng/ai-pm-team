# 中断确认机制设计方案

> 实现 Agent 执行过程中的"暂停-确认-恢复"能力，支持多轮查询匹配让用户确认。
> 对齐 AG-UI 官方 Interrupts 规范 + apps-agent 的 ask_user 工具。

## 二、技术方案

### 2.1 核心机制：ask_user 工具

不改 LangGraph 框架，通过一个特殊工具 `ask_user` 实现中断：

```python
class AskUserTool(Tool):
    """中断确认工具 — Agent 调用此工具时暂停执行，等待用户响应"""

    name = "ask_user"

    def input_schema(self):
        return {
            "type": "object",
            "properties": {
                "interrupt_type": {
                    "type": "string",
                    "enum": ["confirm", "select", "multi_select", "input"],
                    "description": "中断类型"
                },
                "title": {"type": "string", "description": "标题"},
                "message": {"type": "string", "description": "说明文字"},
                "options": {
                    "type": "array",
                    "items": {
                        "type": "object",
                        "properties": {
                            "id": {"type": "string"},
                            "label": {"type": "string"},
                            "description": {"type": "string"}
                        }
                    },
                    "description": "选项列表（select/multi_select 时必填）"
                },
                "default_value": {"type": "string", "description": "默认值（input 时可选）"},
            },
            "required": ["interrupt_type", "title"]
        }
```

### 2.2 执行流程

```
Agent Loop
    │
    ├─ LLM 决定调用 ask_user(type="select", title="请选择客户", options=[...])
    │
    ├─ ask_user 工具执行：
    │   1. 产出 CUSTOM("interrupt") 事件 → 前端渲染确认 UI
    │   2. 挂起当前协程（asyncio.Event.wait）
    │   3. 等待前端 userAction 回传
    │
    ├─ 前端用户操作：
    │   POST /agent/a2ui/event
    │   { userAction: { name: "interrupt_response", context: { value: "C001" } } }
    │
    ├─ ask_user 收到响应：
    │   1. asyncio.Event.set()
    │   2. 返回用户选择的值作为工具结果
    │
    └─ Agent Loop 继续：
        LLM 看到 ask_user 返回 "C001" → 用 C001 继续后续工具调用
```

### 2.3 AG-UI 事件流

```
event: TOOL_CALL_START     {tool_call_id: "tc1", tool_call_name: "ask_user"}
event: TOOL_CALL_ARGS      {tool_call_id: "tc1", delta: "{\"interrupt_type\":\"select\",...}"}
event: TOOL_CALL_END       {tool_call_id: "tc1"}
event: CUSTOM              {name: "interrupt", value: {
                              interrupt_id: "int_001",
                              type: "select",
                              title: "请选择目标客户",
                              message: "找到以下匹配的客户：",
                              options: [
                                {id: "C001", label: "华为技术有限公司", description: "深圳·IT"},
                                {id: "C002", label: "华为云计算技术", description: "贵阳·云"},
                              ],
                              tool_call_id: "tc1"
                           }}
... [等待用户响应] ...
event: TOOL_CALL_RESULT    {tool_call_id: "tc1", content: "C001"}
... [Agent 继续执行] ...
```

### 2.4 前端组件

收到 `CUSTOM("interrupt")` 事件后，前端根据 `type` 渲染对应组件：

| type | 组件 | 交互 |
|------|------|------|
| confirm | ConfirmDialog | 确认/取消两个按钮 |
| select | SelectionCard | 单选列表 + 确认按钮 |
| multi_select | MultiSelectCard | 多选列表 + 确认按钮 |
| input | InputPrompt | 文本输入框 + 提交按钮 |

用户操作后，前端发送 userAction：
```json
POST /agent/a2ui/event
{
  "threadId": "thread_001",
  "userAction": {
    "name": "interrupt_response",
    "surfaceId": "interrupt_int_001",
    "sourceComponentId": "select_btn",
    "context": {
      "interrupt_id": "int_001",
      "value": "C001",
      "cancelled": false
    }
  }
}
```

## 三、Skill Prompt 中的使用方式

### account-insight 的参数解析改造

```markdown
## 参数解析

用户输入的客户标识为: {account_id}

**处理规则**：
1. 如果输入是 ID 格式（纯数字/含下划线），直接使用
2. 如果输入是名称，执行搜索：
   调用 query_data(action="query", entity_api_key="account",
                   filters={"name__contains": "{account_id}"}, page_size=10)
3. 根据搜索结果：
   - 精确匹配 1 条 → 直接使用该客户 ID
   - 匹配多条 → 调用 ask_user 让用户选择：
     ask_user(
       interrupt_type="select",
       title="请选择目标客户",
       message="找到以下匹配的客户，请选择：",
       options=[{id: 客户ID, label: 客户名称, description: "行业·城市"}]
     )
   - 匹配 0 条 → 调用 ask_user 让用户重新输入：
     ask_user(
       interrupt_type="input",
       title="未找到客户",
       message="未找到名称包含'{account_id}'的客户，请输入正确的客户名称或ID"
     )
4. 使用确认后的客户 ID 继续执行分析
```

### batch_cleanup 的危险操作确认

```markdown
## 安全规则

执行删除前必须确认：
1. 先统计符合条件的记录数
2. 查询前 5 条样本数据
3. 调用 ask_user 确认：
   ask_user(
     interrupt_type="confirm",
     title="确认批量删除",
     message="即将删除 {count} 条记录，示例：\n- {sample1}\n- {sample2}\n\n此操作不可撤销。"
   )
4. 用户确认后才执行删除
5. 用户取消则终止操作
```

## 四、实现步骤

### Phase 1：ask_user 工具（2天）

1. 创建 `src/tools/builtins/ask_user_tool.py`

3. 产出 CUSTOM("interrupt") 事件
4. 注册到 ToolRegistry

## 五、与 AG-UI Interrupts 规范的关系

| 维度 | AG-UI 官方 Interrupts | 本方案（ask_user 工具） |
|------|----------------------|----------------------|
| 实现方式 | RunFinished.outcome.interrupt | 工具调用 + CUSTOM 事件 |
| 暂停机制 | 框架级（run 结束） | 工具级（协程挂起） |
| 恢复方式 | 新 run + resume 参数 | 同一 run 内 userAction 回传 |
| 上下文保持 | 需要 checkpointer | 天然保持（同一协程） |
| 多轮中断 | 每次中断结束 run | 支持（同一 run 内多次 ask_user） |
| 前端复杂度 | 需要管理 run 生命周期 | 简单（监听事件 + 回传） |

**本方案优势**：不需要改 LangGraph 框架，利用工具调用机制实现，且天然支持多轮中断（同一次执行中可以多次调用 ask_user）。
