核心设计原则：
  • Agent 纯运行时：neo-apps-ai-agent-service 仅包含执行引擎内核，不嵌入任何业务代码，业务能力全部由 Skill 注入
  • MCP 独立平级：neo-ai-mcp-service 与 Agent 服务平级，独立管理 MCP Server 生命周期，Agent 通过 HTTP 调用其执行外部工具
  • Skill 驱动业务：所有业务场景通过 Skill 声明式定义并注册到 DB，Agent 运行时动态加载执行
  • 业务域微服务双重职责：部署时注册 Tool 定义到 DB；运行时作为远程 Tool 的 HTTP 回调服务，封装后端系统（CRM/ERP/aPaaS）对接逻辑
  • Tool 三类分治：内置 Tool（Agent 进程内执行）· 远程 Tool（HTTP 回调业务域服务）· MCP Tool（经 mcp-service 执行外部工具）
  • 切面注册机制：Skill、Tool、Middleware、MCP 连接均注册到数据库，注册器逻辑封装为独立 Python 包（neo-ai-registry-sdk），Agent 服务和业务服务共同依赖
  • 异步批量分离：长耗时任务（知识库入库、批量分析、数据迁移、记忆整合）由 neo-ai-batch-service 异步处理，不阻塞 Agent 对话主链路
  • 平台统一代理：所有底层 AI 能力通过 neo-ai-agent-platform-service 统一出口，集中计费/限流/审计

State 传递机制

state: ToolState（可读写）
  • Agent 图 state 的业务字段视图
  • Provider handler 通过 get_state(key) 读取
  • 通过 set_state(key, value) 回写（线程隔离 ContextVar）
  • SDK 路由层自动收集 state_patch 回传 Agent
  • Agent 侧通过 ToolState.write_back() 合并到图 state
configurable: dict（只读）
  • 请求上下文（来自 LangGraph config.configurable）
  • 包含：tenant_id、user_id、thread_id、language_code 等
  • 自动过滤 __ 前缀的 LangGraph 内部字段
  • 自动过滤不可 JSON 序列化的对象
  • Provider 只读访问，不可回写

SDK 包模块结构

neo_ai_registry/ ├── __init__.py # 包入口（导出所有公开 API） ├── models.py # ToolDefinition + MiddlewareDefinition + 枚举 ├── state.py # ToolState + set_state/get_state（ContextVar 线程隔离） ├── config.py # ConfigLoader + RegistryConfig（YAML/dict → 配置对象） ├── validator.py # Schema 校验（注册前验证） ├── agent/ # Agent 运行时侧 │ ├── registry.py # AgentRegistry（注册 + 分派 + 转换入口） │ ├── discover.py # discover_tools() / discover_middlewares() │ ├── tool_adapter.py # create_base_tool()（ToolDefinition → StructuredTool） │ └── middleware_adapter.py # create_remote_middleware()（动态生成 AgentMiddleware） ├── provider/ # Provider 服务侧 │ ├── registry.py # ProviderRegistry（内存注册 + handler 绑定） │ └── fastapi.py # create_provider_app() / create_provider_router() ├── feign/ # 远程调用层 │ ├── transport.py # Transport 抽象 + NeoApiTransport（唯一实现） │ └── client.py # ToolFeignClient + MiddlewareFeignClient └── mcp/ # MCP 封装 ├── models.py # McpToolDefinition + McpServerInfo ├── client.py # McpFeignClient（Agent → MCP Service） └── provider.py # McpProvider（抽象接口）
SDK 核心设计要点：
  • Agent 与 Provider 共用一个 SDK：Agent 侧使用 agent/ 子包（消费方），Provider 侧使用 provider/ 子包（提供方），models.py / state.py / feign/ 共享
  • Transport 唯一实现：NeoApiTransport 统一传输层（Eureka 服务发现 + GlobalContext 自动注入 + SkyWalking trace 传播），不再有开发/生产环境分裂
  • 动态类生成：tool_adapter 将 ToolDefinition → StructuredTool（动态 args_schema + InjectedState），middleware_adapter 将 MiddlewareDefinition → AgentMiddleware 子类（只覆写声明的 hooks 方法）
  • ContextVar 线程隔离：set_state/get_state 基于 Python contextvars，每个请求独立的 state_patch，async 安全
  • 自动发现：discover_tools/discover_middlewares 递归扫描目录，自动实例化 BaseTool / AgentMiddleware 子类

Provider Handler 三种响应模式

业务域 Provider 的 Tool handler 支持三种响应方式，由 handler 的返回形式决定。SDK 路由层自动识别并封装为对应协议，Agent Runtime 侧无差别消费。

① 普通 JSON 响应
handler return dict
路由层封装为 {code:0, data:{result, state_patch, agent_data}}
Agent 侧 ToolMessage = json.dumps(result)
② 流式消息（AsyncGenerator）
handler async yield chunks
FeignClient 收集完整结果 {result:[chunks], state_patch, agent_data}
前端直连时转 SSE（event: chunk/agent_data/state_patch/done）
③ AG-UI 业务卡片
handler 调 emit_card(data_key, data=...)
Agent 侧自动补发 adispatch_custom_event("agent_data", card)
V2AGUIConverter 渲染为前端组件卡片

① 普通 JSON 响应（默认）

# 最简模式：handler 返回 dict，SDK 自动序列化为 JSON 响应 from neo_ai_registry.state import ToolState, set_state async def query_customer(input_data: dict, state: ToolState, configurable: dict) -> dict: keyword = input_data.get("keyword", "") tenant_id = configurable.get("tenant_id") records = await crm_service.search(keyword, tenant_id) # 业务逻辑 set_state("last_query_keyword", keyword) # 回写 Agent 图 state return {"status": "success", "records": records, "total": len(records)} # → Agent ToolMessage = '{"status":"success","records":[...],"total":3}' # → 响应: {code:0, data:{result:{...}, state_patch:{last_query_keyword:"..."}, agent_data:[]}}

② 流式消息（AsyncGenerator）

# handler 返回 AsyncGenerator → SDK 自动转 SSE / 收集结果 # FeignClient 模式：收集所有 chunk 为 list 返回 # 前端直连模式（Accept: text/event-stream）：逐 chunk 推 SSE from neo_ai_registry.state import ToolState, set_state from typing import AsyncGenerator async def stream_analysis(input_data: dict, state: ToolState, configurable: dict) -> AsyncGenerator: query = input_data.get("query", "") # 逐步产出分析结果片段 async for chunk in llm_service.stream_analyze(query): yield {"type": "text_chunk", "content": chunk} # 最终产出结构化摘要 yield {"type": "summary", "data": {"conclusion": "...", "confidence": 0.92}} set_state("analysis_completed", True) # → FeignClient 收到: {result:[{type:"text_chunk",...},{type:"summary",...}], state_patch:{...}, agent_data:[]} # → 前端直连 SSE: # event: chunk data: {"type":"text_chunk","content":"..."} # event: chunk data: {"type":"summary","data":{...}} # event: state_patch data: {"analysis_completed":true} # event: done data: {}

③ AG-UI 业务卡片（emit_card + set_result_text）

# 推送 AG-UI 业务卡片：卡片渲染 + LLM 文本分离 # emit_card → 前端渲染组件卡片（CrmDataCard / 自定义组件） # set_result_text → 控制给 LLM 的文本（避免复述卡片内容） from neo_ai_registry.state import ToolState, set_state, emit_card, set_result_text async def search_crm_record(input_data: dict, state: ToolState, configurable: dict) -> dict: entity = input_data.get("entity", "account") keyword = input_data.get("keyword", "") tenant_id = configurable.get("tenant_id") records = await crm_service.search(entity, keyword, tenant_id) set_state("last_search_entity", entity) set_state("last_search_keyword", keyword) # ① 推卡片：data_key 需与前端 chat_component_registry 注册的组件对齐 emit_card("crm_data", data=records) # 等价于: emit_card("crm_data", payload={"data": records}) # 支持一次推多张: emit_card("doc_data", data=doc_list) # ② 指定给 LLM 的文本（可选）：避免 LLM 用文字复述已展示的卡片内容 set_result_text(f"已为用户展示 {len(records)} 条「{keyword}」相关的 CRM {entity} 记录卡片。") # 不调用 set_result_text 时，LLM 拿到的是 return 值的 JSON 序列化 return {"status": "success", "total": len(records)} # → 响应: {code:0, data:{ # result: {status:"success", total:3}, # state_patch: {last_search_entity:"account", last_search_keyword:"仁科"}, # agent_data: [{data_key:"crm_data", payload:{data:[...]}}], # result_text: "已为用户展示 3 条「仁科」相关的 CRM account 记录卡片。" # }} # # Agent Runtime 侧自动： # 1. adispatch_custom_event("agent_data", {data_key, payload}) → V2AGUIConverter 渲染卡片 # 2. ToolMessage = result_text（而非序列化 result）→ LLM 不复述卡片

POST/v2/tools/{api_key}/execute{input, state, configurable}{code:0, data:{result, state_patch}}执行 Remote Tool（支持 SSE 流式）
POST/v2/middlewares/{api_key}/execute{hook, payload, state, configurable}{code:0, data:{result, state_patch}}执行 Remote Middleware
POST/v2/mcp/tools/call{tool_name, arguments, server_api_key?, context?}{content, records, ...}调用 MCP Tool
GET/v2/mcp/tools—[McpToolDefinition]MCP Tool 列表
GET/v2/mcp/servers—[McpServerInfo]MCP Server 列表

服务发现（Eureka）

NeoApiTransport — 唯一传输层实现
  • 底层：neo-ai-infr-eureka.NeoApiClient（统一封装）
  • 服务发现：Eureka 自动解析 app_name → 实例地址（负载均衡 + 健康检查）
  • 上下文传递：GlobalContext（tenant_id、user_id）自动注入 HTTP Header
  • 链路追踪：SkyWalking trace 自动传播（全链路可观测）
  • 异步支持：async_invoke() 原生异步 + invoke() 同步兼容（内部线程池桥接）
  • 超时控制：timeout_ms 透传到 NeoApiClient.ainvoke

Middleware 动态类生成

动态生成 AgentMiddleware 子类，只覆写 hooks 中声明的方法。LangGraph create_agent 通过 cls.METHOD is not AgentMiddleware.METHOD 检测覆写，只为实际覆写的方法注册图节点 — 不覆写不产生空节点，性能最优。

钩子参数转换链路：AgentState → ToolState.from_agent_state() → 序列化 → FeignClient 远程调用 → response.state_patch → merge_patch() → write_back(AgentState)

返回值约定：{"action":"continue"} 不修改 · {"action":"modify","patch":{...}} 修改 state · {"action":"block","reason":"..."} 拦截（仅 wrap_tool_call）

SSE 流式 Tool

Handler 返回 AsyncGenerator → SDK 自动转 SSE（data: {chunk} 逐条推送 → event: state_patch 回传状态 → event: done 结束）
新业务域接入清单：
  • ① 创建 neo-ai-{domain}-service/，依赖 neo-ai-registry-sdk
  • ② 实现 handler：async def handler(input_data, state, configurable) -> dict
  • ③ create_provider_app(domain, handler_map) 一行创建服务
  • ④ startup 中 EurekaGlobalClient().register_eureka()
  • ⑤ Agent 侧 registry.yaml 声明 tools/middlewares，service 指向 Eureka 注册名
  • ⑥ 验证：Agent 启动自动加载 → FeignClient 远程调用 → state_patch 回写

Agent 元数据配置规范（agent.yaml）

每个 Agent 实例通过一份 agent.yaml 声明式配置实现个性化。运行时根据配置动态组装 System Prompt、Tool 集、Middleware 管道、Skill 绑定和特性开关。

# ═══ Agent 元数据配置完整 Schema ═══ name: query-crm-data # Agent 唯一标识（必填） description: CRM 智能查询 Agent # Agent 功能描述 model: deepseek-v4-flash # 指定 LLM 模型（空则使用全局默认） system_prompt: | # Agent 人设与行为规则（支持多行 Markdown） # 角色 你是 CRM 智能查询助手... # 工作流程 ... tools: # 允许使用的 Tool 列表（白名单） - query_schema - query_data - analyze_data skills: # 绑定的 Skill 列表 - crm-query-simple - data_analysis middleware: # 中间件管道配置 inherit: false # 是否继承全局默认中间件（true/false） names: # 指定加载的中间件列表 - logging - loop_detection - tool_error_handling - memory - crm_query_state config: {} # 中间件参数覆盖（按中间件名分组） features: # 特性开关 memory_enabled: true # 记忆系统 subagent_enabled: false # 子 Agent 委派 guardrail_enabled: true # 安全护栏 mcp_enabled: false # MCP 工具接入 skill_autogen_enabled: false # Skill 自动生成 direct_output: true # 工具结果直出（跳过 LLM 二次加工） max_llm_calls: 15 # 单次会话 LLM 最大调用次数 max_step_llm_calls: 8 # 单步骤 LLM 最大调用次数
字段 类型 默认值 说明
name string 目录名 必填。Agent 唯一标识，用于路由和注册表关联
description string "" Agent 功能描述，用于 Multi-Agent 场景下的 Agent 选择和展示
model string ""（全局默认） 指定 LLM 模型标识。为空时使用 AppConfig 中的 default_model。支持所有通过 platform-service 注册的模型
system_prompt string "" Agent 的角色设定、行为规则、工作流程。支持多行 YAML 字符串（| 语法）
tools list[string] [] 允许此 Agent 使用的 Tool 名称白名单。运行时从注册表加载对应 Tool 实例
skills list[string] [] 绑定的 Skill 列表。Agent 可通过 skills_tool 调用这些 Skill
middleware.inherit bool true true：继承全局默认中间件 + 追加 names 中的；false：仅使用 names 中指定的中间件
middleware.names list[string] [] 中间件名称列表，决定加载顺序。常用：logging / loop_detection / tool_error_handling / memory / summarization
middleware.config dict {} 中间件参数覆盖，按中间件名分组。如 {summarization: {max_tokens: 50000}}
features.* bool 见下方 特性开关集合，控制 Agent 能力维度的启停
max_llm_calls int 20 单次会话 LLM 最大调用次数，防止无限循环。超出后强制输出当前结果
max_step_llm_calls int 10 单步骤 LLM 最大调用次数（子 Agent 场景下更严格）

Features 特性开关

开关 默认 作用
memory_enabled true 启用记忆系统（输入侧检索相关记忆注入、输出侧异步提取记忆更新）
subagent_enabled true 允许通过 fork Skill 委派子 Agent 执行任务，启用 SubagentLimitMiddleware
guardrail_enabled true 启用安全护栏（Tool 白名单校验、敏感操作拦截）
mcp_enabled false 启用 MCP 工具接入，Agent 可通过 neo-ai-mcp-service 调用外部 MCP Server
skill_autogen_enabled false 允许 Agent 运行时自动生成 Skill（实验性功能）
direct_output false 工具返回结果直接输出给用户，跳过 LLM 二次加工（适用于格式化输出场景）

典型配置示例

默认入口 Agent（通用对话）
name: default model: deepseek-v4-flash tools: [] skills: [] middleware: inherit: true features: memory_enabled: true subagent_enabled: true mcp_enabled: false
✅ 继承全局中间件
✅ 开启记忆 + 子Agent
❌ 无指定 Tool（依赖 Skill 内部工具）
CRM 查询 Agent（专业场景）
name: query-crm-data model: "" tools: - extract_entity - generate_xoql - execute_xoql - answer_by_data middleware: inherit: false names: [logging, loop_detection, tool_error_handling, memory] features: subagent_enabled: false direct_output: true
❌ 不继承全局中间件（自定义管道）
❌ 禁用子Agent（自身是终端执行者）
✅ direct_output（结果直出前端）
配置与架构的对应关系：
  • agent.yaml 对应架构图中「多 Agent 元数据配置」区块 — 每个 Agent 实例一份配置
  • tools 列表 → 加载注册器从 t_tool 表读取对应 Tool 定义并实例化
  • skills 列表 → 加载注册器从 t_skill 表读取对应 Skill 定义
  • middleware.names → 加载注册器从 t_middleware 表读取并按序组装管道
  • features.mcp_enabled → 控制是否通过 MCP Connector 连接 neo-ai-mcp-service
  • 未来演进：agent.yaml 本身也将迁入注册表（t_agent_profile），实现全配置数据库驱动
