# 三项目场景测试用例清单 — 深度分析

> 基于 `neo-apps-ai-agent-service`、`neo-apps-salescloud-ai-service`、`promptfoo-test` 三个项目的代码逻辑深度分析
> 
> 生成日期：2026-07-06

---

## 一、三个项目的关系定位

```
用户 (CRM 销售人员)
       │
       ▼
┌─ neo-apps-ai-agent-service ─────────────────────────────────┐
│  Agent 运行时引擎：意图识别 → Skill 路由 → 工具调用 → 响应     │
│  (V2: React Agent + 17个中间件 + Skill系统 + 5维记忆)         │
└────────────┬────────────────────────────────────┬────────────┘
             │ 调用业务工具/Action                  │ 被测试
             ▼                                     ▼
┌─ neo-apps-salescloud-ai-service ─┐  ┌─ promptfoo-test ──────────────┐
│  业务领域服务：30+ AI 工具         │  │  自动化评测：SSE/AGUI Provider │
│  (按 APIKEY 工厂路由)              │  │  300+ JSON 用例 + 多断言机制    │
│  20 个 UI 组件                    │  │  多轮对话 + 仿真 + 性能        │
└──────────────────────────────────┘  └───────────────────────────────┘
```

### 项目职责

| 项目 | 核心职责 | 技术栈 |
|------|---------|--------|
| neo-apps-ai-agent-service | Agent 运行时引擎，多层 Agent 编排，会话管理，记忆系统，AG-UI 协议适配 | Python 3.11, FastAPI, LangGraph, LangChain, Redis, MCP |
| neo-apps-salescloud-ai-service | 销售云 AI 业务工具集，30+ 工具 + 20 UI 组件，按 APIKEY 工厂模式路由 | Python 3.11, FastAPI, SQLAlchemy, LLM多模型 |
| promptfoo-test | AI Agent 质量评测平台，覆盖对话能力、Action 执行、记忆、推理等维度 | Node.js, promptfoo, Playwright |

## 二、测试用例梳理维度

从四个测试维度进行完整梳理：

| 维度 | 含义 | 验证目标 |
|------|------|---------|
| A. Skill 功能验证 | 每个 Skill/工具的独立功能 | 工具逻辑正确性 |
| B. Agent 平台能力验证 | 意图识别、路由、记忆、自愈等 | 平台基础设施 |
| C. 端到端仿真验证 | 真实多轮对话全链路 | 用户体验完整性 |
| D. 非功能验证 | 性能、安全、国际化、并发 | 系统质量属性 |

### A2. 智能数据录入（extract-data）

**执行模式：** fork → extract-data Agent
**流水线：** 10步（意图识别→实体匹配→字段提取→校验→确认→写入）

| 子场景 | 用例目录 | 测试要点 |
|--------|---------|---------|
| 创建客户 | create_account | 基本信息提取、必填字段校验、重复检测、确认创建 |
| 创建联系人 | create_contact | 关联客户识别、多字段提取、姓名解析 |
| 创建日程 | create_schedule | 时间解析（明天/后天/下周一）、关联业务、提醒设置 |
| 创建活动记录 | create_activity_record | 沟通方式识别、内容摘要提取、关联客户 |
| 创建自定义实体 | create_custom_entity | 实体名称识别→复用流水线、动态字段 |
| 创建工作报告 | create_work_report | 报告类型选择、时间范围、基础数据加载 |
| 批量拜访计划 | (内含于 salescloud) | JSON数组批量提取、每条独立走流水线 |

**多轮对话关键验证：**
1. 第1轮：用户表达意图 → 系统生成预览
2. 第2轮：用户确认/修改 → 系统执行创建
3. 第3轮：用户追加修改 → 系统调用数据更新
4. 第N轮：重复确认 → 系统识别无需重复操作

| 数据来源 | 人工设计 | 线上真实对话 |
| 会话模式 | 单轮或少量多轮 | 多轮（最多 10+ 轮）|
| 断言类型 | contains + dynamic | contains + llm-rubric |

**仿真用例示例（S0001 — 创建日程+更新日期）：**

```

  → 验证: 识别无需重复修改，不再调用 skill
```

## 七、测试断言机制汇总

| 断言类型 | 语法 | 用途 |
|---------|------|------|
| `contains` | `{"type":"contains","value":["关键词1","关键词2"]}` | 响应必须包含所有关键词 |
| `contains-any` | `{"type":"contains-any","value":["词A","词B"]}` | 响应包含列表中任一 |
| `not-contains` | `{"type":"not-contains","value":["不应出现"]}` | 响应不得包含 |
| `llm-rubric` | `{"type":"llm-rubric","value":"评判标准","threshold":0.8}` | LLM 语义评判 |
| `javascript` | `{"type":"javascript","value":"file://path.js"}` | 自定义 JS 断言 |
| `event_exists` | `{"type":"event_exists","value":"ACTIVITY_SNAPSHOT"}` | SSE 事件存在 |
| `event_not_exists` | `{"type":"event_not_exists","value":"TOOL_CALL_START"}` | SSE 事件不存在 |
| `response_length_gt` | `{"type":"response_length_gt","value":100}` | 响应长度阈值 |
| `no_error` | `{"type":"no_error"}` | 无报错/无崩溃 |
| `dynamic` + `xoql` | 含 `"dynamic":true,"xoql":"..."` | 动态查 CRM 验证 |
