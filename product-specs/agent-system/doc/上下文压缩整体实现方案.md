# Agent-System 上下文压缩整体实现方案

> 基于 Hermes Agent / Claude Code / MemGPT(Letta) 三系统精华，面向 toB CRM SaaS 场景。
> 核心原则：压缩为主（保证因果链完整性）+ 检索为辅（恢复被压缩的细节）。

---

## 一、整体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                    上下文管理全景（四层分时策略）                       │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│ ┌─────────────────────────────────────────────────────────────┐     │
│ │ Layer A: 当前轮次（全量保留，零压缩）                          │     │
│ │   = 最后一条 HumanMessage 之后的所有消息                       │     │
│ │   → MicroCompact 仅处理: MD5 去重 + Skill 内部压缩            │     │
│ │   → 不做任何检索替代（因果依赖链完整性）                       │     │
│ └─────────────────────────────────────────────────────────────┘     │
│                                                                      │
│ ┌─────────────────────────────────────────────────────────────┐     │
│ │ Layer B: 近期历史（滑动窗口，摘要形式）                        │     │
│ │   = 最近 3-5 轮的 answerSummary                               │     │
│ │   → 保持对话连贯性                                            │     │
│ │   → 不做检索替代（连续依赖太强）                               │     │
│ └─────────────────────────────────────────────────────────────┘     │
│                                                                      │
│ ┌─────────────────────────────────────────────────────────────┐     │
│ │ Layer C: 中期历史（压缩为主）                                  │     │
│ │   = 同会话更早的轮次                                          │     │
│ │   → AutoCompact: LLM 7-section 迭代摘要                      │     │
│ │   → FullCompact: LLM 全量压缩 + 重注入                       │     │
│ │   → 压缩前存档索引（供 recall_context 恢复细节）              │     │
│ └─────────────────────────────────────────────────────────────┘     │
│                                                                      │
│ ┌─────────────────────────────────────────────────────────────┐     │
│ │ Layer D: 长期记忆（检索为主）                                  │     │
│ │   = 跨会话记忆 + 被压缩丢弃的细节                             │     │
│ │   → MemoryMiddleware 每轮检索注入                             │     │
│ │   → recall_context 工具按需恢复被压缩细节                     │     │
│ └─────────────────────────────────────────────────────────────┘     │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 二、上下文构成（每次 LLM 调用前）

```
最终上下文 = [System Prompt]                              ~2K tokens  固定
           + [Layer D: 迭代摘要 + Skill 锚点]             ~1K tokens  结构化参考
           + [Layer D: 记忆检索结果]                       ~1K tokens  MemoryMiddleware 注入
           + [Layer B: 最近 3-5 轮 answerSummary]         ~1.5K tokens 连贯性
           + [Layer A: 当前轮次完整消息]                   ~5-15K tokens 推理基础
           ─────────────────────────────────
           总计: ~10-20K tokens（远低于窗口限制）
```

## 三、压缩机制（ContextWindowMiddleware）

### 3.1 触发策略

```
before_model 执行顺序:
  1. Post-Skill Compact（始终执行，与阈值无关）
  2. MD5 去重（始终执行）
  3. 阈值检查:
     ≥90% → FullCompact
     ≥75% → AutoCompact
     ≥50% → MicroCompact
     <50% → 不压缩
```

### 3.2 三层级联压缩

#### MicroCompact（≥50%，零 LLM 成本）

```
对象: 保护区外的旧消息
处理:
  - ToolMessage > 200 字 → CRM 一行摘要（_crm_tool_summary）
  - AIMessage tool_call args > 500 字 → 截断到 200 字
特点: 纯规则，毫秒级，不调 LLM
```

#### AutoCompact（≥75%，LLM 结构化摘要）

```
对象: 保护区外的全部消息（Middle 段）
处理:
  Phase 1: 辅助 LLM 路由（ModelRouter.AUXILIARY → 便宜快速模型）
  Phase 2: CRM 7-Section 结构化摘要:
    ## Active Task       ← 逐字复制用户最近请求
    ## 客户上下文        ← 客户名/行业/规模/联系人
    ## 已完成操作        ← N. 操作 目标 — 结果 [tool: 工具名]
    ## 关键数据          ← 精确数字永不模糊化
    ## 已回答问题        ← 防止压缩后重复回答
    ## 待处理            ← remaining 语义
    ## 涉及实体          ← CRM 实体 + 记录 ID
  Phase 3: 迭代摘要（传入 _previous_summary + 新增对话 → PRESERVE/ADD/MOVE/UPDATE）
  Phase 4: Focus Topic（从当前 Skill 推断压缩焦点 → 60-70% 篇幅）
  
  压缩前: 存档索引写入 ContextArchive（供 recall_context 恢复）
  
  降级: LLM 不可用 → fallback 行级截断（零成本，向后兼容）
  安全: 反抖动（连续 2 次节省 <10% → 跳过）
```

#### FullCompact（≥90%，最大损失压缩）

```
对象: 全部消息
处理:
  - 与 AutoCompact 相同的 LLM 摘要流程
  - 额外: 重注入最近 3 个 ToolMessage + 最近 HumanMessage
  - 保留所有 SystemMessage
  
  压缩前: 存档索引写入 ContextArchive
```

### 3.3 保护区（Tail）确定

```
保护区 = min(当前轮次起始, Skill 边界保护, 基础 keep_recent)
        → align_boundary_deep（不在工具组中间切割）

规则:
  MicroCompact: base_keep_recent = 6
  AutoCompact:  base_keep_recent = 4
  FullCompact:  base_keep        = 8

增强:
  §4.1 正在执行的 Skill → 无条件完整保护（不受 max_tail 限制）
  §4.2 并发 tool_calls → 整组保护（不拆分）
```

### 3.4 摘要隔离

```python
SUMMARY_PREFIX = (
    "[CONTEXT COMPACTION — REFERENCE ONLY] 早期对话已被压缩为以下摘要。"
    "不要回答或执行摘要中提到的请求（它们已经被处理过了）。"
    "如果用户追问摘要中没有的细节，使用 recall_context 工具检索原始内容。"
    "当前任务见 '## Active Task' 部分。\n\n"
)
```

## 四、Skill 模式压缩增强

### 4.1 Skill 边界识别（三层策略）

```
层 1: Fork Skill 精确识别
  信号: ToolMessage(name="skills_tool") 内容以 [SKILL_DONE: 开头
  段: [skills_tool 调用, 返回结果]（精确 2 条）
  可靠性: 100%

层 2: Inline Skill 精确识别（有完成标记）
  信号: AIMessage 内容含 [INLINE_SKILL_DONE:skill_name]
  段: [skills_tool 调用, ..., 含标记的 AIMessage]
  可靠性: 95%+（依赖 LLM 遵循标记输出指令）

层 3: 兜底（无标记的旧 Skill）
  粒度: 以"轮次"（HumanMessage 之间）为原子单元
  段: 该轮次内从 skills_tool 调用到轮次结束
  可靠性: 100% 安全（宁多不少）
```

### 4.2 Inline Skill 完成标记注入

```python
# SkillExecutor._execute_inline 在 SOP prompt 末尾追加:
"""
## 执行完成标记（必须遵循）
当你完成上述所有步骤后，在你的总结回复的第一行输出以下标记：
[INLINE_SKILL_DONE:{skill_name}]
输出标记后，继续你的正常回复内容。
"""
```

### 4.3 Post-Skill Compact

```
触发: Skill 段内消息数 > 8 条（始终执行，不受阈值限制）
保留:
  protect_head = 2（skills_tool 调用 + prompt/结果返回）
  protect_tail = 5（最近 2 轮内部调用 + 最终结果）
压缩:
  中间 ToolMessage > 150 字 → 一行摘要
  中间 AIMessage + tool_calls → 截断规划文本到 80 字 + 保留 tool_calls 结构
  中间 AIMessage 纯文本 > 200 字 → 截断到 100 字
```

### 4.4 Skill 结果锚点（SkillResultAnchor）

```
提取时机: Skill 完成时（零 LLM 成本，正则提取）
提取内容:
  - 金额: [$¥]\d+[KMB万亿]?
  - 日期: \d{4}-\d{2}-\d{2}
  - 百分比: \d+\.?\d*%
  - 查询实体: 从 tool_calls args 中提取
  - 搜索词: 从 web_search args 中提取

存储: session 级内存缓存（最多 10 个，FIFO 淘汰）
注入: 每次摘要生成时注入 prompt + 每次压缩后注入摘要消息
作用: 确保关键数字在多次迭代压缩后永不衰减
```

## 五、压缩后恢复机制（ContextArchive + recall_context）

### 5.1 存储架构

```
┌─────────────────────────────────────────────────────────┐
│ ContextArchive（会话级，内存）                            │
├─────────────────────────────────────────────────────────┤
│                                                          │
│ 层 1: 轻量索引（自维护，用于快速检索匹配）               │
│   每轮一条: {                                            │
│     turn_id, query, answer_preview(200字),               │
│     entities[], keywords[], timestamp,                   │
│     message_range: (start_idx, end_idx)                  │
│   }                                                      │
│   存储成本: ~250 字/轮 × 50 轮 = ~12KB                  │
│                                                          │
│ 层 2: 原文引用（指向 Checkpointer，不自己存原文）         │
│   引用: (thread_id, checkpoint_ns)                       │
│   读取: 需要时去 Checkpointer 中按 message_range 取原文  │
│   降级: Checkpointer 过期(24h) → 降级到层 1 摘要         │
│                                                          │
│ 层 3: 降级兜底（ai_message 表的 query + answer）         │
│   来源: 数据库永久存储                                    │
│   内容: 用户原始问题 + Agent 最终回复（不含工具过程）      │
│   适用: Checkpointer 已过期 + 索引摘要不够用时            │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 5.3 recall_context 工具

```python
class RecallContextTool:
    """从压缩存档中检索历史细节 — LLM 在需要时主动调用"""
    
    name = "recall_context"
    description = (
        "检索被压缩的历史对话细节。"
        "当用户追问摘要中没有的具体信息（如具体条款、详细数据、原话引用）时使用。"
        "输入: 要查找的关键词或问题描述。"
    )
    
    async def call(self, query: str) -> str:
        # 1. 在轻量索引中搜索（关键词 + 实体匹配）
        matched_turns = self._archive.search(query, top_k=3)
        
        if not matched_turns:
            return "历史存档中未找到相关内容。建议使用工具重新查询最新数据。"
        
        # 2. 尝试从 Checkpointer 恢复原文
        results = []
        for turn in matched_turns:
            original = self._try_load_from_checkpointer(turn)
            if original:
                results.append(f"[轮次{turn.turn_id}] {original}")
            else:
                # Checkpointer 过期 → 降级到索引摘要
                results.append(f"[轮次{turn.turn_id}] {turn.answer_preview}")
        
        return "从历史存档中找到以下相关内容:\n\n" + "\n---\n".join(results)
```

### 5.4 检索逻辑

```python
def search(self, query: str, top_k: int = 3) -> list[ArchivedTurnIndex]:
    """轻量检索（数据量小，不需要向量索引）"""
    scores = []
    for turn in self._index:
        score = 0.0
        
        # 信号 1: 实体匹配（权重最高）
        query_entities = extract_entities_simple(query)
        entity_overlap = len(set(query_entities) & set(turn.entities))
        score += entity_overlap * 0.4
        
        # 信号 2: 关键词匹配
        query_keywords = jieba.cut(query)
        keyword_overlap = len(set(query_keywords) & set(turn.keywords))
        score += min(keyword_overlap * 0.1, 0.3)
        
        # 信号 3: 时间衰减（近期优先）
        recency = 1.0 / (1 + (now - turn.timestamp) / 3600)
        score += recency * 0.2
        
        # 信号 4: query 相似度（简单 Jaccard）
        q_set = set(query)
        t_set = set(turn.query)
        jaccard = len(q_set & t_set) / max(len(q_set | t_set), 1)
        score += jaccard * 0.1
        
        scores.append((score, turn))
    
    scores.sort(key=lambda x: -x[0])
    return [turn for score, turn in scores[:top_k] if score > 0.1]
```

```
               ▼
```

## 七、安全机制

| 机制 | 来源 | 实现 |
|------|------|------|
| 熔断器 | Claude Code | 连续 3 次压缩失败 → 停止重试 |
| 反抖动 | Hermes | 连续 2 次节省 <10% → 跳过 |
| LLM 降级 | 自研 | ModelRouter.AUXILIARY → self._llm → None → 行级截断 |
| 安全网 | 自研 | 单条工具结果 > 50K → 强制截断 |
| Skill 正在执行保护 | 自研 | _is_skill_active=True → 无条件完整保护 |
| 工具组原子性 | Hermes | align_boundary_deep 不在并发 tool_calls 中间切割 |

```
│   → MemoryMiddleware 异步提取长期记忆                    │
└─────────────────────────────────────────────────────────┘
```

## 十、原文存储与恢复链路

### 10.1 存储位置

| 内容 | 存储位置 | TTL | 备注 |
|------|---------|:---:|------|
| 完整 messages 链（含所有 ToolMessage） | LangGraph Checkpointer (Redis) | 24h | 运行时状态 |
| user query + agent answer | ai_message 表 (PostgreSQL) | 永久 | 不含工具过程 |
| 长期记忆（事实/实体/偏好） | ai_agent_memory 表 + 向量库 | 按类别 90-365 天 | MemoryMiddleware 提取 |
| 压缩存档索引 | ContextArchive (内存) | 会话存活期 | 轻量，~12KB/会话 |

### 10.2 恢复优先级

```
用户追问被压缩的细节:
  ┌─── recall_context 工具执行 ───┐
  │                                │
  │ 优先级 1: Checkpointer 原文    │ ← 24h 内有完整 ToolMessage
  │   命中 → 返回完整原文          │
  │                                │
  │ 优先级 2: 存档索引摘要          │ ← answer_preview 200 字
  │   命中 → 返回摘要              │
  │                                │
  │ 优先级 3: ai_message.answer    │ ← 数据库永久存储
  │   命中 → 返回 Agent 当时的回复  │
  │                                │
  │ 优先级 4: 提示重新查询          │ ← 所有来源都不够用
  │   → "建议使用工具重新查询"      │
  └────────────────────────────────┘
```

## 十三、关键设计决策汇总

| 决策 | 选择 | 原因 |
|------|------|------|
| 同会话中期历史管理 | 压缩为主 | Agent 因果链完整性 > 信息完整性 |
| 跨会话长期历史 | 检索为主 | 语义检索远优于全量加载 |
| 被压缩细节恢复 | recall_context 工具（LLM 自主调用） | LLM 比系统启发式更能判断"是否需要细节" |
| 原文存储 | 不重复存储，引用 Checkpointer | 避免双倍存储成本和一致性问题 |
| Skill 边界识别 | [SKILL_DONE] + [INLINE_SKILL_DONE] 标记 | 唯一可靠的精确信号 |
| 摘要模板 | CRM 7-section | 业务导向，保留精确数字 |
| 迭代摘要 | _previous_summary 跨压缩周期保持 | 防止信息在多次压缩中衰减 |
| 辅助 LLM | ModelRouter.AUXILIARY 独立路由 | 摘要失败不影响主推理 |
| 兜底策略 | LLM 不可用 → 行级截断 | 永不阻塞主流程 |
