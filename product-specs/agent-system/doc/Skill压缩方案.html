Agent-System Skill 压缩方案

Post-Skill Compact + LLMLingua-2 段级语义压缩 · 版本 2.0 · 2026-06

一、终止标记保障（源头层）

所有压缩逻辑依赖 Skill 段有明确终止标记。系统通过三层机制保证每种退出路径都产生标记：

机制覆盖场景行为
skills_tool._arun try/except异常退出（超时/代码错误）捕获异常 → 返回 [SKILL_DONE:error] skill_name 执行失败
server.py pending interrupt 自动关闭用户跳过确认直接发新消息invoke 前 get_state 检测 → 自动 resume({cancelled:true}) → ask_user 返回"用户取消" → Skill 正常结束 → 加标记
Inline prompt 标记注入LLM 按 SOP 执行完毕SOP 末尾要求输出 [INLINE_SKILL_DONE:skill_name]

二、边界识别（find_completed_skill_boundaries）

层级信号段范围可靠性
层1ToolMessage(name=skills_tool) 以 [SKILL_DONE: 开头skills_tool 调用 AIMessage → 该 ToolMessage100%
层2AIMessage 含 [INLINE_SKILL_DONE:xxx]skills_tool 调用 → 含标记的 AIMessage95%+
层3无标记（兜底）：按轮次划分轮次内首个 skills_tool 调用 → 轮次结束100% 安全

三、活跃状态判定（_is_skill_active）

被 SkillAwareTailProtection 调用，决定是否无条件保护 Skill 段。用 tool_call_id 精确配对，并行安全。

遇到的消息处理
TM(name=skills_tool) 含 [SKILL_DONE:]return False（已完成）
AIMessage 含 [INLINE_SKILL_DONE:]return False（已完成）
AIMessage.tool_calls 含 ask_user将该调用 id 加入 pending_ask_user_ids 集合
ToolMessage 且 tool_call_id 在 pending 集合中从集合移除（已响应）
HumanMessage + pending 集合非空return False（interrupt 被跳过，已放弃）
扫描完无触发return True（仍在执行）

四、Post-Skill Compact 主流程

触发条件（任一满足）

  • Skill 内部消息数 > 8
  • Skill 内部估算 token > 4000

保护区划定

位置条数内容
头部保护2skills_tool 调用 AIMessage + 启动确认 ToolMessage
尾部保护5最后 2 轮内部工具调用 + Skill 最终结果
中间区域可变进入压缩流程

中间区域压缩：双路径策略

路径 A：LLMLingua-2 段级压缩（优先）

前置条件：LLMLINGUA_ENABLED=1

Phase 1 分流：

  • JSON ToolMessage → 结构化组（CRM 规则）
  • 纯文本 TM/AIMessage → 文本组（LLMLingua-2）

Phase 2 压缩：

  • 拼接文本组，§§§ 分隔，带角色标签
  • rate = 文本预算 ÷ 总字符，钳位 [0.25, 0.7]
  • 密度检测 → 动态调整 rate
  • 小数点保护 + force_reserve_digit
  • 兜底回补丢失数值（≤5项）

Phase 3 重建：按 §§§ 拆回各条

降级 Gate：文本<500字 / 模型不可用 / 密度>4.0 / ratio≥0.9

路径 B：逐条规则压缩（降级）

路径 A 返回 None 时执行

类型处理
TM > 150字引擎 AGGRESSIVE：Headroom → LLMLingua-2 → CRM 规则 → 截断
AI+tool_calls截断 content 到 80 字，保留 tool_calls
AI 纯文本 >200字截断到 100 字
其他原样保留

CRM 规则分流：

  • JSON records → 记录数+名称+金额+阶段
  • JSON fields → 实体名+字段数+前6字段
  • JSON 单条 → name/amount/stage
  • 纯文本 → 前80字+金额/百分比/日期

密度检测细节

匹配模式示例
带单位数值500ms, 4.2GB, 99.5%, 128req/s
时间 HH:MM14:30, 09:05
IP 地址192.168.1.1
key=value 赋值max_connections=100

density = 命中次数 ÷ (字符数÷100)。>4.0 放弃 / >2.5 rate≥0.7 / >1.5 rate≥0.55 / ≤1.5 标准

五、就地压缩模式

触发：头尾重叠（总条数 < 7）但 token > 4000。不删条目，逐条压缩 content。

条目条件处理
首尾两条—完整保留
中间 TM>500字 + JSONCRM 规则摘要
中间 TM≥1000字 + 纯文本 + LLMLingua启用引擎 AGGRESSIVE 语义压缩
中间 AI有 tool_calls + >150字截断到 150 字
中间 AI纯文本 ≥800字 + LLMLingua启用引擎 AGGRESSIVE 语义压缩
中间 AI纯文本 >300字截断到 150 字

六、Skill 结果锚点（SkillResultAnchor）

提取内容模式作用

七、尾部保护（后续 MicroCompact/AutoCompact 时）

  • Token 预算：从末尾向前累积（soft_ceiling = 1.5× 预算），中英混合 2字符/token
  • Skill 边界对齐：active → 无条件保护；已完成/已放弃 → 推进到 Skill 起始
  • 工具组原子性：切割点在并发 ToolMessage 组内 → 回退到父 AIMessage

八、端到端数据流

Skill 执行 (25条, ~12000 token) │ ├─ 终止标记产生 ─── skills_tool try/except / server 自动关闭 interrupt / Inline prompt │ ├─ 边界识别 ─────── 层1 精确匹配 [SKILL_DONE:] → (start, end) │ ├─ 保护区 ──────── head=2, tail=5, 中间 18 条进入压缩 │ ├─ 压缩执行 ────── LLMLingua-2 段级（文本） + CRM 规则（JSON） │ 降级: 逐条规则 + 截断 │ ├─ 锚点提取 ────── 金额/日期/百分比/实体 → session 缓存 │ └─ 结果: 25条 → ~8条, 12000 → ~3000 token (75% 节省)

九、边界准确性五层保障

层级位置机制覆盖场景
L1server.pypending interrupt 自动 resume(cancel)用户跳过确认
L2skills_tooltry/except → [SKILL_DONE:error]异常退出
L3ask_usercancel → "用户取消了操作" → Skill 正常结束用户/系统取消
L4_is_skill_activepending_ask_user_ids + HumanMessage 检测兜底：标记缺失不误保护
L5层3 兜底按轮次粒度划分最终保底

正常情况 L1-L3 保证标记产生 → 层1精确识别 → 边界 100% 准确。L4-L5 是纵深防御。

十、Skill 开始与 Done 的闭环识别

压缩层通过"开始信号 + 终止信号"配对识别完整的 Skill 执行段，形成闭环。

开始信号识别

模式开始信号消息结构
ForkAIMessage.tool_calls 含 name="skills_tool"AI(tool_calls=[{name:"skills_tool", id:"tc1", args:{skill_name:"xxx"}}])
Inline同上（通过 ToolMessage 返回内容区分模式）同上，但对应的 TM 内容是 SOP prompt 文本而非 [SKILL_DONE:]

两种模式的开始信号完全一样：LLM 调用 skills_tool。区分在于对应 ToolMessage 的内容。

终止信号识别

模式终止信号消息结构产生方
Fork 正常[SKILL_DONE:silent/summarize/passthrough/continue]TM(name=skills_tool, content="[SKILL_DONE:xxx] ...")skills_tool._arun
Fork 异常[SKILL_DONE:error]TM(name=skills_tool, content="[SKILL_DONE:error] 执行失败...")skills_tool._arun try/except
Inline 正常[INLINE_SKILL_DONE:skill_name]AI(content="[INLINE_SKILL_DONE:xxx] 结果...")LLM 遵循 prompt
Inline 无标记下一个 HumanMessage 或下一个 skills_tool 调用隐式终止（层3 兜底）轮次边界

闭环配对逻辑

开始信号扫描： 遍历 messages → 找到 AI(tool_calls 含 skills_tool) → 记录 start_idx 终止信号匹配（从 start_idx+1 向后扫描）： ├─ 遇到 TM(name=skills_tool) 且 content 以 [SKILL_DONE: 开头 │ → 闭环成功: segment = (start_idx, 该TM的idx) [Fork 精确] │ ├─ 遇到 AI 含 [INLINE_SKILL_DONE:] │ → 闭环成功: segment = (start_idx, 该AI的idx) [Inline 精确] │ ├─ 遇到下一个 skills_tool 调用 或 HumanMessage（无终止标记） │ → 隐式闭环: segment = (start_idx, 前一条的idx) [层3 兜底] │ └─ 扫描到末尾无任何终止信号 → 不闭环: Skill 仍在执行中 [保护，不压缩]

Fork 模式完整生命周期

idx N : AI(tool_calls=[{name:"skills_tool", args:{skill_name:"竞品分析"}}]) ← 开始 idx N+1: TM(name=skills_tool, content="[SKILL_DONE:summarize] 竞品分析 已将...") ← 终止 │ └─ 闭环段: (N, N+1) — Fork 模式段通常只有 2 条（子 Agent 内部执行不可见）

Inline 模式完整生命周期

idx N : AI(tool_calls=[{name:"skills_tool", args:{skill_name:"客户洞察"}}]) ← 开始 idx N+1: TM(name=skills_tool, content="## 客户洞察 SOP\n步骤1...") ← prompt返回 idx N+2: AI(tool_calls=[{name:"query_data", args:{...}}]) ← Skill 内部执行 idx N+3: TM(name=query_data, content="{records:[...]}") idx N+4: AI(tool_calls=[{name:"web_search", args:{...}}]) idx N+5: TM(name=web_search, content="搜索结果...") idx N+6: AI(tool_calls=[{name:"ask_user", args:{interrupt_type:"confirm"}}]) ← 确认中断 idx N+7: TM(name=ask_user, tool_call_id=tc6, content="confirm") ← 用户确认 idx N+8: AI(tool_calls=[{name:"modify_data", args:{...}}]) idx N+9: TM(name=modify_data, content="已更新") idx N+10: AI(content="[INLINE_SKILL_DONE:客户洞察] 洞察完成，已更新客户...") ← 终止 │ └─ 闭环段: (N, N+10) — Inline 模式段包含所有内部工具调用

异常场景的闭环保障

场景消息结构闭环方式
Fork 执行超时AI([skills_tool]) → TM("[SKILL_DONE:error] 超时")try/except 产生标记 → 层1精确闭环
用户跳过 interruptAI([skills_tool]) → TM(prompt) → ... → AI([ask_user]) → HumanMessageserver 自动 resume → Skill 结束产生标记 → 层1精确闭环
自动 resume 失败（极端）同上但无 [SKILL_DONE:]_is_skill_active 检测 pending + HumanMessage → 视为放弃 → 层3 按轮次兜底闭环
Inline LLM 忘输标记AI([skills_tool]) → TM(prompt) → ... → AI(无标记回复) → HumanMessage层3 按轮次兜底: 段 = 轮次内 skills_tool 调用 → 轮次结束

闭环准确率统计（预估）

闭环方式覆盖率边界准确率依赖
层1 精确（Fork + 标记保障）~85%100%[SKILL_DONE:] 标记
层2 精确（Inline + LLM 输出标记）~10%95%+LLM 遵循 prompt
层3 兜底（轮次粒度）~5%100% 安全（宁多不少）HumanMessage 边界

通过源头层保障（server 自动关闭 interrupt + skills_tool try/except），绝大部分场景都落入层1 精确闭环，整体边界准确率 > 99%。
