# 智能审批流产品手册

## 第一章 产品概述

智能审批流是一款面向企业的自动化审批管理系统。它支持多级审批、条件分支、并行审批等复杂场景，帮助企业实现审批流程的数字化转型。

本产品适用于制造业、金融服务、互联网等多个行业，覆盖从采购审批到合同签署的全流程。

### 1.1 核心功能

- 可视化流程设计器：拖拽式配置审批节点
- 智能路由引擎：根据条件自动选择审批路径
- 移动端审批：支持 APP/企业微信/钉钉
- 审批数据分析：实时统计审批效率和瓶颈

### 1.2 技术架构

系统采用微服务架构，核心组件包括：

| 组件 | 技术栈 | 说明 |
|---|---|---|
| 流程引擎 | Camunda BPMN | 支持 BPMN 2.0 标准 |
| 规则引擎 | Drools | 条件分支判断 |
| 消息队列 | RabbitMQ | 异步通知 |
| 数据库 | PostgreSQL | 流程实例存储 |
| 缓存 | Redis | 高频查询加速 |

## 第二章 快速上手

### 2.1 环境准备

部署前请确认以下环境要求：

1. JDK 17 或以上
2. PostgreSQL 14+
3. Redis 6+
4. Docker 20.10+（容器化部署）

### 2.2 安装配置

```bash
# 拉取镜像
docker pull registry.example.com/approval-flow:latest

# 启动服务
docker-compose up -d
```

首次启动后访问 `http://localhost:8080` 进入管理后台。默认管理员账号：admin / admin123。

### 2.3 创建第一个审批流

1. 进入「流程管理」→「新建流程」
2. 拖入「开始节点」→「审批节点」→「结束节点」
3. 配置审批人规则（如：部门主管）
4. 点击「发布」使流程生效

## 第三章 高级功能

### 3.1 条件分支配置

条件分支允许根据表单字段值自动选择不同的审批路径。例如：

- 金额 < 5000：部门主管审批
- 5000 ≤ 金额 < 50000：部门总监审批
- 金额 ≥ 50000：VP + CFO 联合审批

配置方式：在分支网关节点上设置条件表达式 `${amount < 5000}`。

### 3.2 并行审批

并行审批适用于需要多个部门同时审核的场景。所有并行分支全部通过后，流程才继续。

典型场景：合同审批需要法务部 + 财务部同时审核。

### 3.3 审批委托与代理

当审批人请假或出差时，可设置委托规则：

- 临时委托：指定时间段内转交给指定人
- 永久代理：该审批人的所有待办自动转交
- 规则委托：满足条件时自动转交（如超时 24 小时未处理）

### 3.4 与外部系统集成

支持通过 Webhook 和 REST API 与 ERP、CRM、OA 等系统对接：

```json
{
  "event": "approval.completed",
  "processId": "proc_001",
  "result": "approved",
  "approver": "张三",
  "timestamp": "2024-03-15T10:30:00Z"
}
```

## 第四章 运维指南

### 4.1 监控告警

系统内置 Prometheus 指标采集，推荐配合 Grafana 使用：

- `approval_pending_count`：待审批数量
- `approval_avg_duration_seconds`：平均审批耗时
- `approval_timeout_count`：超时审批数

### 4.2 数据备份

建议每日凌晨执行全量备份：

```bash
pg_dump -h localhost -U approval_user approval_db > backup_$(date +%Y%m%d).sql
```

### 4.3 常见问题

**Q: 审批流程卡住不动怎么办？**
A: 检查流程实例状态，确认当前节点的审批人是否存在。可通过管理后台「流程监控」→「异常实例」查看。

**Q: 如何回退已完成的审批？**
A: 系统支持「撤回」操作，但仅限发起人在下一节点未处理前操作。已完成的流程需要管理员在后台手动回退。

**Q: 并行审批中一个分支拒绝了怎么办？**
A: 默认策略是"一票否决"——任一分支拒绝则整个流程拒绝。可在流程设计时配置为"多数通过"策略。
