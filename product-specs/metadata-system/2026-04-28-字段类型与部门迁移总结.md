# 2026-04-28 字段类型修正与 depart_id 迁移总结

## 一、触发事件

客户数据保存报错：`column "dbc_bigint27" is of type bigint but expression is of type character varying`

## 二、根因分析

1. **字段类型不匹配**：元数据中 itemType/dataType 与 dbColumn 物理列类型不一致，前端传字符串写入 BIGINT 列，PostgreSQL 不做隐式转换直接报错
2. **写入链路缺少类型转换**：`EntityDataService` 构建 UpdateWrapper 时直接 `forEach(uw::set)`，未根据 dbColumn 前缀转换值类型
3. **depart_id → depart_api_key 迁移未完成**：大宽表物理列已有 `depart_api_key`，但 Java 实体类和部分代码仍引用 `depart_id`
4. **部门数据不完整**：Common 级 28 个部门未同步到 Tenant 级 `p_tenant_department`
5. **前后端 key 格式不一致**：前端发送 snake_case（`depart_api_key`），后端 `extractFixed` 只检查 camelCase（`departApiKey`）
6. **部门树排序错误**：按 level 平铺排序导致选项位置错位，选"销售部"实际选中"华东销售部"
7. **列表默认排序错误**：`updated_at ASC` 导致最近修改的记录排在最后

## 三、执行的修改

### 3.1 数据库

| 操作 | 影响范围 | 说明 |
|---|---|---|
| 元数据 itemType/dataType 修正 | 41 条 p_common_metadata | 动作一~五，修正 account/opportunity/lead 的字段类型 |
| depart_api_key 回填 | 12 张分片表 119 条 | 老数据的 depart_api_key 从 depart_id 映射回填，无法映射的设为 'root' |
| depart_id 列删除 | 2000 张分片表 | `ALTER TABLE DROP COLUMN depart_id` |
| 部门数据同步 | p_tenant_department +28 条 | Common 级部门同步到 Tenant 级 |

### 3.2 后端 Java

| 文件 | 修改 |
|---|---|
| `EntityDataService.java` | 新增 `castColumnValue()` 方法，3 处 `forEach(uw::set)` 改为 `forEach((col, val) -> uw.set(col, castColumnValue(col, val)))` |
| `EntityDataApiService.java` | `extractFixed` 兼容 camelCase 和 snake_case（`departApiKey` / `depart_api_key`）；默认排序改为 `orderColumn=null, asc=false` → `orderByDesc("updated_at")` |
| `TenantData.java` | 移除 `departId` 字段和 `COL_DEPART_ID` 常量，只保留 `departApiKey` |
| `EntityColumnResolver.java` | `FIXED_COLUMNS` 移除 `depart_id`，保留 `depart_api_key` |
| `XoqlMetadataService.java` | 移除 `departId` 元数据注册 |

### 3.3 前端

| 文件 | 修改 |
|---|---|
| `EntityDataFormDialog.tsx` | form 初始化加 `record.depart_api_key → mapped.departApiKey` 映射；部门树排序改为深度优先遍历 |
| `ShellApp.tsx` | 加入 react-router-dom 路由，URL 格式 `/crm/:entityApiKey/:recordId` |
| `CrmApp.tsx` | 从 URL params 读取 entityApiKey 和 recordId，导航时 `navigate()` 更新 URL |

### 3.4 同步脚本

| 文件 | 修改 |
|---|---|
| `sync/config.py` | 新增 `NEW_ITEM_TYPE_TO_BIZ_PREFIX`（25 种新编码映射），修正注释 |
| `sync/verify_metadata.py` | `_v9_prefix` 改用新编码映射，增加固定列/虚拟字段/RELATION_SHIP+VARCHAR 排除 |

## 四、字段值全链路格式规范

| dataType | dbc 前缀 | JSON 值类型 | Java 类型 | 说明 |
|---|---|---|---|---|
| 1(VARCHAR) | dbc_varchar | string | String | 文本/单选/电话等 |
| 3(BIGINT) | dbc_bigint | number | Long | 整数/日期/关联/时间，禁止传字符串 |
| 4(DECIMAL) | dbc_decimal | string | BigDecimal | 实数/百分比，用字符串避免浮点精度丢失 |
| 5(TEXT) | dbc_textarea | string | String | 文本域/富文本 |
| 6(SMALLINT) | dbc_smallint | number 0/1 | Integer | 布尔，禁止传 true/false |
| 7(TEXT_ARRAY) | dbc_array | string[] | List\<String\> | 多选，禁止传逗号分隔字符串 |

## 五、URL 路由规范

| URL | 页面 |
|---|---|

| `/crm/:entityApiKey` | 实体列表（如 `/crm/highSea`） |
| `/crm/:entityApiKey/:recordId` | 实体详情 |
| `/admin` | 管理后台 |
