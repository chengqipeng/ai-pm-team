# 字段值全链路格式规范

> 日期：2026-04-28
> 目标：每种 itemType 从前端组件 → JSON 传输 → 后端接收 → 写入数据库，全链路值格式完全统一，消除任何隐式转换

---

## 核心原则

1. **前端提交的 JSON 值类型 = 后端 Java 类型 = 数据库物理列类型**，三者严格一致
2. **dataType 是唯一权威**：决定 dbc 列前缀、Java 类型、JSON 值类型
3. **后端不做隐式转换**：如果前端传了错误类型，后端应拒绝而非静默转换
4. **阶段 0 防御性转换是过渡措施**，最终目标是前端严格按规范传值

---

## 关键约束（必须严格遵守）

### 约束 1：BIGINT 列必须传 number，禁止传 string

涉及 itemType：5(整数)、7(日期)、10(关联)、11(整数旧)、15(日期时间旧)、34(多态关联)、38(时间)、41(多值关联)

```
✅ 正确：{ "claimTime": 1714233600000 }
❌ 错误：{ "claimTime": "1714233600000" }
❌ 错误：{ "claimTime": "2026-04-28" }

✅ 正确：{ "territoryHighSeaId": 1001 }
❌ 错误：{ "territoryHighSeaId": "1001" }
```

### 约束 2：DECIMAL 列必须传 string，禁止传 number

涉及 itemType：6(实数/货币)、33(百分比)

```
✅ 正确：{ "annualRevenue": "99999.50" }
❌ 错误：{ "annualRevenue": 99999.50 }     ← JSON number 有浮点精度问题
❌ 错误：{ "annualRevenue": 99999 }         ← 整数也不行，统一用 string

✅ 正确：{ "paymentRate": "0.8500" }
❌ 错误：{ "paymentRate": 0.85 }
```

> 为什么 DECIMAL 用 string？JSON 的 number 类型是 IEEE 754 双精度浮点，`99999999999999.99` 会丢失精度。用 string 传输，后端直接 `new BigDecimal(str)` 无损转换。

### 约束 3：SMALLINT 列必须传 number 0/1，禁止传 boolean 或 string

涉及 itemType：31(布尔)

```
✅ 正确：{ "doNotDisturb": 1 }
✅ 正确：{ "doNotDisturb": 0 }
❌ 错误：{ "doNotDisturb": true }
❌ 错误：{ "doNotDisturb": "true" }
❌ 错误：{ "doNotDisturb": "1" }
```

### 约束 4：VARCHAR 列必须传 string

涉及 itemType：1(文本)、2(单选)、9(自动编号)、16(多选标签)、22(电话)、23(邮箱)、24(网址)、29(图片)、32(地理)、39(文件)

```
✅ 正确：{ "level": "opt_level_a" }
❌ 错误：{ "level": 1 }
```

### 约束 5：ARRAY 列必须传 string[]

涉及 itemType：3(多选)

```
✅ 正确：{ "customerSource": ["opt_a", "opt_b"] }
❌ 错误：{ "customerSource": "opt_a,opt_b" }
```

### 约束 6：null 和空值统一用 null

```
✅ 正确：{ "phone": null }          ← 清空字段
✅ 正确：不传该字段                   ← 不修改
❌ 错误：{ "phone": "" }             ← 空字符串不等于 null
❌ 错误：{ "score": 0 }              ← 如果业务含义是"未填写"，应传 null
```

## 按 dataType 汇总的转换规则

后端接收 JSON 后，按字段的 `dataType`（而非 itemType）做统一校验和转换：

| dataType | dbc 前缀 | JSON 值类型 | 后端校验逻辑 | 写入 DB 的 Java 类型 |
|---|---|---|---|---|
| 1(VARCHAR) | dbc_varchar | string | `instanceof String`，非 string 则拒绝 | String |
| 3(BIGINT) | dbc_bigint | number | `instanceof Number`，取 `longValue()`；string 则拒绝 | Long |
| 4(DECIMAL) | dbc_decimal | string | `instanceof String`，`new BigDecimal(str)`；number 则拒绝 | BigDecimal |
| 5(TEXT) | dbc_textarea | string | `instanceof String` | String |
| 6(SMALLINT) | dbc_smallint | number | `instanceof Number`，取 `intValue()`，校验 0 或 1 | Integer |
| 7(TEXT_ARRAY) | dbc_array | string[] | `instanceof List`，每个元素 `instanceof String` | List\<String\> |

---

## 后端校验代码

```java
/**
 * 根据 dataType 校验并转换前端传入的字段值。
 * 严格模式：类型不匹配直接拒绝，不做隐式转换。
 */
public Object validateAndCast(int dataType, String apiKey, Object value) {
    if (value == null) return null;

    switch (dataType) {
        case 1: // VARCHAR → dbc_varchar
        case 5: // TEXT → dbc_textarea
            if (value instanceof String) return value;
            throw new FieldTypeException(apiKey, "string", value);

        case 3: // BIGINT → dbc_bigint
            if (value instanceof Number) return ((Number) value).longValue();
            throw new FieldTypeException(apiKey, "number(long)", value);

        case 4: // DECIMAL → dbc_decimal
            if (value instanceof String) {
                try { return new BigDecimal((String) value); }
                catch (NumberFormatException e) {
                    throw new FieldTypeException(apiKey, "string(decimal)", value);
                }
            }
            throw new FieldTypeException(apiKey, "string(decimal)", value);

        case 6: // SMALLINT → dbc_smallint
            if (value instanceof Number) {
                int v = ((Number) value).intValue();
                if (v != 0 && v != 1) throw new FieldTypeException(apiKey, "0 or 1", value);
                return v;
            }
            throw new FieldTypeException(apiKey, "number(0/1)", value);

        case 7: // TEXT_ARRAY → dbc_array
            if (value instanceof List) {
                List<?> list = (List<?>) value;
                for (Object item : list) {
                    if (!(item instanceof String))
                        throw new FieldTypeException(apiKey, "string[]", value);
                }
                return list;
            }
            throw new FieldTypeException(apiKey, "string[]", value);

        default:
            throw new FieldTypeException(apiKey, "unknown dataType=" + dataType, value);
    }
}
```

## 前端提交代码规范

```typescript
/**
 * 根据字段元数据的 dataType 格式化提交值。
 * 在表单 submit 时对每个字段调用。
 */
function formatSubmitValue(item: XEntityItem, rawValue: any): any {
  if (rawValue === null || rawValue === undefined || rawValue === '') return null;

  switch (item.dataType) {
    case 1: // VARCHAR
    case 5: // TEXT
      return String(rawValue);

    case 3: // BIGINT
      // 日期选择器返回 Date 对象，需要转为毫秒时间戳
      if (rawValue instanceof Date) return rawValue.getTime();
      // 关联选择器返回 number ID
      if (typeof rawValue === 'number') return rawValue;
      // 数字输入框可能返回 string，转为 number
      const num = Number(rawValue);
      if (Number.isNaN(num)) throw new Error(`${item.apiKey}: 期望 number，收到 "${rawValue}"`);
      return num;

    case 4: // DECIMAL
      // 始终转为 string 传输，避免浮点精度丢失
      if (typeof rawValue === 'number') return rawValue.toString();
      if (typeof rawValue === 'string') return rawValue;
      throw new Error(`${item.apiKey}: 期望 string(decimal)，收到 ${typeof rawValue}`);

    case 6: // SMALLINT (布尔)
      if (typeof rawValue === 'boolean') return rawValue ? 1 : 0;
      if (typeof rawValue === 'number') return rawValue === 0 ? 0 : 1;
      throw new Error(`${item.apiKey}: 期望 0/1，收到 "${rawValue}"`);

    case 7: // TEXT_ARRAY
      if (Array.isArray(rawValue)) return rawValue.map(String);
      throw new Error(`${item.apiKey}: 期望 string[]，收到 ${typeof rawValue}`);

    default:
      return rawValue;
  }
}
```

## 与修正对比表的关联

字段类型修正对比表中的 50 个问题字段，其根因都可以归结为违反了本规范：

| 问题类型 | 违反的约束 | 示例 |
|---------|----------|------|
| A-必炸（单选→bigint） | 约束 1：bigint 列传了 string | `employeeNumber`: 前端传 `"opt_50_200"` 写入 dbc_bigint4 |
| A-必炸（日期声明VARCHAR→bigint） | 约束 1：dataType 声明错误导致前端传 string | `claimTime`: dataType=VARCHAR 导致前端传 `"1714233600000"` |
| B-语义错（关联→decimal） | 约束 2：itemType 标错导致前端传 number 而非 string | `money`: 标为关联(10)但实际是金额 |
| D-列不存在（dbc_int） | 列类型不在规范内 | `leadChannel`: dbc_int 不存在 |

**修正后，所有字段都必须严格遵循本规范的全链路格式对照表。**

## 过渡期兼容策略

在所有前端和元数据修正完成之前，后端保留 `castToColumnType()` 防御性转换作为兜底：

```java
/**
 * 过渡期防御性转换（最终目标是移除此方法，由 validateAndCast 严格校验替代）。
 * 根据 dbColumn 前缀尝试将值转换为正确类型，转换失败返回 null。
 */
private Object castToColumnType(String dbColumn, Object value) {
    if (value == null) return null;
    String str = value.toString().trim();
    if (str.isEmpty()) return null;
    try {
        if (dbColumn.startsWith("dbc_bigint"))   return Long.parseLong(str);
        if (dbColumn.startsWith("dbc_decimal"))  return new BigDecimal(str);
        if (dbColumn.startsWith("dbc_smallint")) return Integer.parseInt(str);
    } catch (NumberFormatException e) {
        log.warn("字段值类型转换失败: dbColumn={}, value={}", dbColumn, value);
        return null;
    }
    return value;
}
```

**最终目标**：前端严格按 `formatSubmitValue()` 提交 → 后端用 `validateAndCast()` 校验 → 类型不匹配直接返回 400 错误 → 移除 `castToColumnType()` 兜底。
